# Material: MTask 四期 / 五期 功能模块培训

> 数据来源：MTask 内部 PRD 与「项目计划（WBS）」真实数据（mtask 服务端），经 mtask MCP 拉取并核对。
> 四期项目：mtask四期（a9911922）｜五期项目：mtask五期（95f31a46）

## 1. Overview（概览）
- **四期**交付两大能力模块：**「估算视图与工作量评估导出」** + **「测试用例管理（需求矩阵关联 + AI 生成）」**。
- **五期**交付一大能力模块：**「AI 控制台 · 项目启动会 PPT 生成」**（一键把项目沉淀资料组织成可编辑原生 .pptx）。
- 三大模块共同把 MTask 从"排期工具"升级为"**对外报价 + 一键成稿**"的闭环：计划 → 估算报价 → 用例覆盖 → 启动会成稿。
- 全部复用既有依赖（exceljs / docx / pdfkit / pptxgenjs），遵循"仅使用已有依赖"协议，不引入新渲染链。

## 2. Background（背景）
- **痛点 1（报价脱节）**：MTask 已沉淀估算所需全部上游数据——需求矩阵 `prd_requirements`、项目计划 `plan_tasks`（含工期/复杂度/依赖）、测试用例 `test_cases`、历史待办 `tasks` **1580 条**，但这些数据只用于排期，**没有转化为可对外报价的工作量口径**；对外报价仍要在系统外手工誊抄 Excel（如 `阜新银行-票据系统优化-工作量评估V2.0.xlsx` 即人工产物），不可追溯、无法随计划变更刷新。
- **痛点 2（用例无结构化）**：用例散落在文档与口头，缺统一库、缺覆盖度度量、缺与需求矩阵的双向溯源。
- **痛点 3（资料不转化）**：项目资料（PRD/矩阵/计划/用例/工作空间分析）沉淀后，启动会材料仍靠人工拼装 PPT，耗时且不一致。
- 现状证据（四期实测）：mtask四期 12 条需求（high 10 / normal 2）；工期分布极窄（normal 16 条 min=1 max=3 avg=1.75，milestone 4 条 avg=7.0）；`complexity` 大部分项目未填。
- 现状证据（五期实测）：AI 控制台已有 6 张卡（AI 项目计划导入 / 离线周报 / AI 周报 / 原始需求生成 PRD / 从 PRD 导入计划 / 从 PRD 生成测试用例），新卡为**第 7 张**；卡片页是 `ReportPage.tsx`（非 AIToolsPage），须复用 `ReportCard` 组件与样式。

## 3. Key Info（关键事实 / 数据）
- **三点估算**：每条计划录入 乐观 O / 最可能 M / 悲观 P；期望值 `E=(O+4M+P)/6`，标准差 `σ=(P-O)/6`，并给置信区间。
- **汇总口径（复刻客户模板 R35~R40）**：最终估算值 → 阶段人月 → 调节系数 → 实际预估人月；按"阶段"（需求/设计/开发/实施…）汇总，单条粒度不足以直接报价。
- **冷启动**：复杂度→系数推导（允许逐条覆盖）；里程碑不进 Σ；排除小计行。
- **导出**：Excel 逐格对齐客户模板（sheet 名/合并区/公式/命名区域/列宽），PDF 直接可交付报价；失败时快照留档 `estimate_snapshots`。
- **测试模块数据模型**：新增 `test_cases`、`case_steps`（步骤子表）+ 枚举常量（服务端单源、前后端共用）。
- **覆盖度**：按 P0~P3 优先级统计用例覆盖；swork 71 条用例（P0 9 / P1 31 / P2 25 / P3 6）。
- **AI 生成**：`TestCaseGenService` 从 PRD/外部导入生成用例草稿，草稿确认后导入；输出预算受 max_tokens 约束（长文易截断，需分章）。
- **五期取数**：读 PRD 文档、需求跟踪矩阵、项目计划、测试用例、工作空间分析，一次点击产出 **12~18 页**原生 .pptx（含甘特/时间线、工作量、风险、沟通管理）。
- **五期技术**：复用 `pptxgenjs@^4.0.1` + worker 池；新版式断言层 + PPT 装配器 + 时间线形状绘制 + 工作量降级逻辑；SSE 流式端点 `POST /api/plans/kickoff-ppt-stream`；并发闸防资源打满。

## 4. Evidence（案例 / 模块拆解）
- **四期·估算模块 WBS**：M1 基础架构（技术验证 Spike E0 + 数据模型迁移 E1）→ M2 核心引擎（PERT 计算 E2 + REST 路由 E3）→ M3 前端交互（面板布局/行内编辑/可视化）→ M4 导出（Excel 复刻 E6 + PDF/MCP）→ M5 联调验收。
- **四期·测试模块 WBS**：数据层（test_cases/case_steps/枚举）→ 后端（用例 CRUD / 批量 / 覆盖度 / 导出）→ 前端（用例列表/矩阵下钻/会话状态）→ AI 生成链路（AI 服务/草稿确认/控制台日志）→ 联调（幂等去重/级联删除/MCP 注册）。
- **五期 WBS**：M1 需求与设计确认 → M2 基础服务端（前置校验/大纲生成）→ M3 核心生成引擎（版式断言/PPT 装配器/时间线/降级）→ M4 接口与交付（SSE 流/文件命名下载/并发闸）→ M5 前端交互（能力卡片/面板互斥/KickoffPptPanel）→ M6 测试验收。
- **技术验证 E0（已放行）**：exceljs 用 `{formula,result}` 双写公式与缓存值、常量命名区域写侧注入可解析重算、28 处合并区无损；结论"复制模板再填充会丢命名区域 → E6 改从零构建"。

## 5. Analysis（分析 / 多视角）
- **价值对比**：四期把"看不见的不确定度"变成"看得见的标准差/置信区间"，报价从拍脑袋→三点法；五期把"人工拼 PPT"变成"资料→一键成稿"，且产物可继续编辑。
- **一致性纪律**：四期/五期均强制复用既有组件与命名（ReportCard、mtask_* MCP 家族、枚举单源），不新造轮子，降低维护成本。
- **风险与降级**：长文 AI 输出受 token 上限（默认 4096 必截断）→ 需抬预算/分章；版式质量用"断言层"做质量门禁；并发闸防流式生成打满资源。

## 6. Outlook（展望 / 建议）
- **非目标（本期明确不做）**：资源费率管理、财务成本核算、跨项目组合（Portfolio）汇总（四期）；五期不做"新 PPT 引擎"，只做"启动会内容装配器"。
- **演化方向**：估算可向 IFPUG 功能点法对照扩展；用例 AI 生成可向更多资料类型扩展；启动会 PPT 可向更多会议类型（周报/复盘）泛化。
- **培训落点**：新成员应先理解"资料沉淀→报价→成稿"的闭环链路，再上手各模块操作。
