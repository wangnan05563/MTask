## 1. D1 —— Git 只读采集架构

### 1.1 通道选择：`execFile` 参数数组（不是 `exec`、不是 shell）

- 先例在位：`server/src/tunnel/tunnel-service.ts:14` 的注释与 `server/src/tunnel/tunnel-service.ts:15` 的 `const execFileAsync = promisify(execFileCb)` 明确写着「不走 shell，参数数组传递避免路径转义问题，适合带路径参数的 CLI 调用」；同一文件 `:419` 已有 `execFileAsync('tar', ['-xf', …], { windowsHide: true, timeout: 30000 })` 的完整用法（超时/隐藏窗口都有先例）。
- 结论：采集层只使用 `execFile('git', [...args], opts)`，**禁止** `exec` / `shell: true` / 字符串拼接。
- 安全收益：路径里的 `;`、反引号、空格不进入 shell 解析，直接满足 PRD A-3 的注入用例。

### 1.2 子命令白名单（只读集合）

| 用途 | 命令 | 说明 |
|---|---|---|
| 可用性探测 | `git rev-parse --is-inside-work-tree` | 非 0 即「不是 git 仓库」→ 降级 |
| 区间统计 | `git diff --stat <range>` | 文件数/增删行 |
| 提交摘要 | `git log --oneline --no-merges <range>` | 「为什么改」的第一证据源 |
| 变更正文 | `git diff -U<n> <range>` | 生成 hunk；`--ignore-cr-at-eol` 见 D1.3 |
| 单文件补读 | `git show <rev>:<path>` | 只在展开上下文时用，仍属只读 |

白名单之外一律拒绝（代码层硬拦，不做「黑名单过滤」）。`checkout / commit / fetch / pull / clone / config --global` 等写命令永不进入参数表——只读性由**命令集合本身**保证，不依赖运行期检测。

### 1.3 Windows 两个硬约束

1. **输出编码**：中文 Windows 上 git 默认按 cp936 输出 commit message，Node 按 UTF-8 解码即乱码。采集统一注入 `-c i18n.logOutputEncoding=utf-8`。
2. **路径转义**：非 ASCII 路径默认被转义成 `\xxX`，锚点不可读且定位失效。统一注入 `-c core.quotepath=false`。
3. **行尾噪声**：`core.autocrlf=true`（Windows 安装默认）会让未改行尾的文件整文件进 diff。统一加 `--ignore-cr-at-eol`。

三者都以**命令行参数**注入（`git -c key=value <cmd>`），不读写用户的全局/仓库 git 配置——这是 E-1 签字后仍然必须守住的边界。

### 1.4 边界与降级

| 边界 | 取值 | 落点 |
|---|---|---|
| 单仓 diff 文本 | 默认 2MB，超出按优先级截断并逐文件点名 | FR-1.4 / FR-7.1 |
| 子进程超时 | 30s（与 `tunnel-service.ts:419` 同口径） | FR-1.4 |
| `maxBuffer` | 显式设置，不用默认 1MB | FR-1.4 |
| 无 git / 非仓库 | `rev-parse` 非 0 或 `ENOENT` → 面板切「粘贴 patch」（raw 30mb 同构） | FR-1.3、E-1 签字结论 |

**可行性判断**：`execFile` 对 `ENOENT`（未装 git）会 reject，按 `err.code === 'ENOENT'` 即可区分「没装 git」与「不是仓库」，降级分支可判定、可测。

## 2. D2 —— SSE 流端点复用路径

### 2.1 端点形态照抄，不造新协议

现网三个 SSE 端点结构一致，取 `prd-generate-stream` 为模板：

- 注册：`api.post('/plans/prd-generate-stream', raw({ type: () => true, limit: '30mb' }), async (req, res) => {` —— `server/src/routes/index.ts:1637`；
- 事件写出口：`const send = (event, payload) => { if (closed || res.writableEnded) return; res.write(...) }` —— `:1667`；
- 中断：`const ac = new AbortController()` —— `:1672`，`res.on('close', () => { closed = true; ac.abort(); })` —— `:1673`；
- 同构复制点：`testcase-generate-stream` `:1780`（`send` `:1805`、`ac` `:1810`）、`ai-generate-stream` `:1833`（`ac` `:1859`、`close` `:1862`）。

新端点只把 `send`/`ac`/`close` 这套骨架搬过来，事件名沿用 `stage / chunk / done / error`，前端 `streamEvents` 无需改动。

### 2.2 前端复用

- `web/src/api/sse.ts:76` 的 `streamEvents(path, data, onEvent, signal)` 已是通用入口；`:82` 发 `POST`，`:86` 把 `signal` 透传给 `fetch`。
- 「停止」= 前端 abort → 连接断开 → 后端 `res.on('close')` → `ac.abort()` → `askStream`/`git` 子进程收手。这条链路在 `ai-generate-stream` 上已有实测注释（必须监听 `res` 的 `close` 而不是 `req.on('close')`，否则请求体被消费完后会提前触发，导致后续事件被误丢）。
- 已知坑（本仓旧账）：SSE 读帧不能自造，必须走 `readStream`；否则会静默丢 `done` 帧（门脚本曾因此假红）。

### 2.3 下载令牌：只用于「导出」，不用于「生成」

- 生成流不落盘、不发 token；用户点导出才走后端装配 → `saveReportBuffer`（`server/src/services/ReportService.ts:172`）→ `done` 事件带 token → `POST /report/ai-download`（`server/src/routes/index.ts:1893`）→ `readAndDeleteReport`（`ReportService.ts:179`）。
- 断线回收沿用 `discardReport`（`ReportService.ts:188`）：token 已发但 `done` 未送达时当场删，避免孤儿文件。
- 文件名走单源白名单 `DOWNLOAD_NAME_RE`（`server/src/util/export-name.ts:18`），三种格式（md/docx/pptx）均已在列，**下载侧零改动**。
- 三种格式的装配全部复用既有构建器：`buildDocx`（`server/src/services/report-builder.ts:170`）/ `buildPptx`（`server/src/services/report-builder.ts:247`）；md 由后端直出，不新增依赖。

## 3. D3 —— 上下文分段装配策略

### 3.1 预算常量分立

- 既有 `PRD_CONTEXT_LIMIT = 6000`（`server/src/util/prdContext.ts:25`）服务的是「PRD 原文注入提示词」，与本场景量级差一个数量级。
- 本功能新设 `LECTURE_CONTEXT_BUDGET`（建议默认 **60,000 字符/次调用**，可配置），**禁止复用 6000**，避免悄悄降质。
- 截断纪律沿用：`trimPrdContent`（`prdContext.ts:76`）的「保头保尾 + 中段显式标注略去字数」（`:77`）——讲稿侧对超大 hunk 用同一形态，告警文案点名文件。

### 3.2 三阶压缩

1. **全量层**：`文件清单 + --stat`，先给 AI 一个全局视图（也用于预检统计）。
2. **单文件层**：每个文件生成 `hunk 摘要`；超大 hunk 保头保尾截断（纪律同 3.1），并记录「已截断」标记。
3. **分组层**：按 `项目 → 模块（目录） → 文件` 两级分组，每组一次 `askStream`；组间不重复注入（结构由大纲锁定）。

### 3.3 模型调用形态

| 阶段 | 方法 | 证据 | 理由 |
|---|---|---|---|
| 大纲 | `AIService.askJson` | `server/src/services/AIService.ts:499` | 自带「解析失败重试 1 次 + `parse` 抛错即判无效」，可直接用 schema 校验大纲 |
| 逐节展开 | `AIService.askStream` | `AIService.ts:584` | 支持 `onDelta` 与 `AbortSignal`，「停止」可即时生效 |
| 普通追问（可选） | `AIService.ask` | `AIService.ts:474` | 同带 `signal` |

### 3.4 上下文展开一层

- 变更文件的调用方/所在类走既有符号端点 `GET /api/workspace/symbols`（`server/src/routes/index.ts:315`），**深度=1**，仅源码类文件。
- 不新建检索/索引机制（N3 边界）；不引入 embedding。

### 3.5 失败与降级

- 单节失败：该节标失败、可单独重试，不拖垮已生成节（分段幂等）。
- 预算不足：先按优先级（变更行数 → 安全敏感路径 → 符号引用数）丢弃低权重文件，并在预检**逐一点名**；用户可选「裁剪继续」或「中止收窄」。
- 零活动数据：预检硬阻塞，不出空壳稿（PRD 反例场景）。
