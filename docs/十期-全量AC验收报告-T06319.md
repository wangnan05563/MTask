## 2. 逐项证据

### AC-01 / AC-31 首屏加载

- 环境：隔离实例 `127.0.0.1:5217`，5k 待办项目 `p-t06314-perf`，当前 HEAD 生产构建 `web/dist`，Chrome headless 1440×1000。
- 实测：任务页首屏可用 **619ms**（阈值 3000ms），首屏 DOM 24 行，按页加载且窗口化。
- 证据：`docs/evidence/t06319-ac/ac31-33-perf-final.log`、`perf-result-final.json`。

### AC-02 / AC-32 搜索响应

- 口径：1,000 份可检索任务文档，100 次搜索（P50/P95 统计）。
- 实测：**P50 14.3ms / P95 18.3ms**，远低于 300ms；分组返回 task 1 条、run 3 条。
- 证据：`docs/evidence/t06319-ac/ac32-search.log`。

### AC-03 / AC-33 滚动帧率

- 场景：5k 全量看板，快速滚动（每 70ms 420px），rAF 采样 2.6s。
- 实测：**平均 59.6fps、帧间隔 P95 16.8ms、>34ms 长帧 0**，达到 60fps 档；看板首屏 200 卡 58.9fps（1 个长帧）。
- 说明：同轮 5k 列表全量滚动 56.9fps（P95 16.8ms），非 AC-33 的看板口径，记录为观察值。
- 证据：`docs/evidence/t06319-ac/ac31-33-perf-final.log`、`perf-result-final.json`。

### AC-04 / AC-34 硬编码色

- 扫描面：`App.tsx` + 概览、任务、计划、需求、报表、队列、执行会话、提示词、模型、设置共 12 个核心页面/入口。
- 首轮门禁：`hardcodedHex=0` 通过，但 Codemod dry-run 发现 2 文件 3 处 `var(--token, #hex)` 回退（`inboxPage.css` 2 处、`InboxBell.tsx` 1 处），组合门 exit 1。
- 修复：两文件改用已定义的 `var(--warning)`，不改变视觉值；复跑 **`corePages=12 hardcodedHex=0`、Codemod `files=0 replacements=0`，exit 0**。
- 证据：`ac34-baseline.log`（首轮失败）、`ac34-final.log`（收口通过）。

### AC-05 / AC-35 无障碍扫描

- 扫描面：首页、任务、计划、需求、报表、队列、执行会话、提示词、模型、设置 10 条关键路径，axe-core WCAG 2 A/AA。

## 4. 遗留与边界

1. **列表 5k 全量滚动为观察值**：同轮 56.9fps（P95 16.8ms、3 个长帧），低于看板 59.6fps；AC-33 只约束看板视图，列表不判失败，但若后续要把列表也纳入 60fps 硬门槛，需单独立项治理。
2. **数值口径为 headless Chrome + SwiftShader**：未覆盖真实 GPU、120Hz 屏与移动端；真机可能更高，不作为反向结论。
3. **AC-02 文档口径**：沿用 T06296 定义，1k 份「本地可检索任务文档」；未索引独立 `prd_docs` 文档对象。
