## 一、项目功能梳理（现状基线）

**定位**：AI 任务开发管理工具——面向「开发者 + AI Agent 协作」的单机优先任务管理桌面应用。

**技术栈**：Electron 33（桌面壳）+ React 18 / TypeScript（web）+ Express（server）+ better-sqlite3（SQLite WAL，单文件可移植）+ exceljs（导入导出）+ MCP SDK（streamable HTTP）。

### 1.1 功能模块清单

| 模块 | 能力概要 | 特色点 |
|---|---|---|
| 任务管理 | 项目/分类/优先级/验证态/归档/截图粘贴、批量 AI 分类、AI 标题美化、外部改库自动刷新 | 任务编号徽标（MCP 按编号定位）、AI 回写审核图标 |
| AI 工具 | 多模型配置（openai-compatible / claude / ollama / workbuddy 四类适配器）、连接测试、模型列表拉取、默认工具 | BYOK 本地配置 |
| AI 控制台 | 并行分析任务（周报/风险/破坏性变更/影响/测试要点/自定义）、任务持久化、结果转存通用需求（指纹防重） | 流式 SSE + 后端续跑 |
| 提示词仓库 | 分类组织、复用、复制到待办 | |
| 通用需求 | 分类 + 条目沉淀、AI 提炼转存、复制到待办 | 内容指纹防重复转存 |
| 项目计划 | 串行瀑布时间线（工作日排期/节假日避让）、Excel 模板导入导出、Excel/Word/Markdown AI 导入、待办双向联动、节假日三模式维护 | WBS 编号 + 反向进度联动 |
| 队列 | 任务批量派发给 AI Agent、状态机收口、结构化日志 | 与适配器联动 |
| 周报 | AI 生成周期报告、模板、令牌只读分享 | |
| MCP 接口 | mtask_list/get/update_task_result/create_task 等，AI Agent 直接定位任务编号并回传结论 | AI 协作的核心通道 |
| 日志/设置 | 动态来源筛选（server/ai/queue）、数据迁移/维护（DB 管理界面）、内网穿透 + 访问令牌、移动端随手记 | |

### 1.2 数据流向（核心链路）

```
任务 ──AI 梳理/美化──▶ 控制台任务 ──提炼转存──▶ 通用需求 ──复制──▶ 任务
  ▲                                                        │
  └── MCP（Agent 按编号回传 handle_result） ◀── 队列派发 ────┘
项目计划 ⇄ 待办（linked_task_id 双向状态同步）
周报 ◀── 周期任务数据；项目计划 ◀── Excel/Word/MD（AI 导入）
```

**差异化定位（相对竞品）**：MTask 是目前少见「**为 AI Agent 而设计的任务系统**」——任务编号、MCP 双向通道、处理结果回写、AI 回写审核工作流，都是为「人机协作闭环」而生；竞品的 AI 多为附加助手。

### 2.2 重点竞品详析

#### Plane（最接近的规模化对标）
- **核心优势**：epics→issues 层级、cycles（迭代）、模块化视图、工作区/团队隔离；企业级自托管成熟度高。
- **交互亮点**：快捷命令面板、拖拽顺畅、issue 详情侧栏信息密度高。
- **可借鉴**：① 层级工作项（epic→issue→sub-issue）——MTask 缺任务父子关系；② cycles 迭代概念对应 MTask「项目计划」但更实时；③ 「自动进度追踪」（子项完成汇总父级）。
- **高频诉求（Issue 观察）**：移动端体验、导入迁移工具、插件扩展。

#### Planka（架构同源的最小可用对标）
- **核心优势**：与 MTask 同为 React + Node.js 栈，极简克制、WebSocket 实时协同、v2.0 UI 大幅改良。
- **可借鉴**：① WebSocket 实时同步（MTask 现为 10s 轮询）；② 卡片评论/活动流；③ SSO/OIDC。
- **局限**：无 AI、无文档能力——正是 MTask 的差异化空间。

#### Leantime（AI 集成的直接对标）
- **核心优势**：AI 助手做**任务分解（decompose）、状态报告生成、项目洞察**——与 MTask 的 AI 梳理/周报高度同构；目标导向（idea→milestone→task 链路）。
- **可借鉴**：① AI 任务分解的交互形态（输入一段目标 → 输出任务树供勾选确认——MTask 已有雏形：Word/MD→WBS）；② 「策略→执行」的关联视图（对应 MTask 通用需求→任务）。

#### Focalboard（警示案例）
- Mattermost 出品、26k stars 仍**实质停滞**（最后发布 2023）——单团队维护大型开源 PM 的可持续性风险；警示 MTask 保持「小而专」、避免功能面无限扩张。

#### AppFlowy（文档-任务融合的标杆）
- 文档中直接创建/转化任务（会议纪要→行动项），「文档与执行零缝隙」。
- **可借鉴**：需求文档 ↔ 任务的双向块级引用（MTask 已有 Word/MD→WBS 单向导入，可进化为「文档块 ↔ 任务」引用）。

### 2.3 差距与优势小结

**MTask 优势**（保持并放大）：AI Agent 深度协作（MCP）、多模型 BYOK、单文件可移植（SQLite）、桌面级离线可用、中文优先。

**MTask 差距**（本 PRD 优化方向）：无实时协同（轮询）、无任务层级/依赖视图、无可视化看板/甘特、无团队协作与账号体系、AI 输出可解释性弱（无 token 用量/成本面板）、移动端能力有限。

## 三、优化需求（三维度）

> 优先级定义：P0 = 补齐核心体验短板，尽快做；P1 = 显著提升价值，规划做；P2 = 探索/长期。

### 3.1 用户体验（UX）

| # | 需求 | 说明 | 优先级 |
|---|---|---|---|
| UX-1 | **任务看板视图** | 现列表为主，增加按分类/状态分列的看板（拖拽流转），参考 Planka v2 极简风 | P1 |
| **UX-2** | **甘特图视图**（项目计划） | plan_tasks 已有时间线数据，渲染条状甘特 + 节假日底纹，支持拖拽改工期 | P1 |
| UX-3 | 任务父子层级 | epic→task 两级（数据加 parent_id），支撑大需求拆解（与 WBS 导入天然衔接） | P1 |
| UX-4 | 快捷命令面板 | Ctrl+K 全局搜索任务/项目/提示词并直达操作（对标 Plane/Linear） | P2 |
| UX-5 | 批量操作增强 | 列表多选后批量改状态/分类/删除（现有批量仅限 AI 分类/美化） | P2 |
| UX-6 | 空状态与引导 | 各页面空状态给「下一步动作」引导（新建/导入/示例） | P2 |

### 3.2 功能联动（Integration）

| # | 需求 | 说明 | 优先级 |
|---|---|---|---|
| INT-1 | **WebSocket 实时同步** | 替换 10s 轮询：server 检测写库变更推送（MCP/队列/多窗口场景即时刷新），参考 Planka | P0 |
| INT-2 | 提示词 ↔ 任务反向引用 | 任务详情显示「来源提示词/通用需求」链接（T00436 已有正向复制，补来源引用与跳转） | P1 |
| INT-3 | 项目计划 ↔ 周报联动 | 周报生成时汇总计划本期完成/延期任务（数据已在库） | P1 |
| INT-4 | 队列 → 任务自动回写状态 | 队列 Job 成功后可配置自动置任务 done 并触发计划联动（现仅回传结果） | P1 |
| INT-5 | 通用需求 → 项目计划 | 通用需求条目一键生成计划草稿（衔接 Word/MD→WBS 管线，来源标注） | P2 |
| INT-6 | 导入迁移器 | 从 Trello/Planka/CSV 导入任务与看板（WeKan 的迁移工具是其增长点） | P2 |

### 3.3 AI 加持（AI）

| # | 需求 | 说明 | 优先级 |
|---|---|---|---|
| AI-1 | **AI 用量与成本面板** | 记录每次调用（模型/token/耗时/成功否），控制台展示——排错与成本可见（日志已有 source=ai 基础） | P0 |
| AI-2 | AI 结果引用溯源 | 美化/梳理结果标注来源模型与提示词版本，可一键重跑 | P1 |
| AI-3 | 对话式任务操作 | 经 MCP 扩展「AI 创建/拆分任务」工具（Agent 对话中直接建任务，回写审核流程复用） | P1 |
| AI-4 | 智能日程建议 | 项目计划 AI 导入时让模型同时给出 startDate 建议（当前仅 WBS 编号+工期） | P2 |
| AI-5 | 每周 AI 摘要推送 | 周报生成后可配置摘要写入收件箱任务（复用队列/随手记） | P2 |
| AI-6 | 多模型对比模式 | 同一任务并行调用多个模型，结果并列对比（适配器已支持多模型，控制台并行框架已就绪） | P2 |

### 3.4 实施路线图建议

- **第一阶段（P0）**：INT-1 实时同步、AI-1 用量面板——补齐「多通道写库可见性」与「AI 成本可见性」两块短板。
- **第二阶段（P1）**：UX-2 甘特图、UX-3 任务层级、INT-2/3/4 联动补全、AI-2/3。
- **第三阶段（P2）**：看板视图、命令面板、迁移器与探索性 AI 功能。

## 四、风险与约束

1. **单人/小团队维护**（Focalboard 警示）：每阶段控制在 1-2 个 P0/P1 特性，保持可维护性。
2. **协议约束**：借鉴竞品交互思路但不复制代码；当前私有协议，若开源需注意依赖传染性（现有依赖 MIT/多协议混合）。
3. **AI 依赖**：BYOK 模式下模型余额/可用性是体验变量（已有 402 透传），AI-1 成本面板是缓解手段。
4. **单机优先架构**：WebSocket/协同功能不得破坏「单文件 SQLite 可移植」的立身之本。
