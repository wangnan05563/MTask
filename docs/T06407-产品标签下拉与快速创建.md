## 1. 数据模型与能力边界

MTask 没有独立的产品标签字典表，也没有全局“创建标签”API。候选标签由项目列表的 `product_key` 现算去重；创建新标签本质是把新值绑定到当前项目（`PATCH /projects/:id { productKey }`），保存成功后其他项目才把它视为候选。因此：

- “创建”不会新增一条全局标签记录，而是新值首次落在当前项目上。
- MTask 当前没有角色/权限模型；沿用现有产品标签保存能力——当前用户可编辑该项目即可创建/绑定。
- 任务描述中的 “AirMirror 三期 UI 规范” 不适用于本仓库；实现使用 MTask Design Token 与现有 UI 原语。

## 2. 交互实现

新增 `web/src/ui/ProductTagCombobox.tsx`：

- 聚焦时立即展示当前值过滤后的候选；空输入展示全部（最多 8 个，更多时提示继续输入）。
- 输入采用 150ms 防抖后过滤，子串匹配；前缀命中的候选排在前面。
- 候选与输入做 `trim().toLowerCase()` 归一化；存在完全匹配（含大小写/首尾空格差异）时不显示“创建「xxx」”。
- 点击已有标签只回填并标记选中；点击“创建「xxx」”调用调用方提供的 `onCreate`，成功后回填并关闭下拉。
- 键盘：↑/↓ 循环移动活动项，Enter 选择/创建，Home/End 跳首尾，Esc 先关下拉；下拉关闭后第二次 Esc 才关闭弹窗。
- 保存失败不关闭下拉/弹窗，保留输入并显示错误；已有标签选择、手动确定和快速创建都走同一条保存链路。
- 下拉在文档流内展开，不再覆盖弹窗底部「取消/确定」；箭头图标相对输入框定位，不随下拉高度漂移。

接入两个入口：

1. 新建项目后的工作空间弹窗：`TasksPage.tsx` 的产品标签区改为 `ProductTagCombobox`，快速创建直接绑定新项目。
2. 存量项目补绑：`editProductKey()` 从 `askInput` 纯文本改为 `askProductTag`，候选、创建、失败保留输入与原弹窗一致。

同时修复了新项目弹窗的两个可见问题：

- `WorkspaceSelect variant="bare"` 的面板原本绝对定位，会盖住下方产品标签；bare 模式改为文档流布局。
- 外层 `<dialog open>` 的遮罩原本只覆盖内容盒；补齐 viewport 尺寸与滚动，避免出现局部灰色块。
