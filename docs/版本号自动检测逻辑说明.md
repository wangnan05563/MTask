# 版本号自动检测逻辑说明

> 对应实现：`server/src/services/UpdateService.ts` ｜ API：`POST /api/update/check`
>
> 本文面向开发与测试人员，说明从配置到「是否有更新」判定的完整链路。

---

## 1. 总体流程

```
前端「检查更新」
   │  POST /api/update/check { force }
   ▼
UpdateService.checkUpdate()
   │  1. 读配置：update.repo（app_settings 表）
   │     缺失 → 抛「尚未配置 GitHub 仓库」
   │  2. 缓存查询（TTL 5 分钟，force=true 跳过）
   │     命中 → 直接返回上次结果
   │  3. 解密 Token（update.token，AES-256-GCM）
   ▼
fetchLatestRelease(repo, token)
   │  HTTPS GET https://api.github.com/repos/{owner}/{repo}/releases/latest
   │  Headers: Accept: application/vnd.github+json
   │           User-Agent: MTask-Updater        ← GitHub 强制要求
   │           X-GitHub-Api-Version: 2022-11-28
   │           Authorization: Bearer <token>    ← 仅私有仓库/提额时携带
   │  超时：15 秒（AbortSignal.timeout）
   ▼
版本比较 compareVersions(latest, current)
   │  current 来自 package.json 的 version 字段
   ▼
返回 UpdateCheckResult { hasUpdate, latestVersion, changelog, downloadUrl, … }
   │  成功结果写缓存（5 分钟）；失败不缓存
   ▼
前端渲染结果卡片 / 中文错误提示
```

---

## 2. 仓库地址规范化（normalizeRepo）

输入接受三种形式，统一归一化为 `owner/repo` 后再拼 API URL：

| 输入 | 归一化结果 |
| --- | --- |
| `mtask-dev/mtask` | `mtask-dev/mtask` |
| `https://github.com/mtask-dev/mtask` | `mtask-dev/mtask` |
| `https://github.com/mtask-dev/mtask.git` | `mtask-dev/mtask` |

无法匹配时视为非法，返回中文错误「仓库地址非法」。API 域名 `https://api.github.com` **硬编码**，不接受自填地址，从机制上保证仅走 HTTPS。

---

## 3. 版本号提取（extractVersion）

从 Release 的 `tag_name` 中提取版本号，正则：`/v?(\d+(?:\.\d+)+)/i`。

| tag 输入 | 提取结果 | 说明 |
| --- | --- | --- |
| `v0.1.1` | `0.1.1` | 标准格式（约定格式） |
| `0.2.0` | `0.2.0` | 允许缺 `v` 前缀 |
| `release-v1.2` | `1.2` | 取第一个数字段 |
| `v0.1` | `0.1` | 两段也接受 |
| `beta` | `null` | 无数字段 → 报「未找到版本号」 |
| `v1.2.3-rc.1` | `1.2.3` | 预发布后缀被忽略（注意：`releases/latest` 本身不返回 prerelease） |

---

## 4. 版本比较（compareVersions）

**逐段数值比较**，段数不齐按 0 补齐：

```
compare("0.1.10", "0.1.9")  → 10 > 9   → +1  → 提示有更新
compare("0.2.0",  "0.1.99") → 2 > 1    → +1  → 提示有更新
compare("0.1.0",  "0.1.0")  → 相等     → 0  → 已是最新
compare("0.1",    "0.1.0")  → 补 0 后相等 → 0 → 已是最新（保守策略）
compare("0.0.9",  "0.1.0")  → 0 < 1    → -1 → 已是最新（远端更旧，视为无更新）
```

关键点：

- 比较是**数值**语义：`0.1.10` 大于 `0.1.9`（字符串比较会得出相反错误结论）；
- 段数不齐补 0：`0.1` ≡ `0.1.0`；
- 仅当**远端 > 当前**才提示更新，相等/更旧一律「已是最新」，避免降级误报。

## 5. 当前版本来源

`currentVersion()` 按以下顺序查找 `package.json` 并读取 `version` 字段：

1. `path.resolve(__dirname, '..', '..', 'package.json')`
   - dev 态：`server/src` → 项目根 `D:\...\26_MTask\package.json`
   - 打包态：`resources/app/server/dist` → `resources/app/package.json`（electron-builder 会把根 package.json 打入 resources/app）
2. `path.resolve(process.cwd(), 'package.json')`（兜底）

两者都不可读时回退 `0.0.0`（任何远端版本都会被判为有更新，属于可见的异常信号）。

## 6. 缓存与限流策略

| 项 | 值 | 说明 |
| --- | --- | --- |
| 成功结果缓存 | 5 分钟（TTL） | 复用全局 ttl-cache，键 `update-check` |
| 失败结果 | 不缓存 | 可立即重试 |
| force 参数 | `true` 跳过缓存 | 前端「检查更新」按钮固定传 force=true，保证用户操作即时生效 |
| GitHub 限流 | 未认证 60 次/时、认证 5000 次/时 | 5 分钟缓存 + 手动触发模式下不会触限 |

缓存失效时机：保存/修改配置（`saveConfig`）时主动 `cacheClear('update-check')`，确保新配置立即生效。

---

## 7. 下载地址选择

`releases/latest` 返回的 `assets` 列表中按优先级选取：

1. 名称匹配 `/setup|installer|\.exe$/i` 的第一个 asset（Windows 安装包）；
2. 无匹配 asset → 回退 Release 页面 URL（`html_url`）。

---

## 8. 错误映射表

| HTTP 状态 / 异常 | 映射后中文提示 |
| --- | --- |
| 超时（AbortSignal 15s） | 连接 GitHub 超时，请检查网络或代理设置 |
| fetch 网络错误 | 无法连接 GitHub（HTTPS）：\<原始信息\> |
| 404 | 仓库不存在，或该仓库尚未发布任何 Release（请先在 GitHub 创建 Release） |
| 401 | 认证凭据无效（401）：请检查 Token 是否正确、是否已过期 |
| 403 | GitHub 请求被限流（403）：未认证额度 60 次/小时，请稍后重试，或配置 Token 提升额度 |
| 其他 5xx/非 2xx | GitHub 返回异常状态 \<code\>，请稍后重试 |
| tag 无版本段 | Release 标签「\<tag\>」中未找到版本号（约定 vX.X.X），无法比较 |
| 未配置仓库 | 尚未配置 GitHub 仓库，请先在下方填写仓库地址 |

---

## 9. 安全设计要点

- Token 仅在 `fetchLatestRelease` 调用瞬间解密使用，不写日志、不进响应体；
- 数据库只存 AES-256-GCM 密文（`iv.tag.ciphertext` 三段 base64）；
- 配置读取接口 `GET /api/update/config` 仅返回 `tokenConfigured` 布尔值与 `maskSecret` 掩码；
- API 地址硬编码 HTTPS，`redirect: 'follow'` 亦仅作用于 GitHub 官方域名。
