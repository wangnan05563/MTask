# mtask 移动端优化需求 PRD

> 版本：v1.0 ｜ 日期：2026-09-30 ｜ 产出：T01387
> 适用范围：MTask Web 移动端（`web/src/mobile/`，PWA 形态，经隧道远程访问）

## 1. 背景与目标

### 1.1 背景

MTask 是「AI 任务开发管理工具」，桌面端（Electron + Web）已覆盖任务、队列、AI 编排（执行会话/监督器）、PRD/计划/需求矩阵、周报等完整闭环；移动端当前为一套约 1100 行代码的轻量 PWA（`MobileShell` 底部 5 Tab：任务 / 随手记 / 队列 / 提示词 / 更多），定位是「随手记 + 远程查看」。用户经内网穿透（tunnel）在手机上访问，核心场景是：随时随地捕捉想法（随手记）、查看 AI 执行进展、取用提示词。

移动端与桌面端的能力差距正在拉大：桌面端近期新增的执行会话监控、监督器告警、任务状态机（running/failed/unread）等「AI 监控 AI」核心能力，移动端完全不可见；移动端自身也存在只读为主的交互短板（任务不可编辑、队列不可操作）。

### 1.2 目标

1. **保持「轻」**：移动端不做桌面端的全量复制，聚焦「看进展、快捕捉、能处理紧急事项」三件事。
2. **补齐关键闭环**：让「AI 执行状态」在手机上可见、可干预（重派/熔断），把移动端从旁观者升级为遥控器。
3. **体验对齐主流开源水准**：以 Vikunja、Super Productivity 等成熟开源项目的移动端体验为基准（离线能力、快速捕捉、主题系统）。

### 1.3 非目标（本期不做）

- 不开发原生 App（iOS/Android 原生壳），继续 PWA 路线。
- 不做 PRD/需求矩阵/计划等重编辑场景的移动端实现（只读浏览即可）。
- 不做多用户协作（MTask 当前单用户架构）。

## 2. 竞品调研摘要

### 2.1 调研方法

在 GitHub 检索与 MTask 同类的任务管理开源项目，筛选标准：① star 数较高或持续维护（2026 年仍有活跃提交）；② 移动端体验有明确投入（PWA/响应式/原生 App）；③ 与 MTask 形态相似（自托管、任务/看板/时间管理）。全部数据来自 GitHub 仓库/官方 README 及第三方权威评测（2026-09 检索核实），未采信无法核实的来源。

### 2.2 核心竞品一览

| 项目 | 仓库 | Stars（约） | 技术栈 | 移动端形态 | 与 MTask 相关的亮点 |
|---|---|---|---|---|---|
| Vikunja | go-vikunja/vikunja | 4.8k | Go + Vue | 响应式 Web + 可安装 PWA | Quick Add Magic 自然语言录入；CalDAV 双向同步；列表/看板/甘特/表格四视图；Todoist/Trello 导入 |
| PLANKA | plankanban/planka | 12.4k | Node + React | 响应式 Web（有移动端专项优化 PR #776）+ iOS/Android 测试 App | WebSocket 实时同步；100+ 通知渠道；Pro 版：手机/平板专项适配、5 主题+强调色、跨项目仪表盘、卡片模板、重复卡片 |
| Super Productivity | johannesjo/super-productivity | 21.6k | Angular（Electron + PWA） | Web/Android/iOS 全平台 | 本地优先离线；v18（2026-03）移动端改进：Android 后台同步；亮/暗/Zen 多主题；未完成任务自动顺延（rollover）；短语法快速录入 |
| AppFlowy | AppFlowy-IO/AppFlowy | 70.5k | Flutter + Rust | iOS/Android 原生 | 离线优先；文档+数据库多视图；开源 Notion 替代定位，移动端交互打磨成熟 |
| Tasks.org | tasks/tasks | —（未获权威计数，不列） | Android 原生 | Android App | 日/夜主题+主题包+标签强调色；桌面小部件；位置提醒；智能重复任务（特性据 Lifehacker 评测及官方仓库） |

### 2.3 关键洞察

1. **离线优先是移动端第一公民**。四款头部竞品全部以「本地优先/离线可用」为根基（AppFlowy、Super Productivity 全量本地；Vikunja PWA + CalDAV；PLANKA 有离线测试 App）。MTask 移动端已有草稿补提雏形，但离线能力仅覆盖随手记。
2. **快速捕捉交互上限是「3 步 + 零格式」**。Google Tasks 把新建按钮放底部中央（MTask 已对齐）；Vikunja/Super Productivity 更进一步——自然语言/短语法直接解析日期、标签、优先级，「输入即结构化」。
3. **实时状态 + 通知是远程场景刚需**。PLANKA 的 WebSocket 实时同步与 100+ 通知渠道说明：远程用户对「不打开 App 也能知道变化」的需求极强。MTask 的「AI 执行中任务失败」正是最需要推送的事件。
4. **主题系统的行业水位 = 明暗跟随系统 + 自定义强调色**。PLANKA Pro（5 主题+强调色）、Tasks.org（主题包+标签强调色）、Super Productivity（含 Zen 极简主题）均已超出「明暗二选一」。
5. **移动端适合「只读浏览 + 少量高频写」的分层设计**。竞品普遍把重操作留在桌面/宽屏，移动端聚焦浏览与快速动作；MTask 现有「只读 + 跳桌面端」的思路与之一致，短板在于「高频写」太少（连任务编辑都没有）。

## 3. 移动端优化需求清单

### 3.1 客户体验

| 编号 | 需求 | 现状问题 | 方案要点 | 优先级 |
|---|---|---|---|---|
| CE-01 | 任务详情页（移动端） | 待办列表只能勾选完成，点任务无详情 | 新建 `MobileTaskDetail` 半屏抽屉：标题/描述/状态/优先级/分类/图片附件只读展示 + 完成/搁置快捷操作；底部「在桌面端编辑」深链 | 高 |
| CE-02 | 失败任务醒目告警位 | 任务 `failed`/`unread` 状态在移动首页无区分 | 首页顶部聚合条：失败 N 条 / AI 待读 N 条，点击过滤；红点常驻直至处理 | 高 |
| CE-03 | 下拉刷新 + 骨架屏统一 | 仅有首页下拉刷新；队列/提示词/更多切 Tab 无加载态 | 封装 `PullRefresh` 与 `Skeleton` 公共组件，5 Tab 统一接入；弱网下骨架屏代替白屏 | 中 |
| CE-04 | 弱网/无网体验完善 | 离线仅覆盖随手记；其他 Tab 断网直接报错 | 全局离线横幅（现有 WifiOff 图标强化为可点击查看草稿入口）；队列/任务页缓存上次数据（`stale-while-revalidate` 内存缓存），断网展示旧数据 + 「数据截至 xx:xx」角标 | 高 |
| CE-05 | 快速捕捉增强（短语法） | 随手记仅支持标题文本 | 参考 Vikunja Quick Add Magic：输入 `!high 明天 交付评审` 解析出优先级/截止日期；解析预览条在提交前展示识别结果，可手动修正 | 中 |
| CE-06 | PWA 添加到主屏引导 | manifest/SW 已具备但用户无感知 | 首次经隧道访问成功后弹一次性引导卡（截图式说明 iOS「添加到主屏幕」/Android「安装应用」），localStorage 记忆不再弹 | 低 |
| CE-07 | 触控热区与手势规范 | 部分可点击元素 < 44px | 全局走查：所有可点击元素热区 ≥ 44×44；列表项支持左滑（完成）/右滑（详情）手势，`touch-action` 防与下拉刷新冲突 | 中 |

### 3.2 功能扩展

| 编号 | 需求 | 现状问题 | 方案要点 | 优先级 |
|---|---|---|---|---|
| FE-01 | 执行会话监控页（移动） | 桌面端 `ExecSessionsPage` 能力移动端为零——「AI 监控 AI」场景手机上不可见 | 新增移动 Tab（或「更多」一级入口）：会话列表（active/stalled/failed/done 徽标 + 心跳相对时间 + phase 摘要），轮询 10s；failed 会话一键「重派」（调现有监督器 REDISPATCH 通道） | 高 |
| FE-02 | 队列移动端从只读升级为半操作 | `MobileQueue` 仅展示，编排需跳桌面端 | 保留只读卡片 + 新增：失败 Job 单条重试按钮（复用 REST 重试端点）、队列级「暂停/继续」开关；拖拽排序等重编排仍引导桌面端 | 中 |
| FE-03 | 任务创建完整化 | 移动端只能经随手记建任务，无优先级/分类/项目多选 | 随手记提交前可选：优先级（四级单选）、分类、项目（记忆上次选择）；不增加必填项，保持 ≤3 步 | 高 |
| FE-04 | 监督器事件通知（Web Push） | 任务失败/会话停滞只能在打开页面时发现 | PWA Web Push：服务端在「任务 failed / 监督器 ESCALATE」时经隧道推送（VAPID）；iOS 16.4+ PWA 支持已在能力范围；设置页提供开关与测试按钮 | 中 |
| FE-05 | 归档/历史移动只读浏览 | `MobileMore` 有入口但列表无分页无筛选 | 归档页：按月分组 + 关键词过滤；历史页：最近 7 天任务状态流转时间线 | 低 |
| FE-06 | 周报移动摘要卡 | 周报需回桌面看 | 「更多→周报」改为摘要卡：本周完成/新增/失败计数 + 趋势迷你条形图（纯 CSS 实现），完整报告仍跳桌面 | 低 |

### 3.3 UI 升级

| 编号 | 需求 | 现状问题 | 方案要点 | 优先级 |
|---|---|---|---|---|
| UI-01 | 组件规范化（对齐桌面 TasksPage 基准） | 移动端样式为散落的 inline style，与桌面端 CSS 变量体系（--text-secondary/--border-strong/--accent 等）部分脱节 | 抽取 `mobile/ui.ts` 公共样式层：卡片、列表项、徽标、半屏抽屉四类基础组件，全部走桌面端同款 CSS 变量，保证明暗主题下一致；新页面禁止新增 inline 色值 | 高 |
| UI-02 | 信息层级重构（首页） | 首页为平铺待办列表，无分组 | 按状态分组：失败/进行中（running）→ 待办 → 今日已完成；每组带计数徽标；超过 20 条折叠 | 中 |
| UI-03 | 底部导航扩展方案 | 现 5 Tab 定型，加执行会话入口需动布局 | 「更多」页改为桌面端侧栏同构的二级聚合页（图标+描述双行卡片），执行会话/归档/周报等新增入口统一落位；中央「随手记」FAB 不动 | 中 |
| UI-04 | 空态与引导统一 | 各页空态文案/插图风格不一 | 统一 `EmptyState` 组件（图标 + 一句话 + 行动按钮），文案入库 `i18n.ts` 便于双语 | 低 |

### 3.4 主题升级

| 编号 | 需求 | 现状问题 | 方案要点 | 优先级 |
|---|---|---|---|---|
| TH-01 | 明暗跟随系统 | 现仅手动切换，无跟随 | 设置项三选一：跟随系统 / 亮 / 暗；`matchMedia('(prefers-color-scheme)')` 监听实时切换 | 高 |
| TH-02 | 自定义强调色 | 强调色硬编码 `--accent`（#2563eb） | 提供 6 个预置强调色（蓝/青/紫/绿/橙/玫红）+ 自定义取色器，写入 CSS 变量并持久化；所有组件必须消费变量而非硬编码色值（依赖 UI-01 先行） | 中 |
| TH-03 | 极简阅读主题（Zen） | 无 | 参考 Super Productivity Zen 主题：去徽标/去计数/放大字号，适合通勤时只读浏览；入口放「更多→设置」 | 低 |

## 4. PC 端可复用功能清单

按「迁移价值 = 用户价值 × 移动场景契合度 ÷ 适配成本」排序：

| 排序 | PC 端功能 | 移动端迁移方案 | 可行性评估 | 优先级 |
|---|---|---|---|---|
| 1 | 执行会话监控（ExecSessionsPage + ExecSessionService） | FE-01：只读列表 + failed 重派按钮。数据全走现有 REST，无服务端改动 | 低成本高价值——「躺在床上看 AI 干活/救火」是隧道远程访问的最典型场景 | 高 |
| 2 | 任务状态机与失败告警（ai_state、expireStaleRunning） | CE-02：首页聚合告警条。零服务端改动，纯前端消费现有字段 | 低成本 | 高 |
| 3 | 队列编排（QueuePage 的重试/暂停） | FE-02：仅开放单 Job 重试与队列暂停两个幂等操作 | 中成本；REST 端点已存在，主要工作量在触控交互与防误触 | 中 |
| 4 | 主题体系（settings.tsx 的 CSS 变量切换） | TH-01/02：复用桌面端变量命名，移动端只加取色器 UI | 低成本 | 高 |
| 5 | 监督器事件流（SupervisorService/ServisorAudit） | FE-04：以监督器决策事件（ESCALATE/REDISPATCH）为推送触发源 | 中高成本——Web Push 需服务端新增 VAPID 订阅管理，建议单列迭代 | 中 |
| 6 | 历史页（HistoryPage/HistoryService） | FE-05：时间线只读复用 | 低成本，价值中低 | 低 |
| 7 | 任务图片附件（TaskImageService） | CE-01 详情页展示图片；随手记图片上传已具备 | 低成本 | 中 |
| **不建议迁移** | PRD/需求矩阵/计划编辑、DbAdmin、命令面板、隧道配置 | 移动端仅提供「查看入口跳桌面端」 | 编辑密度过高、误操作风险大、屏幕空间不足 | — |

## 6. 预期效果与下一步建议

### 6.1 预期效果（V1 完成后可度量）

1. **远程救火能力**：AI 执行失败从「次日桌面端才发现」变为「手机首页红条 + 10 秒内重派」，平均故障响应时间（MTTR）预期从小时级降至分钟级。
2. **捕捉转化率**：随手记从纯文本升级为带优先级/日期的结构化任务，随手记→有效待办的转化提升（可统计短语法使用率验证）。
3. **离线韧性**：断网场景下 5 个 Tab 全部有可用降级视图，不再出现白屏/报错。
4. **主题一致性**：移动端与桌面端明暗主题视觉完全一致，强调色可个性化。

### 6.2 下一步行动建议（纯观察提示，本单不建实施单）

1. 先核验执行会话/监督器 REST 端点在隧道鉴权下的可用性与权限粒度（FE-01 前置条件）。
2. UI-01 组件规范化是 V1 其余需求的地基，建议作为第一张开发单先行。
3. Web Push（FE-04）需先确认隧道（现有 tunnel 服务）对 VAPID 端点的支持情况，建议做一次技术预研再排期。
4. 竞品调研明细中各项目特性持续演进（如 PLANKA Pro 移动端适配、Super Productivity v19），后续版本规划时可按 2.2 表仓库链接复查。
