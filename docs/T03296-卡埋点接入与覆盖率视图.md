# T03296 未接埋点 8 卡接入 card_key + G-2 覆盖率视图

## 背景

T03172 只开了 `ai_usage.card_key` 通道与 `/api/ai/coverage` 出数，写入方仅 8 张与通道 kind 一对一的卡。
PRD G-2 的分母是「全部可用卡」，分子来自 card_key；8 张已上线卡（PRD 生成/PRD 导入/计划导入/总结 PPT/启动会 PPT/测试用例/代码评审讲稿，加原有的周报）未写 card_key 时覆盖率永远偏低，且「没人用」与「没接埋点」两态无法区分。

## 改动

### 1. 写入单源下沉

新增 `server/src/util/aiUsageRecord.ts`，把原 AIService 私有的 `recordUsage` 整体迁入（SQL 唯一一处）。
原因：PRD 生成 / 测试用例生成两个服务直连适配器（各自独立实现 `runtimeWithModel` 以避免循环依赖），
无法经 AIService 落用量；下沉到 util 后两者共用同一落库口径。AIService 改为 import。

### 2. ask/askJson/stream 显式卡

- `AIService.askJson` opts 新增 `cardKey?`，内部 4 条用量分支（预算回退/失败/成功/解析失败）全部透传。
- 各写入点显式传卡，不靠 kind 推断：

| 卡片 | 写入点 |
| --- | --- |
| `ai.prd_gen` | `PrdGenService` 主流程 chatStream（含 8K 回退）+ 兜底补问 chat（`recordUsage`） |
| `ai.prd_import` | `PlanService.aiParsePrd`（单轮）+ `aiParsePrdChunked`（分片） |
| `ai.plan_import` | `PlanService.aiParseWbs`（文档拆分）+ `aiParseDrafts`（Excel 分块） |
| `ai.summary_ppt` | `summaryPptOutline` 大纲 askJson |
| `ai.kickoff_ppt` | `kickoffService` 大纲 askJson + 风险/沟通措辞 askJson |
| `ai.test_case_gen` | `TestCaseGenService.callOnce` 每次真实调用（含回退重试） |
| `ai.code_review_lecture` | `lectureService.outlineLecture` askJson + 分段 askStream |
| `ai.weekly_report` | 既有 `ReportService`（T03243 已接，复核保留） |

### 3. 注册表

`server/src/util/aiCards.ts`：7 张卡 `metered: false → true`。16 张可用卡全部接入后，`unmeteredKeys` 归零。

### 4. 覆盖率视图（G-2）

`web/src/pages/UsagePanel.tsx` 新增「可用卡片覆盖」分区，消费 `GET /api/ai/coverage`：

- 标题行：`YYYY-MM，covered/total 张有成功生成，覆盖率 N%`；
- 基线说明直接展示服务端 `baseline.note`（首个完整月由数据推导，不手工记上线日）；
- 三态图例：**已采用**（当月有成功生成）/ **没人用**（埋点已接、当月零调用）/ **没接埋点**（写入点未写 card_key，附张数）；
- 逐卡一行：卡片名 + card_key + 分组 + 三态 + 成功/失败计数；
- 覆盖率是「整月」口径，与上方「近 N 天」用量窗口分开取数、分开标注，避免两口径同屏。
