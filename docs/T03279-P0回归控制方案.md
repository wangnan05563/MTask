# T03279 2.1 P0 回归控制方案

> 验收项（原单）：按 §7.2 排序；数据安全修复先合入并回归，不以分期为由跳过 P0；建立回归门禁。
> 取证时点：2026-10-29 ｜ 回归入口：[`scripts/run-p0-regression.mts`](../scripts/run-p0-regression.mts) ｜ 本轮结论：**PASS=12 FAIL=5，7 项 P0 无门，严格模式不放行**

## 1. 控制面：把 §7.2 的顺序变成机器可判

PRD §7.2 把 P0 分成三批：

| 批次 | 需求 | 控制含义 |
| --- | --- | --- |
| ① 阻断与数据安全 | UX-01、UX-03、UX-05、UX-06、UX-07、UX-10 | 必须先合入并回归；本批非绿则整轮不放行 |
| ② 基础入口与主题 | PM-102、PM-103、PM-301 | ① 全绿后才进入 |
| ③ 高感知能力 | PM-101、PM-105、AI-101、AI-102、AI-104、AI-301 | ①② 之后 |

落到命令上就是 `scripts/run-p0-regression.mts`：

- 按 §7.2 顺序串行跑全部已登记 P0 门，逐支打印结果与耗时；
- 首行固定 `PASS=<绿门数> FAIL=<非绿门数>`，可被 `grep '^PASS='` 取数；
- 无门的 P0 项一律打 `GAP` 行，**永不计入 PASS**；
- `--strict` 额外要求「零 GAP 且第①批全绿」，否则 exit 1——这是「数据安全修复先合入并回归」的机器可判形式；
- 默认模式只跑已登记的门，日常回归用；`--batch=N` / `--only=UX-01,PM-102` 支持按批或按项复跑。

## 2. 放行口径（与《验收门判据规约》一致）

| 结果 | 判法 |
| --- | --- |
| GREEN | exit 0，且输出无 `[FAIL]`/`FAIL` 行、无 `[SKIP]`/`SKIP` 行 |
| FAIL | 有 FAIL 行（含 exit 0 的「红但退出码未传递」——一并记红并点名） |
| BLOCK | exit≠0 且无 FAIL 行：前置件/实例未就绪，**不算绿** |
| GAP | 该 P0 项没有门，**不算绿** |

SKIP 不折算成绿、阻断不折算成绿、缺门不折算成绿——与本项目既有的「不给假绿」口径一致。
