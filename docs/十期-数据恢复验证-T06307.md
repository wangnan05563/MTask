# 十期 · 数据恢复验证（T06307 / REQ-039）

## 结论

在 T06306 备份包基础上补齐 `--restore`：**先完整校验归档，再恢复到空目录**，恢复后按 manifest 对目标文件逐项复核 SHA-256/大小、对恢复库执行 `PRAGMA integrity_check`，并落盘 `restore-report.json`。配套 `verify-t06307-restore.mjs` 覆盖 13 条恢复与完整性用例，隔离夹具 **13/13 PASS**；真实 103 MB 归档恢复到临时目录 **10 秒级完成、10 文件 223,249,777 bytes 全部一致、SQLite 校验 ok**。全程本地文件，不连接云端。

## 实现

### 恢复流程

1. `--verify` 同等强度预检：旁车 SHA-256 → 条目路径穿越检查 → 逐文件 size/SHA-256 → `PRAGMA integrity_check`。**预检不通过直接返回失败，目标目录不会创建或写入。**
2. 目标目录必须不存在或为空；非空一律拒绝，避免覆盖生产数据。
3. 解包到系统临时目录后还原：
   - `db/mtask.db` → `<target>/mtask.db`；
   - `files/a/b.txt` → `<target>/a/b.txt`（去掉 `files/` 前缀）。
4. 恢复后再次对目标文件逐项计算 SHA-256，必须与 manifest 一致。
5. 对恢复库执行 `PRAGMA integrity_check`，输出 `restore-report.json`（归档哈希、恢复时间、文件数/字节数、SQLite 结果、错误清单）。

### 安全边界

- **不覆盖现有数据**：目标非空即拒绝；生产替换需人工停服后指定空目录，脚本不自动接管生产。
- **校验前不落盘**：损坏归档、旁车哈希不符、路径越界均在校验阶段终止。
- **拒绝特殊条目**：解包只接受普通文件与目录，符号链接/硬链接/设备文件一律过滤，配合 `preservePaths=false` 防止写入逃逸。
- **不打包也不恢复 `tunnel/**`**：访问令牌敏感，恢复后需重新配置。
- 解包改用 npm `tar` 库（已声明为生产依赖），规避 Windows/sandbox 下系统 `tar` 子进程退出信号丢失导致的挂起；打包仍使用系统 tar。

## 边界（本单未做）

- **不做生产自动替换**：只恢复到空目录，停服、切换数据目录由运维人工执行；避免脚本误覆盖在线库。
- **不做 UI 一键恢复**：完成定义为“交付测试报告 + 可复核证据”，当前通过 CLI/npm 执行。
- **不做云端备份/恢复**：按任务边界只验证本地包。
- **不恢复 `tunnel/**`**：敏感配置有意排除，恢复后需重新配置隧道。
- 真实恢复抽查是**历史快照**数据，不与恢复时刻的在线库做行数差异比较；完整性以归档 manifest 字节级一致为准。
