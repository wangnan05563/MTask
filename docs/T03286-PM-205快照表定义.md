# T03286 PM-205 快照表定义（M3 3.2）

> 决策对象：项目洞察日快照的表结构、唯一性与聚合调度
> 结论：日快照落在 `metric_day_snapshots`，周期时间百分位样本单独落在 `metric_day_cycle_samples`；调度由 `MetricSnapshotService` 按业务日幂等写入
> 产品约束（PRD PM-205）：快照是**长历史唯一来源**；事件保留期不得替代快照；页面须标注真实可回溯窗口

## 1. 表结构

### 1.1 `metric_day_snapshots`（日快照）

| 列 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | 行 id |
| `project_id` | TEXT NOT NULL → projects(id) ON DELETE CASCADE | 项目维度，删项目即级联清理 |
| `stat_date` | TEXT NOT NULL | 统计日（业务日，`YYYY-MM-DD`） |
| `tz` | TEXT NOT NULL | 统计所用时区（D-12：项目时区优先，未配置回系统时区） |
| `todo_count` / `done_count` | INTEGER | 当日待办/已完成存量 |
| `created_count` / `completed_count` | INTEGER | 当日新建/完成流量 |
| `due_total` / `overdue_count` | INTEGER | 到期总数/逾期数 |
| `captured_at` / `created_at` | TEXT | 采集时刻/落库时刻 |

约束与索引：
- `UNIQUE(project_id, stat_date)` —— 同项目同业务日只有一行，重跑是覆盖不是追加
- `idx_metric_day_snapshots_project(project_id, stat_date)` —— 区间扫描走索引

### 1.2 `metric_day_cycle_samples`（周期时间原始样本）

单独成表的原因：百分位**不可跨日合并**，只存日级 P50/P90 会让任意区间无法重算；按「完成日 + 任务」落样本，区间用池化样本计算。

## 2. 写入语义（幂等）

`MetricSnapshotService` 写入路径：
- 快照行：`INSERT … ON CONFLICT(project_id, stat_date) DO UPDATE SET …`，重复采集同一天是整行刷新
- 周期样本：同业务日先 `DELETE FROM metric_day_cycle_samples WHERE project_id=? AND stat_date=?` 再批量插入，保证样本集与快照口径一致，不叠加历史
- 时区：`ymdInTimezone` 取系统/项目时区下的日历日，行内落 `stat_date + tz`，展示层标注时区

## 3. 调度与可回溯窗口

- 采集入口在 `MetricSnapshotService`（项目维度按日聚合），对外读取走洞聚合摘要（T03261 `/api/metrics/*`）
- 可回溯起点 = 该项目最早的 `stat_date`；早于它的日期一律视为**不可回溯**，页面标注真实窗口，不用事件表倒推
- 事件保留 90 天只影响明细回看，不影响快照长历史（R-03 的应对即此）

## 4. 回滚

- 两张表均为增量新建：`DROP TABLE` 即恢复原形态；不影响既有 tasks/plan_tasks/ai_usage
- 建表语句 `CREATE TABLE IF NOT EXISTS` 幂等，重启服务不会重复建表
