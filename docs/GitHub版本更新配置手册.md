# 版本更新功能 — GitHub 人工配置手册

> 适用版本：MTask ≥ 0.1.x ｜ 功能入口：设置 → 关于 → 「版本更新」模块
>
> 本手册面向需要手动配置 GitHub 仓库检查更新的用户/运维人员，全部操作均在应用界面内完成，无需修改任何代码。

---

## 一、功能概述

「版本更新」模块通过 HTTPS 访问 GitHub Releases 接口，自动拉取仓库中**最新发布的 Release**，将其版本号（tag，约定 `vX.X.X` 格式）与当前安装的应用版本比较：

- 有更新 → 展示最新版本号、发布时间、更新日志，并提供「下载新版本」入口；
- 无更新 → 提示「当前已是最新版本」。

---

## 二、仓库地址配置方法

### 步骤 1：确认仓库已发布 Release

版本检测依赖 GitHub Releases（不是 tag 本身）。若仓库只有 tag 而无 Release，检测会提示「尚未发布任何 Release」。

发布 Release 的方法：仓库页面 → **Releases** → **Draft a new release** → 选择或新建 tag（如 `v0.1.1`）→ 填写标题与更新日志 → 附加 Windows 安装包（如 `MTask-setup-0.1.1.exe`）→ **Publish release**。

### 步骤 2：在应用中填写仓库地址

打开 **设置 → 关于 → 版本更新**，在「仓库地址」输入框填写以下**任意一种**格式（应用会自动规范化）：

| 格式 | 示例 |
| --- | --- |
| `owner/repo` | `mtask-dev/mtask` |
| 完整 URL | `https://github.com/mtask-dev/mtask` |
| 带 `.git` 后缀 | `https://github.com/mtask-dev/mtask.git` |

### 步骤 3：保存

点击 **「保存配置」**。配置保存在本地应用数据库中，重启应用后仍然生效。

## 三、认证凭据获取与存储规范

### 3.1 什么时候需要 Token

| 仓库类型 | 是否需要 Token |
| --- | --- |
| 公开（public）仓库 | **不需要**，留空即可 |
| 私有（private）仓库 | **需要**，且 Token 需具备该仓库的读取权限 |

> 未认证请求受 GitHub 限流：每 IP 每小时 60 次；配置 Token 后提升至 5000 次/小时。应用内置 5 分钟结果缓存，正常使用不会触限。

### 3.2 Token 获取步骤（截图建议见括号标注）

1. 登录 GitHub → 右上角头像 → **Settings**（截图：Settings 入口位置）；
2. 左侧最底部 → **Developer settings**（截图：Developer settings 菜单项）；
3. **Personal access tokens → Fine-grained tokens** → **Generate new token**（截图：Generate new token 按钮）；
4. 填写 Token 名称（如 `mtask-updater`），设置过期时间（建议 ≤ 90 天）；
5. **Repository access** 选择「Only select repositories」→ 勾选目标仓库；
6. **Permissions → Repository permissions → Contents** 设为 **Read-only**（检测更新只需读权限，**切勿授予写权限**）；
7. 点击 **Generate token**，复制生成的令牌（`github_pat_...` 开头）。

> ⚠️ 令牌只在生成时完整显示一次，请立即复制；丢失只能重新生成。

### 3.3 在应用中配置 Token

在「访问令牌」输入框粘贴令牌 → 点击 **「保存配置」**。

### 3.4 存储规范（应用侧保证，无需用户操作）

- Token 使用 **AES-256-GCM** 加密后存入本地数据库，**不以明文落盘**；
- 加密主密钥与本机绑定（环境变量 `MTask_MASTER_KEY` 可显式指定），数据库文件拷贝到其他机器无法解出明文；
- 配置读取接口**永不返回明文 Token**，只返回「已配置」状态与掩码（如 `gith****pat_`）；
- 输入框为密码型（password），避免旁观泄露。

## 四、版本号匹配逻辑说明

应用对 Release 的 tag 按以下规则解析与比较（详细算法见《版本号自动检测逻辑说明》）：

1. 从 tag 中提取版本号：匹配 `v?数字.数字(…)` 模式，`v` 前缀可有可无；
   - `v0.1.1` → `0.1.1`；`0.2.0` → `0.2.0`；
   - tag 中无数字版本段（如 `release-note`）→ 提示无法比较；
2. 与当前版本（应用自带 `package.json` 的 `version` 字段）**逐段数值比较**，段数不齐补 0；
   - `0.1.10 > 0.1.9`（数值比较，非字符串比较）；
3. 远端版本 **大于** 当前版本 → 提示有更新；等于或小于 → 提示已是最新。

## 五、更新失败时的错误处理机制

所有失败均以**中文提示**展示在模块下方，不会中断页面使用。常见错误与处置：

| 错误提示 | 原因 | 处置方法 |
| --- | --- | --- |
| 仓库地址非法 | 输入不符合 `owner/repo` 或 URL 格式 | 检查输入格式 |
| 仓库不存在，或尚未发布任何 Release（404） | 仓库地址写错 / 无 Release | 核对仓库地址；在 GitHub 发布 Release |
| 认证凭据无效（401） | Token 错误、过期或权限不足 | 重新生成 Token 并更新配置 |
| GitHub 请求被限流（403） | 短时间请求过多 | 等待约 1 小时，或配置 Token |
| 连接 GitHub 超时 / 无法连接 | 断网、防火墙、需要代理 | 检查网络；如需代理请配置系统代理 |
| Release 标签中未找到版本号 | tag 不符合 `vX.X.X` 约定 | 在 GitHub 按 `v主.次.修订` 规范重打 tag |

错误隔离原则：

- 检查失败**不影响**应用任何其他功能；
- 检查结果缓存 5 分钟，失败结果**不缓存**，可立即重试；
- 保存配置前建议先点「测试连接」，用草稿配置验证连通（测试不落库）。

## 六、快速自检清单

- [ ] 仓库地址能通过「测试连接」（返回最新版本号）
- [ ] 私有仓库已配置只读 Token
- [ ] 最新 Release 的 tag 符合 `vX.X.X` 格式
- [ ] Release 已附加 Windows 安装包（否则「下载新版本」会跳转发布页）
