# 十期 · 可操作收件箱（T06295）

## 对应需求

| 编号 | 要求 | 本次落点 |
| --- | --- | --- |
| REQ-032 | 可操作收件箱：统一待办事项，支持分类、认领、审批、重试及批量处理 | 新增独立 `inbox_items` 事项表与 `/api/inbox` 系列接口；页面支持分类/状态/项目筛选、认领、忽略、转任务、打开任务。审批/重试/批量未纳入本单，见「边界」 |
| PRD §A2 | 分类：待我决策、AI 失败、待验证、系统、订阅（可选）；条目字段与下一步动作；未读只影响角标；open 必须被动作解决；同一事件按 key 去重；默认保留 90 天 | 四分类（订阅未纳入）；字段含 id/type/source/task_id/run_id/severity/created_at/status/assignee；未读仅角标；open 由认领/忽略/转任务/源消失解决；`event_key` 唯一索引；90 天窗口 |

## 改动

### 服务端

- 新增 `server/src/db/inboxSchema.ts`：
  - `inbox_items` 增量表，字段 `id / type / source / task_id / run_id / project_id / title / body / severity / status / assignee / event_key / unread / resolution / created_at / updated_at / claimed_at / resolved_at / last_seen_at`。
  - `status`：`open / ignored / resolved`；`type`：`decision / ai_failed / verify_pending / system`；`source`：`task / exec_session / manual`。
  - `event_key` 唯一索引去重；`(status,type,updated_at)`、`task_id`、`(unread,status)`、`(project_id,status)` 查询索引。
  - `schema.ts` 启动时调用 `ensureInboxSchema()`，老库幂等建表，不改任务/会话/通知旧表。
- 新增 `server/src/services/InboxService.ts`：
  - **同步来源（90 天窗口）**：`status=todo AND ai_state=failed` → `ai_failed/danger`；`ruling_state=待裁决` → `decision/warning`；`status=done AND verified=0` → `verify_pending/warning`；最近 50 个 `exec_sessions.status=stalled` → `system/warning`。归档、搁置、已转历史任务不进入。
  - **去重**：`task_ai_failed:{task_id}` / `task_ruling:{task_id}` / `task_verify:{task_id}` / `session_stalled:{session_id}` 唯一键 + `INSERT OR IGNORE`。
  - **自动收敛**：每次列表/摘要读取做幂等同步；仍活跃的源事件刷新 `last_seen_at`（2 分钟内不重复写），超过 10 分钟未见的 open 源条目置 `resolved + source_cleared`，避免任务修好后旧条目永久悬挂。
  - **动作**：`claim` 只写 `assignee='我'` 与 `claimed_at`，`status` 保持 open；`ignore` 置 ignored；`convert` 只允许无 `task_id` 的条目，走 `TaskService.create` 建普通任务并把条目置 resolved，`resolution=converted_to_task`，禁止转入 `sys-inbox`。
  - **计数**：`open` 与 `unread` 只算 open；分类计数按 open + 当前项目；`system` 条目无项目归属。
- `server/src/routes/index.ts` 新增：
  - `GET /api/inbox/summary?projectId=`；
  - `GET /api/inbox?status=open|ignored|resolved&type=&projectId=&limit=&offset=`（limit ≤100）；
  - `POST /api/inbox/read`（ids 可选；缺省清全部 open 未读）；
  - `POST /api/inbox/:id/claim`、`ignore`、`convert`（body `projectId`）。
  - 参数/状态/分类非法返回 400；不存在 404；终态重复动作 409。

### 前端

- 新增 `web/src/pages/InboxPage.tsx` + `inboxPage.css`：
  - `PageShell + PageHeader + FilterBar`；五个分类页签（全部 / 待我决策 / AI 失败 / 待验证 / 系统）+ 状态/项目筛选 + 转任务目标项目。
  - 行内动作按条目能力给下一步：有任务 → 打开任务；system → AI 控制台；无任务 → 转任务；待处理 → 认领、忽略。已忽略/已解决显示终态与 `resolution` 原因。
  - 打开页面成功取数后 `POST /inbox/read` 清未读，并派发 `mtaskInboxChanged` 刷新顶栏；列表分页 50 条，支持加载更多。
  - 960px 以下筛选条改为换行（页面壳默认横向滚动会把分类页签滚出可视区），760 档三档截图实测 5 个页签全部可见、无横向溢出。
- 新增 `web/src/ui/InboxBell.tsx`：顶栏收件箱按钮，**角标数 = open 数**（`99+` 封顶），未读只显示右下角小圆点；点击切 `inbox`；60s 轮询 + `mtaskInboxChanged/mtaskNavigate`/可见性刷新。
- `web/src/ui/tabs.ts` 增加 `inbox` 页面键；`primaryNavGroups.ts` 首页分组增加「概览 / 收件箱」二级页签，一级入口仍为 5 个。
- `App.tsx` 挂载 `InboxPage`、顶栏 `InboxBell`，增加 `Ctrl/Cmd+Shift+I` 直达收件箱（输入态/弹窗内不抢键）。
- `web/src/api/client.ts` 增加 `InboxType/InboxStatus/InboxItem/InboxCounts/InboxListResult/InboxSummary` 契约。

## 边界

- 本单解锁 PRD §A2 的「列表展示、分类筛选、认领、转任务、忽略、打开任务」；**未做审批/拒绝、重试、批量处理、指派、稍后**，也未接邮件。审批/重试/批量依赖现有任务审批与执行链路，应另开派生单，不把「已展示按钮」当成已交付。
- 认领是单机本地语义：`assignee` 写「我」，没有多用户账号体系，不伪造远端用户分配。
- 项目筛选只匹配条目 `project_id`；`system` 会话条目无项目归属，选中具体项目时会从列表与计数中排除（全局视图才显示），这是当前数据模型的可解释边界。
- `convert` 只对无 `task_id` 的条目开放；已有任务条目请直接打开任务，避免同一事项复制成两张任务。
- 同步在 GET 列表/摘要时发生（幂等 + 2 分钟节流 + 10 分钟收敛），首次访问 220 条真实数据约 460ms；若后续条数继续增长，应改为后台定时同步或显式 `POST /inbox/sync`，而不是继续加重每次读取。
- 默认 90 天保留只控制「是否生成新条目」，不自动删除存量 `inbox_items`；90 天清理任务需要单独实现，避免误删用户已认领/已忽略记录。
- 订阅分类未实现（PRD 标注可选）；无手工新建条目入口，当前来源全部由任务/会话事件派生。
