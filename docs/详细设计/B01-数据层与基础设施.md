# B01 数据层与基础设施

> 覆盖：`db/connection.ts`、`db/schema.ts`、`util/crypto.ts`、`util/ttl-cache.ts`、`services/AppSettings.ts`、`services/ChangeBus.ts`、`services/LogService.ts`
> 定位：系统最底层，提供数据库连接、表结构、加密、缓存、应用 KV、变更事件、日志缓冲。其余所有模块均依赖本层。

---

## 1. db/connection.ts — SQLite 单例

**职责**：进程内唯一的 better-sqlite3 连接管理。

- 导出 `getDb(): Database`（懒加载单例）。
- 连接参数：WAL 模式；失败回退 DELETE 模式；`busy_timeout=5000`；每次连接后 `wal_checkpoint`。
- 同步 API（`better-sqlite3`），所有 service 直接 `getDb().prepare(...).all/get/run`，无需 async。
- 数据目录：`MTask_DATA_DIR` 默认 `server/data`，文件 `mtask.db`（WAL 配对 `-wal`/`-shm`）。

## 2. db/schema.ts — 建表 / 迁移 / 种子

**职责**：首启动幂等建表、历史库迁移兜底、种子数据。

- 导出：`initSchema()`、`seedInboxProject()`、`seedPromptCategories()`、`ensureColumn()`、`backfillTaskNo()`、`ensureQueueJobsCascade()`。
- `initSchema()` 在 server 启动（`index.ts`）时调用，先建全部表再补索引。

**完整表（17 张，键列见概要设计 §6）**：
`projects`、`tasks`、`task_categories`、`task_images`、`ai_tools`、`queues`、`queue_jobs`、`prompt_categories`、`prompts`、`req_categories`、`req_entries`、`app_settings`、`console_jobs`、`plan_tasks`、`holidays`、`ai_usage`。

**迁移细节（幂等，对老库安全）**：
- `ensureColumn`：补列 `task_no`、`handle_result`、`parent_id`、`user_sort`、`queue_jobs.ticket/submitted_at`、`req_entries.fingerprint`、`plan_tasks.archived` 等。
- `backfillTaskNo()`：存量任务补发 `T` + 5 位数字编号（从最大序号 +1）。
- `ensureQueueJobsCascade()`：老库 `queue_jobs` 缺 CASCADE 时整表重建（rename→create→copy→drop，事务内）。
- 种子：`sys-inbox` 收件箱（确定性 id，禁止删）；5 个内置提示词分类 + 示例提示词（`builtin=1`）。

**索引**：覆盖 `tasks(project_id)`、`tasks(archived)`、`tasks(project_id,archived)`、`tasks(archived,pinned,created_at)`、`queue_jobs(queue_id,status)`、`prompts(category_id,pinned,updated_at)`、`ai_usage(created_at/tool_id,created_at)` 等。

## 3. util/crypto.ts — 加解密

**职责**：API Key / 更新 Token 加密（AES-256-GCM）。

- 导出 `encrypt(plain: string): string`、`decrypt(cipher: string): string`、`maskSecret(s: string): string`（脱敏，仅显首尾）。
- 主密钥：`MTask_MASTER_KEY` 环境变量；缺省时由本机指纹派生（仅开发兜底，生产必配）。
- 密文含随机 IV + 认证 Tag，GCM 防篡改；明文绝不落日志。

## 4. util/ttl-cache.ts — 极简 TTL 缓存

**职责**：内存 KV 缓存，读多写少列表提速。

- 导出 `cacheGet(key)`、`cacheSet(key, val, ttlMs?)`、`cacheClear(prefix?)`。
- 默认 TTL 5s；`ai-tools/models` 用 5min；写端点主动 `cacheClear` 保持一致。
- 用于：`projects`、`prompt-categories`、`req-categories`、`queues`、`report-templates`、模型列表。

## 5. services/AppSettings.ts — 应用 KV

**职责**：`app_settings` 表的键值读写。

- 常量 `INBOX_PROJECT_ID = 'sys-inbox'`。
- 导出 `getSetting(key)`、`setSetting(key, value)`、`getDefaultNoteProjectId()`（用户设置优先，否则收件箱）。
- 存储项：默认记事项目、队列自动完成任务开关 `queue.autoCompleteTask`、报表推送收件箱 `report.aiSummaryToInbox` 等。

## 6. services/ChangeBus.ts — SSE 变更事件总线

**职责**：后端→前端的实时变更通知源。

- 导出 `changeBus`（EventEmitter）、`notifyChange(kind: 'tasks'|'plans'|'queue')`。
- 各 service 在数据写后调用 `notifyChange`；`index.ts` 的 `GET /api/events` 订阅并向 EventEmitter 监听者 `res.write` SSE 帧；含 25s 心跳防代理超时。

## 7. services/LogService.ts — 后台日志环形缓冲

**职责**：劫持 `console.*`，供前端「日志」页增量查看。

- 导出 `logService`（单例）：`init()`（尽早拦截 console）、`list(since?: number)`、`push()`。
- 环形缓冲上限 2000 条，每条带自增 `seq`；`GET /logs?since=` 增量拉取。
- server ready / 慢请求日志 / 错误均经此进入缓冲，前端 LogsPage 按 `seq` 游标轮询。

---

## 依赖与边界

- 依赖：`better-sqlite3`、`node:crypto`、`node:fs`。被 **所有** service / route 依赖（最底层，不反向依赖业务）。
- 边界：连接参数与数据目录由环境变量控制；迁移函数对老库安全（事务内重建）；密钥主密钥缺失时仅开发兜底，生产环境必须由部署注入 `MTask_MASTER_KEY`。
