> 版本：v7.0（2026-10-26）
> 上游：`docs/概要设计-七期增量-项目管理与AI工作台优化.md`（T03155）、`docs/PRD评审报告-MTask-项目管理与AI工作台优化-整合版.md`（T03154）
> 范围：本项目 PRD 49 条需求涉及的**数据模型增量**与**接口契约**；既有接口不重复描述。
> 关联任务：T03156（本文件）

---

## 1. 设计约定

| 项 | 约定 |
|---|---|
| 基础路径 | `/api/*`，统一 `X-Access-Token`（`scope=read` 仅放行 GET）与 CSRF 守卫 |
| 时间 | 落库保持原值；纯日期字段 `YYYY-MM-DD`；业务日投影走 `timePrimitives` |
| 缺省值 | 缺失用 `null` 表达，不用 `0`/空串冒充；展示层统一占位符 |
| 分页 | `{ items, total, page, pageSize }`；结构化搜索的 `total` 必须为过滤后总数 |
| 幂等 | 写操作支持 `Idempotency-Key`（外发/分享/重派）；重复键返回首次结果 |
| 错误体 | `{ error: { code, message, details? } }`；HTTP 4xx/5xx 与 code 一一对应 |

## 2. 数据模型增量

### 2.1 已落地（既有，供设计对齐）

```sql
-- ai_usage：D-05 卡片维度（幂等加列 + 索引）
ALTER TABLE ai_usage ADD COLUMN card_key TEXT NOT NULL DEFAULT 'unknown';
CREATE INDEX IF NOT EXISTS idx_ai_usage_card ON ai_usage(card_key, created_at);

-- prompts：D-06 使用计数
ALTER TABLE prompts ADD COLUMN usage_count INTEGER NOT NULL DEFAULT 0;
```

### 2.2 本期新增表（草案）

```sql
-- 迭代：D-02 —— 计划行的带时间集合，不建立任务排期模型
CREATE TABLE IF NOT EXISTS project_iterations (
  id          TEXT PRIMARY KEY,
  project_id  TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  goal        TEXT DEFAULT '',
  dod         TEXT DEFAULT '',              -- 完成定义（Definition of Done）
  start_date  TEXT NOT NULL,                -- YYYY-MM-DD
  end_date    TEXT NOT NULL,
  status      TEXT NOT NULL DEFAULT 'todo', -- todo/doing/done（仅容器状态，不是任务状态）
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_iter_project ON project_iterations(project_id, start_date);

-- 计划行归属（可空：未规划）
ALTER TABLE plan_tasks ADD COLUMN iteration_id TEXT;

-- Webhook 订阅（outbound，PM-402）
CREATE TABLE IF NOT EXISTS webhook_subscriptions (
  id          TEXT PRIMARY KEY,
  project_id  TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  url         TEXT NOT NULL,
  secret      TEXT NOT NULL,               -- 仅用于签名，接口返回脱敏
  events      TEXT NOT NULL,               -- JSON 数组，白名单：task.done/task.verified/plan.done/...
  enabled     INTEGER NOT NULL DEFAULT 1,
  created_at  TEXT NOT NULL
);

-- 投递回执（逐条，PM-402 ④）
CREATE TABLE IF NOT EXISTS webhook_deliveries (
  id              TEXT PRIMARY KEY,
  subscription_id TEXT NOT NULL REFERENCES webhook_subscriptions(id) ON DELETE CASCADE,
  event           TEXT NOT NULL,
  dedup_key       TEXT NOT NULL,
  payload         TEXT NOT NULL,
  status          TEXT NOT NULL,           -- pending/ok/failed
  attempts        INTEGER NOT NULL DEFAULT 0,
  last_error      TEXT DEFAULT '',
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL,
  UNIQUE(subscription_id, dedup_key)
);

-- 脱敏分享快照（PM-404，只读）
CREATE TABLE IF NOT EXISTS share_snapshots (
  id          TEXT PRIMARY KEY,
  project_id  TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  scope_json  TEXT NOT NULL,               -- 导出范围（页面/筛选/列集）
  token       TEXT NOT NULL UNIQUE,        -- 访问凭据（随机，不入日志）
  expires_at  TEXT,
  revoked_at  TEXT,
  created_at  TEXT NOT NULL
);
```

> 迁移策略：全部 `IF NOT EXISTS` / `ensureColumn`，在 `initSchema()` 尾部执行；回退只需忽略新列/新表，旧路径不引用即安全。

### 2.3 无新表的派生对象

| 派生对象 | 数据来源 | 说明 |
|---|---|---|
| 逾期计划 | `plan_tasks(end_date,status,progress)` + 业务日 | 逾期率 = 逾期行数 / 有效行数；两者同时返回 |
| 燃尽 | `plan_tasks` + `task_events` + `holidays` | 按业务日采样，缺失日不插值 |
| 项目洞察 | 上述聚合 + `ai_usage` | 只读，响应带 `sampleSize` |
| 卡片覆盖率 | `ai_usage.card_key` × `aiCards` 注册表 | 分母剔除禁用/未发布卡 |

## 3. 接口契约

### 3.1 结构化搜索（PM-102）

```
POST /api/tasks/search
{ "expr": "status:todo AND project:P1 (priority:high OR priority:normal)",
  "page": 1, "pageSize": 50, "sort": "updated_at:desc" }
→ 200 { "items": [...], "total": 1234, "page": 1, "pageSize": 50,
        "degraded": false, "hint": "" }
```

- 语法：字段白名单 `status/priority/project/category/verified/derived`；支持 `AND/OR/NOT`、括号、引号短语；大小写不敏感。
- 非法语法：`degraded=true`，退化为全文模糊，`hint` 返回首个错误位置与说明。
- 无语法：保持既有模糊匹配语义。
- **实现约束**：解析为 AST → 生成参数化 SQL 片段（字段白名单，禁止拼接原始串）→ 在 DB 全集执行后再分页；禁止先在内存取前 500 条过滤。
- 性能目标：1000 条数据集 ≤300ms（验收门断言）。

### 3.2 看板设置（PM-101）

```
GET  /api/projects/:id/board-settings
→ { "wipLimit": 10, "hiddenEmptyCols": ["done"] }        // hiddenEmptyCols 仅会话级，前端不落库
PUT  /api/projects/:id/board-settings
{ "wipLimit": 12 }                                        // 1..50，越界 422
→ { "wipLimit": 12 }
```

- WIP 计数口径：仅统计 `status='todo'` 的卡片；`done` 列不告警。
- 全部项目混合视图只显示数量，不应用某项目上限（PRD PM-101 ⑥）。

### 3.3 迭代（PM-201）

```
GET    /api/projects/:id/iterations?status=doing
POST   /api/projects/:id/iterations
{ "name": "S1", "goal": "…", "dod": "…", "startDate": "2026-10-01", "endDate": "2026-10-14" }
→ 201 { "id": "…" }

PUT    /api/iterations/:id
{ "name"?, "goal"?, "dod"?, "status"? }                   // status: todo/doing/done

POST   /api/iterations/:id/attach
{ "planTaskIds": ["…"], "mode": "add" }                   // mode=add|replace
→ { "attached": 12, "skipped": ["…越过时间窗…"] }

GET    /api/iterations/:id
→ { ...iteration, "planTasks": [{id,title,start_date,end_date,progress,status}] }
```

- 时间窗外计划行允许手动挂载，但响应必须回 `skipped` 原因（不静默丢弃）。
- 删除迭代：`DELETE` 仅解绑（`iteration_id=null`），不删计划行。

### 3.4 燃尽与预测（PM-205 / PM-204 / AI-204）

```
GET /api/projects/:id/burndown?from=2026-10-01&to=2026-10-31
→ { "points": [{ "day": "2026-10-01", "remaining": 42, "ideal": 50 }],
    "missingDays": ["2026-10-07"], "tz": "Asia/Shanghai", "sampleSize": 30 }

GET /api/plans/:id/forecast
→ { "method": "time-progress@1", "expectedEnd": "2026-11-12",
    "range": ["2026-11-05", "2026-11-20"], "basis": { "progress": 40, "elapsed": 12, "workdays": 22 },
    "confidence": "low|medium|high", "reasons": ["progress<30%"] }
```

- 里程碑（`kind='milestone'`）预测走**子项聚合**模型，普通计划行走**时间进度**模型；两者不共用公式（D-03）。
- 缺失业务日进 `missingDays`，不插值；置信度必须有 `reasons`。

### 3.5 项目洞察（PM-205）

```
GET /api/projects/:id/insights?period=30d
→ { "sampleSize": 128, "overdue": { "count": 7, "rate": 0.067, "valid": 104 },
    "throughput": { "perWeek": 9.2 }, "aiUsage": { "calls": 210, "cards": 6 },
    "notes": ["样本量 < 30 条，比率仅供参考"] }
```

- 规则：`valid`（分母）与 `count` 同时返回；`sampleSize` 不足时 `notes` 必须包含提示（禁止 0% 冒充）。

### 3.6 AI 预估与生成（AI-101～104、AI-301、D-04）

```
GET  /api/ai/cards                                   // 注册表单源（meteured 状态）
POST /api/ai/preflight
{ "cardKey": "ai.summary_ppt", "projectId": "…", "scope": {…} }
→ { "available": true, "reason": null,
    "estimate": { "version": "est@1", "calls": [2,3], "chars": [18000,26000], "seconds": [40,90] } }

POST /api/ai/generate
{ "cardKey": "ai.summary_ppt", "projectId": "…", "scope": {…}, "idempotencyKey": "…" }
→ { "jobId": "…" }                                    // SSE/轮询取进度
```

- 预估只含次数/字符量/耗时，**不得出现金额字段**（D-04）。
- 不可用统一 `{available:false, reason:{code,message,fixAction}}`（D-14）。
- 调用点必须显式传 `cardKey`（8 张卡），通用通道不得按 `kind` 推断。

### 3.7 覆盖率与用量（G-2、AI-301、D-11）

```
GET /api/ai/coverage?month=2026-10
→ { "cards": [{ "cardKey": "ai.prd_gen", "metered": true, "published": true,
                "calls": 12, "state": "metered|unmetered|unused" }],
    "denominator": 9 }
```

- 分母：已发布且启用的卡；`state` 区分「没人用（unused）」与「没接埋点（unmetered）」。
- 排序：优先精确 `card_key` 频率；历史不足用默认序（D-11）。

### 3.8 执行会话（AI-402、D-10）

```
GET  /api/exec-sessions?projectId=…&visible=1
→ { "items": [{ "id":"…", "taskNo":"T03177", "state":"active|stalled|failed|done",
                "phase":"验证与回传", "lastHeartbeatAt":"…", "taskId":"…" }],
    "serverTime": "…" }

POST /api/exec-sessions/:id/redispatch
{ "reason": "stalled", "idempotencyKey": "…" }
→ { "newSessionId": "…", "reused": false }
```

- 刷新双档由前端控制：可见 2s / 隐藏 15s（不在服务端推送）。
- 重派复用 `RelayDispatchService` 单引擎；原会话保留为历史，不删除。

### 3.9 批量与回执（PM-105、UX-02）

```
POST /api/tasks/bulk
{ "action": "status|priority|category|archive|delete", "ids": ["…"], "value": "done" }
→ { "ok": 18, "failed": [{ "id": "…", "taskNo": "T…", "reason": "…" }], "undoToken": "…" }

POST /api/tasks/export-selected
{ "ids": ["…"], "format": "csv|xlsx" }      // 仅所选；沿用既有格式
→ 文件流（响应头带 `X-Exported-Count`）
```

### 3.10 Webhook 与分享（PM-402 / PM-404）

```
POST   /api/webhooks            { "projectId":"…", "url":"https://…", "events":["task.done"], "secret":"…" }
GET    /api/webhooks?projectId=…    → secret 脱敏为 `whsec_***`
PATCH  /api/webhooks/:id        { "enabled": false }
GET    /api/webhooks/:id/deliveries?status=failed   → 逐条回执

POST   /api/shares              { "projectId":"…", "scope": {…}, "expiresInDays": 7 }
→ { "token": "…", "url": "…" }
POST   /api/shares/:token/revoke
```

- 投递签名：`X-MTask-Signature: t=<ts>,v1=HMAC_SHA256(secret, ts + "." + body)`；重试 1/5/30 分钟，最多 3 次，`dedup_key = sha256(event+entityId+version)`。
- 分享快照：只读 token、可过期、可撤销；脱敏字段清单固定（负责人邮箱、本地路径、token、密钥一律剔除）。

## 4. 口径公式（单源）

| 指标 | 公式 | 边界 |
|---|---|---|
| WIP 超限 | `count(tasks where status='todo' and project=X) > wipLimit` | done 列不计；混合视图不告警 |
| 逾期率 | `overdue / valid`；`valid` = 有 `end_date` 的计划行（分母口径见 D-12 统一测试） | 业务日按项目时区；边界日是否含当日由统一测试固定 |
| 燃尽剩余 | 当日未完成计划行数 | 缺失日不插值 |
| AI 成功率 | `done_jobs / (done_jobs + failed_jobs)`，用户取消不进分母 | 部分产物不得计 done |
| 覆盖率 | `metered_cards_with_calls / published_enabled_cards` | 三态区分 |
| 预估偏差 | `(actual - estimate) / estimate` | 仅提示，不阻断 |

## 5. 验收映射（可进命令门）

| 接口/规则 | 断言方式 |
|---|---|
| 结构化搜索全集过滤 | 造 501+ 条，第 501 条起仍能命中；`total` 与 DB 计数一致 |
| 看板 WIP | 造 11 条 todo → 超限文案出现 N；done 列不告警 |
| 燃尽/预测 | 固定数据集 + 固定时区，断言 `points` 与 `missingDays` |
| 覆盖率三态 | 造 unmetered/unused/metered 各一卡，断言 `state` |
| 会话重派 | 重派后原会话状态不变、新会话 active、`reused=false` |
| Webhook 签名 | 断言 HMAC 与 `dedup_key` 唯一约束 |
| 分享脱敏 | 断言响应中无 email/本地路径/token |

## 6. 兼容与回退

1. 新表新列全部可空/有默认；旧版本代码忽略即安全。
2. 接口向后兼容：仅新增可选字段；旧字段语义不变。
3. 关闭开关（`app_settings`）：`webhook.enabled`、`share.enabled`、`search.structured` 任一关闭时回退旧路径。
4. 回退演练：用生产库副本启动旧二进制度读一遍关键页面（不做写操作），确认无 `no such column` 类崩溃。
