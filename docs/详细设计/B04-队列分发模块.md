# B04 队列分发模块

> 覆盖：`services/QueueService.ts`
> 定位：AI 任务分发队列的构建、触发、Job 状态机、异步提交/轮询收口。FR4（队列构建/发送/回执/重试）。

---

## 1. 状态机

- **Job**：`queued → sending → success | failed | timeout`
- **Queue**：`draft → running → finished | failed`
- 仅 `draft` 队列可编辑（追加/删除 Job）；发送后进入 `running`，全部收口后收敛为 `finished`。

## 2. 关键方法

| 方法 | 作用 |
|------|------|
| `create(name, date)` | 新建当日队列 |
| `getById(id)` / `list()`（5s 缓存） | 查询 |
| `addJobs(queueId, items)` | 追加 `{taskId, toolId}[]` 为 `queued` Job（单事务，仅 draft 可编辑） |
| `sendAll(queueId, send)` | **同步路径**：串行保序逐 Job `send()`，写 `response_payload`/`error`，队列置 `finished` |
| `submitAll(queueId, submit)` | **异步路径**：逐 Job `submitOneJob`；同步即返→`success`，异步受理→`sending`+记 `ticket/submitted_at`；尚有在途则队列保持 `running` |
| `submitOneJob(job, submit)` | 单 Job 提交；`accepted=true` 返回 `true`（在途），否则 `false` |
| `pollPending(poll)` | **异步收口**：被主循环每 5s 调用；遍历 `status='sending' AND ticket IS NOT NULL` 的 Job，`poll(ticket)`：`success→写回并完成`、`failed/timeout→写失败`；队列内无在途 sending 时收敛 `finished` |
| `resetFailed(queueId)` | `failed/timeout` 重置 `queued` |
| `snapshotTaskContext(job)` | 发送前固化任务上下文到 `request_payload`（避免任务被改导致回执错位） |
| `autoCompleteQueueTask(taskId)` | 成功后置待办 done（受 `AppSettings.queue.autoCompleteTask` 开关，默认开），触发计划联动 |

## 3. 依赖与服务启动

- 依赖：`TaskService`、`AIService`（构建 sender/submitter/poller）、`ChangeBus`、`LogService`、`AppSettings`、`ttl-cache`。
- 涉及表：`queues`、`queue_jobs`、`tasks`。
- **主循环收口**（`server/src/index.ts` 末尾）：`setInterval(() => QueueService.pollPending(AIService.buildPoller()), 5000)`；`.catch` 兜底避免单次异常中断定时器；进程常驻随 Electron 存活。

## 4. 核心流程

1. **同步发送**：`POST /queues/:id/send` → `sendAll` → `buildSender().send(job)` 串行保序 → 逐 Job 写 `response_payload` → 队列 `finished`。
2. **异步提交**：`POST /queues/:id/submit` → `submitAll` → `buildSubmitter().submit(job)` → 同步即时 `success`，异步 `accepted` 则 `sending`+`ticket` → 队列 `running`。
3. **轮询收口**：每 5s `pollPending(buildPoller())` → `adapter.poll(ticket)` → `success` 写回 + `autoCompleteQueueTask`（置 done → 触发计划联动）→ 无在途则队列 `finished`。
4. **重试**：`POST /queues/:id/reset` → `resetFailed` 把 `failed/timeout` 重置 `queued`，可重新 `submit`。

## 5. 边界与异常处理

- **上下文快照**：发送前固化 `request_payload`，回执与发送时任务快照对齐，避免任务被改导致错位。
- **超时降级**：`buildPoller` 中 `running` 且 `elapsed > config.timeoutMs` 降级为 `timeout`，可重置重发。
- **收口幂等**：`pollPending` 仅处理 `sending AND ticket` 的 Job，已终态不重复处理。
- **采纳语义**：Job 回执仅保存文本（`response_payload`），人工审阅后「采纳」才写 `ai_summary` 并置 done（呼应 Plandex Review Sandbox 思路）。
