# B08 配置 / 更新 / 迁移模块

> 覆盖：`services/ConfigService.ts`、`services/UpdateService.ts`、`services/SettingsService.ts`
> 定位：AI 工具配置（密钥加密/默认绑定）、GitHub 版本更新检查、跨机数据迁移 bundle。FR3 / 更新 / 迁移。

---

## 1. ConfigService — AI 工具配置

**职责**：AI 工具 CRUD、连接测试、模型列表、密钥加解密、默认工具、运行时配置。

**关键方法**：
- `list` / `listAdapterTypes` / `create` / `update` / `remove`
- `testDraft`（草稿连接测试，不落库）/ `testConnection`（已保存工具）
- `listModelsDraft` / `listModels`（解密密钥，5min 缓存）
- `getApiKey(id)`：按需解密返回明文（界面默认脱敏）
- `getDefaults` / `setDefault(id, kind)`：`is_default_organize` / `is_default_develop` 互斥（每种用途单默认）
- `getRuntimeConfig(toolId)`：解密 `api_key_enc` 注入 `ToolConfig`，供 AIService 运行时使用

**依赖**：`util/crypto`、`adapters/*`、`util/ttl-cache`；表 `ai_tools`。
**边界**：密钥仅加密落库（`api_key_enc`），界面脱敏；未配置 `model` 时 `AIService.runtimeWithModel` 抛 `MODEL_UNCONFIGURED`（前端提示先配模型，不静默回退）。

## 2. UpdateService — 版本更新

**职责**：GitHub Releases 版本检查。

**关键方法**：`currentVersion` / `getConfig` / `saveConfig` / `testConfig` / `checkUpdate`。
- 配置：repo（`owner/repo` 规范化）、token（AES 加密存储）。`checkUpdate` 5min 缓存。
- REST：`GET /update/version`、`GET/POST /update/config`、`POST /update/test`、`POST /update/check`。

## 3. SettingsService — 数据迁移（换机）

**职责**：全量业务数据 bundle 导出/导入。

**关键方法**：`exportBundle()` / `importBundle(data, mode)`。
- **模式**：`overwrite`（清空覆盖）/ `keep`（保留已有 id）/ `merge`（覆盖同名 id）。
- API Key：导出时明文导出，导入时按本机主密钥重加密（避免跨机密钥不可用）。
- 单事务导入，失败自动回滚；危险操作 `overwrite` 前端二次确认（不可恢复）。
- REST：`GET /settings/export`、`POST /settings/import {data, mode}`。

## 4. 依赖与边界

- `ConfigService` 依赖 `crypto`、`adapters`、`ttl-cache`；`UpdateService` 依赖 `crypto`、GitHub API；`SettingsService` 依赖全部业务表 + `crypto`（密钥重加密）。
- 边界：
  - 密钥主密钥缺失时导出/导入的密钥重加密仅开发兜底；生产环境须注入 `MTask_MASTER_KEY`。
  - `overwrite` 会清空并替换全部数据，操作不可恢复。
  - 默认工具每种用途单例（互斥），避免歧义。
  - 更新 token 加密存储，界面脱敏；`checkUpdate` 缓存 5min 防止频繁打 GitHub。
