### 0.2 整合原则

1. **不复制竞品，不推翻既有产品边界**：坚持本地优先、单机单用户、任务 `todo/done` 二元状态、AI 任务闭环和 RTM 全链路优势。
2. **先修数据安全与核心阻断，再扩能力**：静默丢稿、覆盖无确认、重复导入、核心链路必败、键盘不可达优先于新实体与高级分析。
3. **同一能力只保留一个行为定义**：合并命令面板、移动端、主题、可访问性、AI 卡片、执行会话等重叠需求；原编号保留在来源栏。
4. **指标必须可观测**：没有数据源的指标先补最小埋点，不以估算值冒充真实用量或金额。
5. **外部已批准 PRD 不重写**：AI-202、AI-205 仅登记范围、排期和依赖，验收仍以其原 PRD 为准。

## 1. 背景与目标

### 1.1 背景

MTask 已具备任务/看板、计划/甘特/时间线、里程碑、需求矩阵、测试用例、估算、提示词仓库、多厂商模型配置、AI 能力卡以及“派发—执行—回传—通知”闭环。两份来源文档分别指出两类互补问题：

- **能力层**：[C] 认为迭代、过程洞察、Webhook、模型路由、生成溯源等能力需要补齐，同时必须避免照搬多人协作、任务三态和自动写码等不符合当前定位的能力。
- **体验与质量层**：[U] 发现现有链路仍存在内容静默丢失、重复导入、失败态误导、键盘不可达、产物难找回、导航缺失和移动端入口不完整等问题。

因此，本次优化不是单纯“加功能”，而是以**核心链路可信、关键操作可达、生成结果可解释**为底座，再逐步扩展项目管理和 AI 能力。

## 4. 范围与非目标

### 4.1 本期范围

- 桌面端现有九个一级菜单、设置、命令面板和全局反馈机制的体验整改。
- 项目管理的看板、迭代、预测、洞察、集成与分享能力。
- AI 工作台的生成可靠性、溯源、模板、卡片组织、模型路由与 Agent 会话可观测性。
- 移动端任务核心链路及需求/计划只读入口。
- 为指标和可靠性所需的最小、向后兼容数据迁移。

### 4.2 非目标

1. 不引入多人实时协作、角色权限或组织体系。
2. 不改变任务二元状态机，不新增任务截止日，不把计划 `deps` 与任务阻塞关系合并。
3. 不在移动端提供甘特编辑、计划复杂编辑或完整桌面功能复制。
4. 不实现 Issue→自动写码→提交 PR 的编码代理；AI-201 仅只读代码问答。
5. 不做真实 token/金额计费，不用字符量伪装金额。
6. 不做 inbound Webhook；外部写入仍经既有 API Token/MCP 边界。
7. 不因竞品存在而重构已有 RTM、估算、AI 闭环和主题机制。
8. macOS/Linux 桌面打包、完整 UI 一次性 i18n 迁移不在本版承诺内。

### 4.3 核心对象与统一口径

| 对象 | 本 PRD 定义与边界 |
|---|---|
| 任务 | 执行待办，状态仅 `todo/done`；没有任务级截止日、迭代直接归属或第三态 |
| 计划行 | 有起止日期/工期/进度的计划实体，是迭代、逾期和计划预测的直接对象 |
| 里程碑 | 特殊计划行，按子项聚合；预测依据子项进度，不与普通计划行的时间进度模型混用 |
| 需求 | 可关联计划、任务和用例；PRD 导入、AI 计划导入必须保留该关联体系 |
| 迭代 | 项目下带起止日期、目标和完成定义的计划行集合；不是新任务状态或跨项目任务容器 |
| AI 卡 | 一项配置化产品能力；有稳定 `card_key`、前置条件和可用状态，不等同于 AI 通道 `kind` |
| AI job / segment | job 是用户一次生成任务，segment 是其分段；G-3 按 job 统计，重试 segment 不重复生成成功 job |
| 执行会话 | 外部 Agent 的执行实例；与 AI 卡生成 job、队列项分开建模和统计 |
| AI 用量 | 调用次数、字符量、耗时等代理指标；`card_key` 标识能力，不表示 token 或金额 |
| 逾期计划 | 在统计业务日已到期且未完成的有效计划行；逾期率与逾期数量分别呈现 |

## 5. 功能需求

**优先级定义**：P0=当前基线必须先完成的数据安全、核心阻断和高感知能力；P1=下一阶段的完整能力与一致性；P2=依赖数据积累、深度定制或较高成本能力。优先级不等于工时承诺。

**需求规模**：本版共 49 条功能需求。其中 [C] 的 35 条全部保留并直接使用原编号；另有 14 条 UX 归并需求（UX-01～UX-14）用于承载 [U] 的具体缺陷、规范与低频增强。

### 5.1 任务、导航与列表

#### PM-101 看板列设置与 WIP 软上限
- **优先级 / 来源**：P0 ｜ [C:PM-101]
- **需求**：列头显示实时任务数；支持隐藏空列；项目级 WIP 上限默认 10、可配 1～50，超限只做橙色软提示。
- **验收**：① 数量随任务变化实时更新；② WIP 只统计未完成 `todo` 卡片，`done` 列不告警，超限显示“超出建议上限 N”；③ 修改即时生效；④ 隐藏空列在会话内保持；⑤ 不阻断任务拖入；⑥ 全部项目混合列只显示数量，具体项目视图才应用该项目上限，避免跨项目口径混淆。

#### PM-102 命令面板、结构化搜索与键盘导航
- **优先级 / 来源**：P0 ｜ [C:PM-102；U:U36～U38]
- **需求**：统一命令面板入口、命名、搜索语法、结果定位和快捷键；页面列表从 `TABS` 单源生成。

### 5.5 设置、移动、集成与分享

#### PM-104 移动端核心链路与只读项目入口
- **优先级 / 来源**：P1 ｜ [C:PM-104；U:U41]
- **需求**：移动端支持任务状态、新建任务、通知和周报；更多中新增需求/项目计划只读入口；甘特只读。
- **验收**：① todo↔done 与桌面同步；② 新建含标题/优先级/项目；③ 通知可读并跳任务；④ 周报只读可见；⑤ 需求与计划无需“切桌面版”即可进入只读视图；⑥ 甘特明确只读且无编辑控件误导。

#### PM-401 项目级 outbound Webhook
- **优先级 / 来源**：P1 ｜ [C:PM-401]
- **需求**：按项目订阅任务/计划/逾期事件，HTTPS only、HMAC-SHA256、指数退避重试和投递日志；不含 inbound。
- **验收**：① 可增/改/停用 URL、事件和密钥；② 事件后 ≤5 秒首次投递，请求超时有明确上限；③ `X-MTask-Signature` 可验证，payload 含事件 ID+时间戳以支持接收方幂等；④ 失败后按 1/5/30 分钟重试三次并记录，日志保留 30 天，应用重启后待重试项可恢复；⑤ 非 HTTPS、URL 内嵌凭据和重定向到非 HTTPS 均拒绝，内网地址须显式确认；⑥ 停用后不再投递并取消未执行重试；⑦ 密钥加密存储，payload 按事件白名单最小化，URL/响应日志脱敏。

#### PM-402 导入导出扩展
- **优先级 / 来源**：P2 ｜ [C:PM-402]
- **需求**：支持 GitHub Issues CSV、Jira CSV 和通用字段映射预览；任务/计划可导出 Markdown/JSON。
- **验收**：① 两类外部 CSV 自动识别约定字段；② 映射可人工调整；③ 错误行逐条点名且不静默丢弃；④ Markdown 含任务树/状态/优先级；⑤ 1000 行导入 ≤30 秒；⑥ 导入结果回执复用 UX-02 规范。

#### PM-403 多时区与时间展示
- **优先级 / 来源**：P2 ｜ [C:PM-403]
- **需求**：默认系统时区，可按项目设置显示时区；报告和导出物带时区信息。
- **验收**：① 时间首次出现有时区标识；② 项目截止日期按项目时区渲染；③ 导出含时区元信息；④ 未设置时明确跟随系统；⑤ 跨夏令时测试日期不偏移。

#### PM-404 脱敏分享快照
- **优先级 / 来源**：P2 ｜ [C:PM-404；整合 D-09]
- **需求**：导出项目统计、里程碑和逾期计划摘要，可选是否含任务标题；不包含多人协作或权限能力。

- **优先级 / 来源**：P1 ｜ [U:U31～U32]

### 7.3 关键依赖

## 8. 验收标准与质量门禁

### 8.1 需求级验收

1. 第 5 章每条需求的具体验收项全部通过；标“外部 PRD 登记”的两条按原文验收。
2. 每条需求须留下可复现证据：自动化测试、截图/录屏、性能采样、API 响应或数据库断言之一，不接受仅以“页面看起来正常”结论。
3. P0 的 G-6 缺陷集必须逐条回归，尤其是重复导入、取消覆盖、双向导和键盘可达。

### 8.2 系统级验收

| 门禁 | 通过标准 |
|---|---|
| 构建与静态检查 | 服务端、Web 类型检查和生产构建通过；新增 lint/视觉/可访问性门禁无未解释豁免 |
| 核心 E2E | 新项目→PRD→需求→计划→任务→AI 周报→产物打开全链路通过；失败/取消/重试分支同步覆盖 |
| 数据正确性 | 转计划携带正确项目 ID；重复导入无重复；迁移幂等；预测/逾期同一数据单源同值；统计字段真实落库 |
| 状态与恢复 | 加载失败不冒充空态；刷新/切页后长任务可恢复；未保存内容按需求被保护；错误明细可回看 |
| 双端与双主题 | 桌面九页、设置、移动核心链路在浅色/暗色下通过；最小窗口、窄屏和最大字号无关键操作遮挡 |
| 键盘与读屏 | G-7 核心路径通过；NVDA 三流程冒烟通过；无 `button button`；焦点顺序可预期 |
| 性能 | NFR-01 在约定数据集上留采样结果；未达项不得用平均主观体验替代 |
| 安全 | 代码问答无写/执行路径；Webhook 签名/停用/重试验证；分享快照与日志敏感字段扫描通过 |

### 8.3 指标与 AI 质量验收

- G-1 固定卡种、数据集、模型与硬件，样本包含首次确认、流式生成、必要重试和下载，报告 P50/P90；不得只用顺利样本。
- G-2 由 `card_key` 和卡片可用状态出数；G-3 按 job 统计，重试/取消/部分产物按 §1.2 口径；G-4 由计划行和快照出数。
- AI-203 在固定标注集上报告分类/优先级准确率及 shown/accepted/dismissed/timeout；AI-201 报告有效引用率和引用点击；AI-101 对报告关键数字做来源抽样核对。
- AI-204/PM-204 以固定历史夹具评估预测误差和偏差，缺失值不得静默按 0；预测结果必须带口径和非承诺提示。
- 数据不足时展示“数据积累中”及可回溯窗口，不得显示 0、空图或推算历史冒充实测。
- 指标看板本身也遵循失败/空态分离和来源溯源要求。

## 9. 风险、假设与待验证事项

### 9.1 风险与应对

| 编号 | 风险 | 影响 | 应对 |
|---|---|---|---|
| R-01 | P0 项较多，修复与新能力并行造成回归 | 核心链路不稳定 | 按 §7.2 排序；数据安全修复先合入并回归，不以分期为由跳过 P0 |
| R-02 | 增量加列、快照或迭代模型迁移失败 | 数据丢失或统计分叉 | 幂等迁移、备份、重复执行测试和 API/落库断言；技术方案先评审 |
| R-03 | 事件默认保留 90 天，历史洞察不足 | 长趋势无法重建 | PM-205 尽早写日快照；页面标注真实窗口 |
| R-04 | AI 用量预估偏差、生成失败或输出幻觉 | 用户不信任或浪费配额 | 三项预估+偏差提示、分段重试、溯源与人工确认；不自动采纳建议 |
| R-05 | 预测被误解为承诺 | 错误汇报与管理决策 | 算法可解释、共用单源、常驻“预测值非承诺” |
| R-06 | Webhook 或分享快照泄露敏感信息 | 本地隐私边界被破坏 | HTTPS/HMAC/订阅最小化/可停用；快照字段白名单与敏感扫描 |
| R-07 | 代码问答越权写文件或执行命令 | 本地代码损坏 | 只读技术边界、安全测试；编码代理仍须另行立项评审 |
| R-08 | 竞品信息过时或未实测 | 对标判断偏差 | 保留检索日期，每季度复核；竞品 UI 结论不作为直接验收依据 |
| R-09 | 视觉与读屏覆盖遗漏 | 暗色、窄屏或辅助技术仍不可用 | 建立页面×主题×字号×断点矩阵；补 NVDA、4K/8pt 走查 |
| R-10 | 外部 PRD 依赖未就绪 | AI-202/AI-205 排期阻塞 | 独立跟踪前置签字和 S0～S8，不影响其他需求交付 |
| R-11 | 移动端只读与桌面编辑口径分叉 | 数据不一致或误操作 | 复用 API/权限判断，只读控件不伪装可编辑，做双端同步回归 |
| R-12 | 统计历史为空或 `unknown` 过多 | 排序与目标初期不稳定 | 默认配置序兜底；只从埋点上线的完整周期评估 G-2 |

### 9.2 产品假设

1. 产品继续以 Windows 桌面、本地单用户为主，移动端是配套入口。
2. 既有 T01876、T02090、Q-1～Q-3 决策持续有效；本版仅取代 [C] 中 Q-6 的“本期不做”建议。
3. 为统计和可靠性进行向后兼容的增量加列是可接受的，但须经过技术方案与迁移验证。
4. AI 是可选能力；未配置模型时，核心项目管理功能仍完整可用。
5. 两份来源文档中的“现状”是相应取证日快照，不代表本版编写时仍未修复；排期前应做当前态复核并更新证据，不改变已统一的产品口径。
6. 竞品研究用于发现机会，不要求功能数量逐项对齐，也不构成对竞品未来功能的承诺。

### 9.3 非阻塞技术决策

- PM-201 是否采用零新表路径，由技术方案验证表达能力与迁移成本后决定；无论选择何种实现，迭代行为均按 D-02。
- PM-205 快照表结构和聚合任务调度由技术方案定义；产品侧只约束快照为长历史唯一来源。
- UX-07 的 PRD 防丢可采用 dirty 确认或会话草稿，至少满足一种，不得两种都缺。
