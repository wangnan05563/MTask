## 0. 复评结论

**整体判断：值得做，但必须换实现通道。** v1 把「图示语汇」当作可以零侵入挂进 `Block[]` 的纯增量，而 T02171（时间线分页承载）与 T02172（柔性块分型可读高 + `dataKeys ≤ 2` 硬校验）已经把版面预算层改成了「按块类型收口、收不下就 drop 并点名」——照 v1 原样接线，新组件在最新代码上的默认结果是**画不出来 + 一堆省略告警**，正是 T02166 最初投诉的形态。

| v1 条目 | 复评处置 |
|---|---|
| A 横向流程图 `flowBlocks` | **保留但改判**：通道改「一页一复合块」，数据源必须换成项目真数据（里程碑链），`pipeline` 硬编码五阶段**删除** |
| B 卡片 `cardBlocks` + 标签 `chipBlocks` | **砍 card，留 chip**（T02156 已把表格/图表做成卡片层次） |

## 2. 修订后的改动清单

### A′【高价值】`flow` 版式：一页一复合块 + 项目真数据源

**通道（关键：仿时间线，不仿表格块）**

1. `server/src/services/kickoffBuilder.ts`
   - `Block['shape'].kind` 联合增 `'rightArrow'`（`:55`，现为 `'rect' | 'diamond' | 'line'`）；`Block['shape'].tone` 增 `'flow'`。
   - `shapeToneColor`（`:971-978`）增 `tone === 'flow' → PALETTE.brandBright`；色值一律取自 `PALETTE`，不新增 hex 字面量（PRD §6.3 门禁 6）。
   - 形状块带字：`Block.shape` 增可选 `label?: { text: string; pt: number }`，`drawBlock` 的 shape 分支改为——有 `label` 时走 `slide.addText(label.text, { ...geo, shape: kind, fill: { color }, color: PALETTE.onBrand, align: 'center', valign: 'middle', fontFace: FONT.face })`，无 `label` 时维持现 `addShape`。**一块一形状一带字**，从源头避免「rect 叠 text」被 `findOverlaps(tol=0.02)` 判成重叠。
   - 新增 `flowPass(item, b, frame, cursor, out): { drawn: number; notes: string[]; dropped: string[] }`：**整组节点自成一个绘制单元**（内部自己等分宽度、算箭头位），产出 `Block[]` 后直接 `return`，不进 `fitStack`/`flexStrip`。
   - `layoutBody` 接线：判定 `flowPage = item.layout === 'flow'`，`rawBlocks` 过滤掉由 flow 承载的那个 key（与 `:802-806` 的 `tlShape && k === 'timeline'` 同一写法），并在 bullets 预算里按 `TL_MIN_H` 的同类方式预留 `FLOW_MIN_H`。
   - 门禁豁免：`blockBoundsIssues`（`:926-935`）与 `contentBoxes`（`:937-940`）的 `tone === 'axis'` 条件扩成 `tone === 'axis' || tone === 'flow'`——箭头是连接装饰，不是内容盒。

2. `server/src/services/kickoffService.ts`
   - `KICKOFF_LAYOUTS`（`:533`）增 `'flow'`（9 → 10 值）。`OUTLINE_SYSTEM` / `OUTLINE_SYSTEM_RETRY` 的 `layout∈[...]` 由常量插值自动带上，无需改文案；但需给模型一句 flow 页的**内容约束**（「flow 节点一律来自下方里程碑阶段名，禁止编造步骤」），沿用 `sanitizeBullets` 的真值改写口径。
   - **不新增 `dataKeys`**（见失效前提 3）：flow 页用 `layout:'flow'` + `dataKeys:['milestones']` 表达。

3. **数据源（这是 A′ 与 v1 的分水岭）**
   - 节点 = `b.milestones` 按 `start_date` 升序取前 4~6 条的 `title`（里程碑名是库内真值，天然有序，正是启动会要看的阶段交付链）；不足 3 条则该页不成立 → 回退 `list` 版并留痕，比照 `timelineDegradeReason` 的写法。
   - `chip` 变体（原 B 保留的一半）：标签 = `b.assignees` 的 `name (planCount)`，横向流式排布用 `estimateTextWidthIn`（`kickoff-layout.ts:342`）算宽、超宽换行；同样走「一页一复合块」。
   - **删除 v1 的 `KickoffBundle.pipeline?: string[]`**：Bundle 现有 8 类字段（`kickoffService.ts:311-329`）全是项目真数据，新增一个「采集→大纲→确认→装配→导出」的自指管线页，等于新增一类技术性套话，与 T02166 的裁决直接冲突。

### C【中价值】降级页 `fit:'shrink'` + 留痕口径同步

1. `Block['text']` 增可选 `shrink?: boolean`；`drawBlock` 文本分支（`:1027-1035`）`t.shrink ? { fit: 'shrink' } : {}`。
2. 只在 `degradeToSafe`（`:959-965`）与 `appendBrandPage` 的降级落点（`:1165-1167`）置 `shrink: true`；正文页维持现「预测量 + 截字留痕」，避免静默缩成小字（验收 7「宁素不出坏页」）。
3. **必须同步的谎报点（v1 未列）**：现有 note 文案「多余部分按 pptxgenjs 截字」（`:838`）在开启 shrink 的页上不成立（字是被缩小、不是被截）。降级页 note 要改为「按 fit:shrink 自动收缩」，并复核依赖该文案的断言：`scripts/verify-t02172-kickoff-flex-floor.mts` F-04、`scripts/verify-t02166-kickoff-ai.mts` C-05（shrink 后字符数不减，C-05 的「≥60 实字」判据不受影响，仍需实测确认）。

### D【中价值】空正文页断言（重定义）

1. 判据改为**正文块为空**：`bodyBlocks.length === 0`（不含标题块与脚注）→ `warnings.push('第 n 页正文为空（数据块均因版面不足被省略），已按安全版式回塞要点')`，并把 `bullets` 回塞进 `safeFrames().body`；正文与要点都空时保留标题页并降级为章节页式留白，不静默出「只有标题的页」。
2. 落点：`appendOutlinePage` 在 `resolvePageBoxes` 之后（`:1200` 附近），与 `degradedPages` 同一登记通道。
3. **必须进离线门**：这条形态目前只在真链路门 C-05 以「<60 字」被间接兜住，而那道门要跑真 AI + 隔离实例；生成时拦截 + 离线断言才是可回归的防护。
