# T03730 · HTML 版 PRD 导入解析规则

> 适用入口：「AI 工作台 → 从 PRD 导入项目计划」（`PrdImportPanel` → `POST /api/plans/ai-parse-prd` → `PlanService.extractPrdTextDetailed`），
> 以及 MCP 工具 `mtask_import_prd`（同一分派函数）。
> 实现：`server/src/services/htmlDoc.ts`（纯函数，零新增依赖）。

## 1. 设计原则

1. **结构搬运，不做字段映射**——HTML 只被转成与 `.md/.docx` 同口径的层级文本；语义拆分（里程碑/明细/需求编号）
   仍由既有 AI 提示词完成，字段映射逻辑不硬编码进解析器，后续调整映射只改提示词。
2. **容错优先**——Confluence 导出、内部 Wiki、浏览器「另存为」三类来源的 HTML 各有脏法（命名空间标签、未闭合标签、
   内联脚本），解析器按单遍扫描容错处理，不要求 XML 合法。
3. **不静默丢内容**——无法转成正文的片段计入 `parseWarnings` 随接口返回，导入面板按警示级打日志；
   完全提取不到正文时直接报错（附原因与可操作建议），不让 AI 对着空文档空转。
4. **非 HTML 流程零改动**——`.docx/.md/.txt/.xlsx/.csv/.pdf` 分支保持原实现，仅把分派函数拆出「带告警」的变体。

## 2. 支持的文件与来源

| 扩展名 | 通道 | 说明 |
| --- | --- | --- |
| `.html` / `.htm` / `.xhtml` | 本规则 | Confluence 导出页、内部 Wiki 页面、浏览器「网页，仅 HTML」另存 |
| `.docx` | 既有 | Word 标题样式 → `#` 层级 |
| `.md` / `.markdown` / `.txt` | 既有 | 原样透传 |
| `.xlsx` / `.csv` | 既有 | 每行一条、单元格以 ` \| ` 分隔 |
| `.pdf` | 既有 | 文本型 PDF 可解析，扫描件会明确报错 |

## 3. 解析流程

```
字节流 ──decodeHtmlBuffer()──▶ 字符流（先读 <meta charset>，GBK/GB2312 等按声明解码，缺省 UTF-8）
        ──去噪──▶ 注释/doctype/CDATA/head 剔除；<script> <style> <svg> <iframe> 等整块跳过并记账
        ──单遍扫描──▶ 标题/列表/表格/段落按块落地
        ──校验──▶ 正文为空或过短 → 抛错；跳过项/无 alt 图片/无标题层级 → 告警
        ──▶ Markdown 层级文本 → 既有 aiParsePrd()（提示词：`【PRD 文档】\n<文本>`）
```

### 元素映射表

| HTML | 输出 | 备注 |
| --- | --- | --- |
| `<title>` | 首行 `# 页面标题` | 去掉 ` - Confluence` 后缀；与文内同名一级标题去重 |
| `h1`~`h6` | `#`~`######` | 层级直接决定 WBS 识别依据 |
| `p` / `div` / `section` / `article` / `blockquote` 等块级标签 | 段落（块之间空行分隔） | 未知标签当透明处理，文本保留 |
| `<br>` | 段落内换行 | 表格单元格内折成空格 |
| `ul` / `ol` / `li` | `- ` / `1. ` 项目符号，嵌套按层缩进 2 空格 | 裸 `<li>`（无列表容器）按一级列表兜底 |
| `dl` / `dt` / `dd` | `dt` → 列表项；`dd` → 紧随其后的缩进说明行 | 说明行不与条目之间插空行 |
| `table` / `tr` / `th` / `td` | 每行 `单元格 \| 单元格` | 与 Excel 导入同口径；嵌套表格文本并入单元格 |
| `pre` / `code` | 原样保留换行 | 不做代码围栏（避免 AI 把它当代码而非正文） |
| `<hr>` | `---` | |
| `<img alt="…">` | `[图片：alt]` | 无 `alt` 计为丢失并告警 |
| `<a href>` | 保留链接文字；**空锚点**补 `[链接：href]` | 图标链接不再整条消失 |
| HTML 实体 | 解码 `&amp; &lt; &nbsp; &ldquo; …` 与 `&#65;` / `&#x41;` | 未收录的命名实体按原样保留 |
| 正文中的裸 `<`（如 `a < b`） | 原样保留 | 标签名必须紧贴 `<`，比较式不会被误判成标签 |

### 主动跳过（计入告警）

`script` `style` `noscript` `template` `svg` `math` `iframe` `object` `embed` `canvas` `video` `audio` `picture` `map` `select` `option` `button`。

## 4. 无法识别内容时的行为

- **部分不可读**：接口仍返回 200，`parseWarnings[]` 逐条说明，面板以 `⚠` 打日志。示例：
  - `有 2 处图片缺少替代文本（alt），未写入正文；若图片承载需求信息，请在原文档补 alt 或改用含文字的版本（PDF/Markdown）。`
  - `已跳过 1 处非正文元素（<iframe>×1）——脚本、样式、图表、内嵌页面与表单控件不会进入解析；如其中含正文，请改用 PDF/Markdown 或手动补充。`
  - `未识别到任何标题层级（h1-h6），已按段落输出——若原文档的章节层级丢失，请在导入预览里手工调整 WBS 层级。`
  - `HTML 正文超过 4000 段，已截断尾部 N 段；建议拆分为多份文档分别导入，避免需求被漏拆。`
- **整体不可读**：返回 400，错误文案含诊断与建议，例如
  `HTML 未提取到可读正文（可识别文本 0 字，跳过非正文元素 0 处）。常见原因：正文由 JavaScript 动态渲染（保存下来的 body 为空）……`
- **人工兜底**：预览界面的需求/计划行可逐条勾选与编辑（`include` / 改写标题与描述），这就是「手动映射」通道。

## 5. 已知限制

1. **纯前端渲染的页面**（SPA / 需要登录后才渲染的 Wiki）另存后 body 为空 → 会明确报错；请改用 PDF/Word 导出，或在浏览器中全选正文粘贴成 `.md`。
2. **图表与画布**（`<svg>` / `<canvas>` / 流程图组件）不可读；若图中含需求信息，请补文字说明或改用含文字的导出物。
3. **图片中的文字**不识别（无 OCR），只保留 `alt` 文本。
4. **复杂表格**（合并单元格、嵌套表头）按「行 → 单元格」扁平化，`rowspan/colspan` 的语义会丢失；需要严格表格语义时改用 `.xlsx`。
5. **正文里带 `>` 的裸比较式**（如 `a < b > c`）可能被当作标签段吞掉部分字符——虽已把「标签名紧贴 `<`」作为判据把常见情况挡掉，极端写法仍可能误判。
6. **编码**：仅按 `<meta charset>` / `http-equiv` 声明解码；声明缺失且非 UTF-8 的老页面会出现乱码（可用浏览器重新另存为 UTF-8）。

## 6. 配置指引

- **模型与预算**：HTML 转出的正文通常比纯文本长（表格/列表逐行展开）。建议 PRD 解析所用工具 `max_tokens ≥ 8192`；
  代码已按 `minMaxTokens=8192` 托底，并在首轮截断时自动走「精简重试 → 分片多轮解析」。
- **长文档**：超过分片阈值（`PRD_DIRECT_CHUNK_CHARS`）自动按标题边界分片，多轮结果合并重排编号；分片失败会以
  `truncatedNote` 显式告知缺失片，不会静默吞掉。
- **段数上限**：`htmlToMarkdown(html, { maxBlocks })` 默认 8000 段（防御超大网页）；触顶会给出截断告警。
