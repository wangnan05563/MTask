# 验收门判据规约（T02293）

约束 `scripts/verify-*` 的**断言写法**。起因是两类门红得与功能对错无关：

- **锁实现字面量**：门用正则匹配源码文本（函数名、CSS 类名、中文文案、注释里的一句话）。
  任何人做一次等价重构，门即恒红——实测例：commit `66eb5cd` 把内联 `resolveDeps(...)` 提成共享函数
  `applyPlanItemDeps(...)`，行为不变，同门的行为断言仍 PASS，只有字面锚点红。
- **锁生产数据事实**：门 `SELECT` 生产库断言某批业务数据存在（例：「四期归档态 K/M-K 批次 = 12 行」，
  写死 `created_at` 时间戳）。那批 12 行此后被 T01874「彻底删除」通道清掉，门永无复绿可能。

生产数据是**易变的外部状态**，门必须能在任意时点复跑；重构是**常态**，判据不能假设实现形态不变。

## 四条硬判据

1. **断言打在行为或产物上，不打在源码文本上。** 允许的被测对象：HTTP 响应、SQLite 查询结果、
   导出的 PPTX/XLSX/PDF 产物、渲染后的 DOM（结构属性与计算样式）、纯函数的返回值。
   反例（禁止作为唯一判据）：`/export function startReportTmpSweeper/.test(源码)`、
   `/const MIN_CHART_H = 1\.2/.test(源码)`、`readFileSync('...KickoffPptPanel.tsx')` 后匹配中文文案。
2. **门内自造数据，不依赖存量业务数据。** 夹具由门自己写入隔离库/隔离实例；
   断言只引用本轮自己造出来的行。门需要「真实项目」时，用日备份副本或自建夹具，
   并把「生产库现状」显式降级为 `skipped()` 留痕（不冒充 PASS）。
3. **确需保留字面锚点时（如「不许出现硬编码色值」这类静态红线），必须配一条同义行为断言兜底，
   且只在行为断言通过时才算绿。** 即：行为断言 FAIL ⇒ 该条 FAIL；行为断言 PASS 而字面锚点 FAIL
   ⇒ 记 `FAIL`（说明重构换了写法但没换行为，人来判定是改锚还是改码），不允许静默放行。
4. **每条改判必须配负对照。** 新写/改造的断言要有一条「反证」：在副本里把被测行为真的破坏掉
   （摘掉注册、抽掉导出、篡改一个值），断言必须因此变红。没有负对照的恒绿断言视为无效判据。

## 临时副本与破坏性反证的边界

- 破坏只发生在 `git worktree add --detach` 出来的副本或临时数据目录里；真实工作树与他人 WIP 不动。
- Windows 上 worktree 的 `node_modules` 靠 **junction** 挂仓库根：清理必须**先解除 junction**
  再 `git worktree remove`，否则顺着链删掉真实依赖。
- 临时根必须落**可写盘**（本机 C: 常年 0 可用，指过去会假性 `SQLITE_FULL` / 写失败，把绿判成红）。
- 门**不得**执行 ABI 切换、`electron-builder` 等会覆写仓库根 `node_modules` 原生二进制的步骤；
  需要跑到构建末段的门用桩在该边界前退出，并按字节校验原生二进制未被改动。

### 秒级静态门这一类（T02617 起）

行为门要几分钟，就必须在**被守护的东西自己跑之前**有一道秒级门，否则退化发生在「没人跑门」的窗口里。
T02617 立的是这一类的第一条：它不判「守卫管不管用」（那是 `verify-t02321-pack-precheck.mts` 的重活），
只判**守卫还在不在**——四条发布入口（`scripts/打包.mjs`、`scripts/dist.js`、`scripts/构建打包.bat`、
`scripts/build-pack-t.bat`）对 `scripts/lib/head-precheck.mjs` 的**调用形态引用**在三条面上都在。
两条纪律：

- **只认调用形态**，注释里提到守卫名不算（`REM` / `::` / `//` / 块注释续行四种诱饵都由
  `scripts/lib/guard-reference.mjs` 的 `isCommentLine` 剔掉）。摘掉调用行只留注释，是最像「没出事」
  的一种退化——本单立约现场的实测形态是：索引里一份把步骤计数退回 `/6`、整段预检都不在的旧
  `scripts/打包.mjs`（同一时刻 HEAD 已经是 `/7` 且带第 [3] 步预检）。
- **任一面丢引用即红，且三面各出一条断言**：索引态（`git show :<path>`）单独成立，才拦得住
  「已 stage 但还没提交的内容把守卫抹掉」。负对照用 `GIT_INDEX_FILE` 副本 + 独立
  `GIT_OBJECT_DIRECTORY` 造「无守卫的 stage」，并断言真实索引字节哈希不变、夹具 blob 不在真实对象库。

`package.json` 的 `verify:*` 登记位仍缺（该文件常年被并发会话占着 `MM`，本单不动它）——
接线先落在发布入口自己的最早一步（`runHeadPrecheck` 进重门之前自检，`--skip-head-check` 时只告警留痕），
登记缺口留给 package.json 空出来时补。

### 改判反模式（实测踩过的「假判据／假红」形态，编号沿用台账既有引用，写门时先自查）
改造本身也会写出坏判据。以下各条都是本轮实测抓出来的，形态各异，根因同一个：**断言打在了非行为字段上**。

1. **把立即执行的 IIFE 当 thunk 交给 `okPair`**：`okPair(ok, L, (() => {...})(), ...)` ⇒ 运行期
   `fn is not a function`。判据 3 的配对函数按 thunk 约定调用行为侧，签名即契约。
2. **拿两次构建的 zip/pptx 字节相等当「模拟没留残渣」**：docProps 里有生成时刻，两次构建的字节**必然**不同
   ⇒ 恒红。可比对象是解包后的幻灯片 XML 文本，不是压缩包字节。
3. **「旧字面量在产物里零残留」混淆了值同一与角色同一**：`PAPER_BG` 与 `ON_BRAND` 同为 `FFFFFF`
   （`server/src/util/exportStyle.ts:86,107`），纸面色搬家后品牌带白字仍留该值——那是另一支单源常量在起作用。
   正确判据是**出现次数随表下降且增减相等**：装配层若真抄了一份，次数不会降，牙齿不丢。
4. **扫描通道旧值时先不剥门自己写的夹具文本**：大纲标题里门自撰的项目名会冒充「产品抄本」，
   把门的夹具当成产品的第二份来源 ⇒ 恒红。取证对象只算产品从入参搬上页面的那些字。
5. **负对照写反**：把「篡改后的夹具仍含占位」当断言（篡改根本不会让判据转红）——负对照要证的是
   **判据在行为被破坏时变红**，不是假夹具也长得很绿。同理，例外清单式判据（`c.startsWith('总工作量') ||
   c.includes('一律记')`）本身就是换了个马甲的文本锚，要改写成「不存在第二种占位形态」这类值级规则。
6. **`await api(...).json` 少吃了一对括号**：`await` 优先级低于成员访问，取到的是 `api(...).json`
   （undefined）而不是响应体 ⇒ 与任何字符串比都恒红。取体一律 `(await api(...)).json`。
7. **放行侧拿不存在的 id 测**：`validateProjectIds` 在数量帽**之后**还查库内存在性
   （`server/src/services/reportService.ts:99-109`），用假 id 永远量不出「8 个放行」这一半。
   判据要放行就得经 sanctioned 写入通道（`POST /projects`）在门内造真数据，或改测「帽在哪一格」
   （8 不被帽拦、9 被帽拦且点名个数）。
8. **跨进程「逐字符相同」两侧取的不是同一个变量**：HTTP 侧用 `ESTIMATE_COEF_KEYS[0]`（collaboration），
   门进程硬写 `.schedule` ⇒ 拿两句天生不同的话比相同，红得没有信息量。同源比对的前提是
   **同一个入参表达式**，档名/键名要从同一个常量取。
9. **按猜的交付形态写文档类判据**：附录 A 的逐页清单在**围栏代码块**里（`parseTables` 恒 0）、
   §7 是「项/要求/依据」三列约束表而非 `### 7.x` 小节、§5.2 的「对本 PRD 的落点」只在表头出现一次
   （按整节扫行必恒红）。文档结构判据先量出真实形态（表行数 / 编号条目数 / 区间行），再写断言。
10. **夹具把必含键放在会被产品清空的版式页**：`thanks`/`section` 页的 `dataKeys` 会被
    `validateOutlinePage` 显式清空并记 warning（`server/src/services/kickoffService.ts:807-810`），
    把 `workload` 写进结束页等于门自己造一次硬失败。夹具版式要与产品口径同构。
11. **门「红」之前先问「被测的是哪一份产品代码」**：工作树里可能躺着别的路径留下的**过期产品文件**
    （本轮实测 `PlanService.ts`/`estimateCopy.ts` 等 8 个产品文件比 HEAD 少 659 行），门 tsx 直跑
    读的正是这份工作树，于是把「HEAD 里已经存在的功能」判成「没实现」。红要先定性：
    在 `.gatewt/` 里 `git worktree add --detach` 出一份 HEAD 副本同跑一遍，副本绿即为工作树污染，
    不是产品缺陷也不是判据错。
12. **负对照的构造方式绑死在「修复前」的产品现状上**：`verify-t02354-mcp-prd-preview` 的 N-02 变体原本是
    往 HEAD 副本的入参 schema 里**补一行** `dryRun`（当时的 HEAD 还没有这条通道，补上即「广告了却不认账」）。
    `a0bdc76` 把 dryRun 回补进产品后，同一份补丁变成「schema 里多写一遍、handler 照样认账」⇒ 变体不再落库
    ⇒ 负对照恒「无漂移」，红线自己失效。负对照要破坏的是**行为本身**（把 `if (a.dryRun === true)` 短路），
    而不是给旧世界补一块新世界的零件；且锚点命中判定要同时要求两条腿（schema + handler）在场，
    产品哪天真缺了 handler，就报「变体没打上」亮红而不是静默假绿。
13. **把同句别处的词借给锚点当「期望标识符」**：给 `routes/index.ts:1842` 判 `buildPptx`（那是下一处锚点的
    符号）、给 `tunnel-service.ts:1,8` 判 grep 命令文本里的 `rev-parse`——借来的词只会把**真锚点**误判成失配；
    反过来「借来的词恰好也出现在附近」又会掩盖真漂移。标识符只认锚点自己那个反引号跨度。覆盖面薄不靠放宽窗口
    补救：要么改文档写法（`路径:行号 标识符`，本批校锚时同批补 12 处），要么加**分母腿**（本批 F-A5：带标识符的
    锚点 ≥20 条）让「无标识符可查」的空判据自己变红。


14. **行为腿的取值时间早于实测（改判改到一半的形态）**：配对项的行为断言，数据往往来自后面几组才产生的实测值（SSE 线上帧、下载工件、tmp 清单）。断言若留在原位，只有两条路——用「源码里有这句」冒充行为腿（等于没改判），或提前取值拿到空对象让判据恒真。正确做法：**把配对项声明成惰性数组（thunk），实测组跑完再统一发射**，发射点前若环境缺口（夹具项目没建成）就记 SKIP，不冒充 FAIL。
    配套两条：① **新增探针要当场清场**——本轮为拿 error 帧加的探针会「降级出一稿并落一个令牌」，把紧随其后的「下载即删、tmp 归零」判据染红（真红，但根因是探针污染而非功能失守）；② **「零残留」类判据必须配对照面**（同一目录本轮确曾非空），否则 TMP_DIR 指错时整组恒绿而无人察觉。

### 提交纪律（本规约定的一条硬红线）

隔离 index 提交（`GIT_INDEX_FILE` + `commit-tree` + 带旧值守卫的 `update-ref`）只保证**不裹挟别人的
staged 改动**，不保证 `git add` 进去的工作树内容是新的。本轮实测：批③ `a22cd5a` 把一份过期的
`server/src/mcp/server.ts` 提进了 HEAD，静默抹掉了 `0c3dfa2`（T02354，已 done+verified+归档）加进去的
`mtask_import_prd` dryRun 预演通道 4 处改动——症状是门判「带 dryRun 的调用真的写了库」，
直到 `a0bdc76` 才回补。所以：**提交任何产品文件前先 `git diff HEAD -- <该文件>`**，
出现的删除行必须是本单自己要删的，否则就是拿着过期副本在提交。

19. **篡改型负对照不「自证变异已落地」**：N 组最常见的失效形态是替换/注入的目标串在被取证对象里
    根本不存在（`verify-t02100` 的 N-01 曾把 XML 片段替换成仓里没有的标记），于是
    `副本 === 原件`，判据「照样转红」其实是拿原件在红。凡篡改类负对照必须同批断言
    **副本确实不等于原件**（`tampered !== original`／`UPDATE` 的 `changes === 1`／改名后原锚点确实取不到），
    再让同一条判据对它翻红。
20. **字面腿与行为腿都要过一次「永真式探针」**：改判后的判据本身也可能是空壳——字面腿喂**空源码**
    仍为真＝该条正则不承重；行为腿在**抽掉运行期实测料**（清空回填对象）后仍为真＝它根本没在读实测。
    两条探针都便宜且通用（`verify-t02131` 的 N-01/N-03 即此），比逐条手写反例更能覆盖「批量降级成
    字面腿」的那一类改判。参数化取证面（`literal(mcp, plan)` 而非闭包捕获常量）是前提。

21. **把「门自己的读取超时」当成产品的丢帧／泄漏**：用 `Promise.race([reader.read(), sleep(600)])`
    读 SSE 时，超时一赢，那条**迟到的帧就永久丢了**（race 不会替 reader 保留已 resolve 的 chunk），
    于是 `done` 永远不在手上、令牌被算成孤儿——判据红，但产品一行没错。正确写法：把读取循环放进
    **后台 pump**（自己 `while` 读到 `event: done|error` 再 `cancel`），外层只对 pump 做超时；
    超时值取「最慢一次真调用」的量级而不是常量 600ms。归因通道先于修复：在疑似落笔阶段打印
    「名册/在册文件/孤儿」三元组（`orphanMark`），一轮实跑就能区分「没发帧」与「发了没被读」——
    二者改法相反，前者要修产品，后者要修门（`verify-t02142` 本轮即由此从 8 红收到 0 红）。
22. **把「同一份件里本来就有的两种合法形态」当成失守**：行为腿的对照对象必须同实例、
   同批次、同形态。两种实测形态：① 拿**全文所有表格**的统一列数当判据（`verify-t02044-e7` G-33——件里
   本就有封面信息表 4 列与报价表 N 列，跨表统一列数把正常结构判成行为失守，正确做法是先按表分组、
   再在**每张表内部**判列数并只看表头单元格）；② 拿**两次导出的完整件名逐字相等**当「同一命名规则」
   的证据（R-10——`exportStamp` 精确到秒，两次 HTTP 调用跨秒是常态，于是判据随机红；应先摘掉时间戳段
   再比，或让两次取数落在同一次调用里）。同族的还有把生成时刻、随机端口、PID 写进相等断言——
   凡是「门的观测环境差异」都不许冒充「产品行为差异」（与反模式 2 同根）。

23. **浏览器侧探针的转义层数与超时返回值**：CDP 探针要在 Node 模板字面量里拼 JS，`\d` 会被 cooked
    成 `d`（正则静默变成 `/(d+)/`），实测取数为空 → 行为腿假红；正确写法是 `\\d`。同族的还有
    `until()` 超时返回 `''` 而不是 `null`，调用方直接 `.join()`/`.slice()` 会崩栈或把空串当证据——
    超时应返回 `null`，行为腿对返回值显式做 `Array.isArray`/类型守卫。改判 UI 门时先加一条
    「探针非空」腿（如 `Array.isArray(EV.x) && EV.x.length > 0`），能一轮暴露这类门侧缺陷。

24. **用「手写存储键 + reload」切换应用状态**：验证「切到空项目」时，门若直接
    `sessionStorage.setItem('plan.projectId', ...)` 再 `Page.reload()`，实测 reload 后该键又变回旧值
    （外部写入未赢过应用自身的 `useStorageState` 回写；隔离最小复现反而无法重现），空项目判据因此恒假红。
    应用状态切换应走**真实 UI 路径**（点项目选择器的 `button[aria-haspopup="listbox"]` →
    点 `[role="button"][aria-pressed]` 行，项目名用夹具数据），判据同时覆盖用户可达性；
    要验刷新保持，就读应用自己写回的存储值再 reload，别读门里手写的那一份。

25. **控件点击条件把「目标自身的当前选中态」当成「期望的业务布尔值」**：门里要切到某档时写
    `if (r.checked !== false) r.click()`——`r` 是**待点击的目标**，它未选中时 `checked===false`，
    条件恒跳过，于是从未点中，后面所有「切回内部版/切到客户版」的行为腿全按初始态跑：首导出
    仍是客户版、折叠提示不消失、快照受众/件名全错，一次级联 7 条假红（`verify-t02043-ui` E-06/
    E-07/E-11/E-16、P-06/P-08/P-17）。写法应是 `if (!r.checked) r.click(); return r.checked ? 'ok' : 'stuck';`
    ——点击条件只判断「需不需要点」，返回值再对期望态收口；切档 helper 的动作腿要独立断言
    目标控件的**终态**，不能只靠后续业务腿反推。同族：**UI 显示精度决定断言容差**——界面按两位
    小数显示人月（0.71）而服务端 payload 是全精度（0.70859），行为腿容差写 1e-6 必假红；容差下限
    取显示精度的一半（两位小数→`0.005`），并在同类判据里统一复用该常量，而不是逐条拍脑袋。
    （空实测料下的 `undefined === undefined` 恒真属反模式 20 同族，凡数值相等判据先过 `Number.isFinite`。）

26. **结构定位器用「后代按钮计数」代替「直接子计数」**：正文区里除操作钮外还住着第三方渲染器的工具条
    （`MarkdownContent` 自带「渲染视图/源码视图/复制」3 枚按钮），`container.querySelectorAll('button').length`
    于是恒不等于操作入口数，`openEditor()` 因「不是恰 1 钮」直接拒绝点击，编辑器开不进、S6/S7 整条链级联假红
    （`verify-t01700-probe` B-11 首版）。改法：操作入口按**同层直接子**取
    （`[...inner.children].filter(c => c.tagName === 'BUTTON')`），后代计数只作为反证记进证据字段；
    同一原则适用于标签栏（「恰 5 个直接子 BUTTON」）与确认层（「恰 2 枚按钮的 fixed 覆盖层」）——
    写计数判据前先问一句「这个容器里还住着谁」。
27. **「发过请求」不等于「新快照落回页面」**：竞态类判据若只数 CDP `Network.responseReceived`，PATCH **之前**
    发出的在途请求同样计入，等于用「可能有旧值」冒充「确实落回了新值/旧值」；而拦截注入若只看
    「我调了 `Fetch.continueResponse`」，页面到底有没有消费那一体，证据上是空的（不消费也照样绿）。
    改法：在 `Page.addScriptToEvaluateOnNewDocument` 里对 `window.fetch` 做**只读**包装（`clone()` 后按夹具
    标记记录每条列表响应含哪个值），行为腿要求「含新值的那条落回过」而非「有请求落回过」，陈旧快照腿
    要求「释放之后落回的条目仍是陈旧体」——注入的牙齿由页面侧记账钉死，而不是由时间窗猜测。
28. **一条「入场券」句柄失配会扇出几十条同根因红**：打包壳门的行标识/视图归属句柄（`li[data-tl]`、
    `badge.closest('[data-tl]')`）写错时，后续每条依赖该入口的行为腿一起变红（实测一轮 40 条里红 20+），
    红的分布看着像产品大面积失守，实则一个定位器。改法：把「入口是否成立」本身做成前置断言并在红因里
    带候选数（如逐枚点开面板钮时留痕 `aria-expanded`／正文是否含夹具标题／命中的是第几枚），
    先让第一枚失败点可命名，再谈其余红；行归属要从 `parentElement.closest(...)` 起走，
    否则控件自身带同一 `data-*` 属性时 `closest` 命中自己、归属恒真（或恒假）。
29. **CDP 调用不设 per-call timeout 就是僵尸挂起**：`send` 只 `pending.set(id, res)` 而无超时，
    一旦某条响应丢失（渲染进程被对话框阻塞、连接半断），门既不报错也不退出——实测 >10 分钟零输出，
    而渲染页/后端/进程全部存活，`netstat` 里 ws 仍 ESTABLISHED、CPU 0%，从外部完全无法区分「还在跑」与「已死」。
    改法：每条 `send` 带超时（默认 30s，`--cdp-timeout` 可调）并在超时时把**最后一条命令名**写进错误；
    `ws` 的 `close`/`error` 事件里 `abortPending` 把所有在途请求一次性以失败收口；
    再在每个相位边界打一行阶段标记（入场/选择器/抽屉/编辑/放大/框选/计划/移动/收尾），
    使任何一次挂起都能报出「卡在哪个相位」而不是沉默。
30. **「面板根／选中态」由容器描边判定时，表格行与表单控件会劫持结果**：把「含夹具文本的最小可见节点」
    沿祖先链找第一枚「上边框 solid ≈1px」的盒子当面板根，实测先命中 `INPUT`（透明边框、宽度 0），
    排除后又命中 `TR`（列表行本就有 1px 实线 `rgb(229,231,235)`），两者都不是面板——判据在错盒子上照样绿/红。
    改法：优先取最近的**分节/地标祖先**（`section/main/aside/article/form/fieldset/dialog/[role=dialog]`），
    兜底遍历时显式跳过 `TR/TD/TH/TABLE/INPUT/TEXTAREA/SELECT` 与透明/全黑 alpha=0 的边框；
    宽度阈值用区间（0.5–1.5px）而非 `=== 1`，因为 DPI/缩放会让 1px 计算成 0.666667；
    标题类文本还要同时认 `<input>` 的 `value`（壳里用例标题渲染在输入框内，`innerText` 判据会空转）。
31. **改名型负对照的两种「变异未落地」变体**（批㉕ 实测，都是反模式 19 的分支）：
    ① 只替换**第一处**——同一标识符在一份源码里出现多次时（`markLinkedTaskDoneUnread` 在
    `milestoneProgress.ts` 里既有定义又有调用点），替换后其余出现仍命中锚正则，字面腿照绿而门以为证到了；
    ② **保留前缀式改名**（`token.slice(0,4) + '__RENAMED__'`）——两字锚「红线」改名后写作
    `红线__RENAMED__`，串里仍含 `红线`，同样漏判。两种都要改成**全量替换成不含原串的标记**
    （`src.split(token).join('__RENAMED__')`），并把自证条件从「原文含该串」改成「变异后**不含**该串」；
    反向锚（禁词）走另一条自证：注入后必须「变异后**含**该串」。
32. **「平台边界测不了」多半是前提错误，不是事实**（批㉖ 实测）：门里出现「本仓跑不了 Electron IPC /
    起不了真安装器，所以只能静态断言接线」这类理由时，先怀疑**注入点**而不是能力——Node 的
    `Module._load` 钩子可以在 `require` 前把任意模块换成替身，配合 `delete require.cache[路径]` 就能
    **真的加载产品源码**：`electron` 换成假 `app`/`ipcMain.handle`（把 handler 收进 Map 供门直接调用）/
    `Notification`/`contextBridge`+`ipcRenderer`，`node:https` 换成 `node:http`（本地夹具无需 TLS），
    `node:child_process` 换成 `spawn(process.execPath, ['-e', …])`（**退出码是真的**，比返回固定码强），
    `app.whenReady` 返回永不 resolve 的 Promise 即可让启动体不执行而模块照常完成接线。
    判定口径：只有「安装包本体／真机交互」这类**外部世界**才是不可注入的，进程内的每一条 handler
    都没有理由留在源码正则上。替身必须只贴边界：被驱动的仍是 `MAIN_PATH`/`PRELOAD_PATH` 里的真文件，
    否则测的是门自己写的假货（反模式 20 的加强版）。
33. **现状钉住型缺陷探针不能进行为袋当字面锚的行为腿**（批㉖ 实测）：驱动过程中撞出的产品缺陷，
    门里常按「钉住现状、修好后此条转红提醒改断言」写成一条 `ok()`。若把它塞进 `BEV` 并被某条 `okPair`
    依赖，产品**修好那天**该锚点会报「行为失守（功能未达成）」——红因完全反了，把一个改进读成失守。
    缺陷现状钉住只做**独立局部断言**（不进袋、不挂任何锚点），并由逐键孤立检测（N 组）确认没被误接。
34. **全局计数器做判据时要改成 scoped 差值**（批㉖ 实测）：用 `reqLog.length === 2` 证「重试不重新下载」，
    在长门里必然被**前后无关驱动**（同一夹具的其他场景、负对照复跑）往同一数组里追加请求而误红；
    判据要写成「被测动作前后的差值 == 0」并保留两侧读数打印，既免疫又更贴语义。
35. **「改判前反证面」不能硬写 HEAD**（T02616 实测）：新门要证「反面（缺陷版）确实会红」，最顺的写法是
    `git show HEAD:…`。但门与修复**同批入库**之后，HEAD 里已经是修好的版本 ⇒ 反证面永远取不到缺陷文本，
    这条判据从此恒红（自杀门）。正确写法是**派生**：HEAD 若仍写着反面字面量就用 HEAD，否则用
    `git log -S '<反面字面量>'` 定位「摘掉它那次提交」的父提交当反证面，并把「反证面=〈ref〉」打印进证据。
    配套的字面腿还要同时断言「工作树不再写死 且（反证面是 HEAD 之外时）HEAD 也不再写死」，

54. **「与 HEAD 不同」当成「会把已落地内容回退」——同一条红里混了两个方向的活**（T02713 收口后自查，`scripts/verify-index-staleness.mjs` 的 A-02）：初版把「索引 blob ≠ HEAD blob」一律塞进 S 判红，还写成「磁盘本身是过期副本」。但 `索引 ≠ HEAD` 有两种**危害相反**的形态：① 索引是 HEAD 的**更旧**版本 ⇒ 按索引提交真的会回退已落地工作；② 索引是 HEAD **之后**/异源的第三态（他人未提交的暂存工作）⇒ 按索引提交恰好帮他人落地，不是失守。同判红 ⇒ 红因不可归因，还会把 ②的删除行算进「规模」，让一个数混装两个方向。判据：判「回退风险」必须**取证方向**——用该路径自己的已提交版本链定位（`git log --format=%H --raw --abbrev=40 -n 40 -- <rel>` 取每次提交的 new 侧按序成链，new 在前 ⇒ 第 0 位即 HEAD 版；索引 blob 落在链上更靠后 ⇒ 落后 N 版，一条都不命中 ⇒ 异源，列为不判红的 F 形态且不计入风险规模）。规模腿同口径改吃「D ∪ S 的删除量」而不是 `git diff --cached HEAD` 总量。自查两条：(a) 报告里每条 S 是否带得出「落后几版」的取证，带不出就不该判红；(b) 默认 `--raw` 给 7 位短号，长历史上有前缀撞车风险 ⇒ 版本链比对一律 `--abbrev=40` 取全号。附带自证道的两记实锤（同一轮 `--selftest` 里当场红，未进台账）：夹具取数误用了**报告格式化函数**（`topMovers` 返回字符串不是对象）⇒ `cacheinfo` 参数变 `undefined` ⇒ 半截抛错，靠 52 的 `ST-AB` 兜底腿才没被报成绿；以及给 600 条候选各 spawn 一次 `git show` 量行数，是 53 那条「为每个误报路径 spawn」的同形慢法。判据：打印器与取数器分家，夹具候选先用**一次** `ls-tree` 的全表加静态过滤（扩展名/数量上限），不要逐条起进程。
55. **变异夹具的期望桶由被测仓当天的并发状态决定**（T02713-b，`--selftest` 同机两轮不同读数自抓）：同一份工作树门体，第一轮 `9 PASS / 0 FAIL`，几分钟后变 `7 PASS / 2 FAIL`——只因选靶逻辑按「两版之间改动量最大」抓到了**他人正在改**的文件（`MM`）。对这种文件 `--cacheinfo` 塞旧 blob 后，索引/工作树/HEAD 三方互异 ⇒ 变异落进 W 桶（只点名不判红）而不是 S 桶 ⇒ 「S 形态必须点名」与「回退删除量超阀即红」两条腿同时失去对象，却不会报错，只是**默默不红**。这不是门坏，是夹具没把自己的前置条件当判据。判据：负对照的靶子必须带**可核对的前置条件**，并把它写成一条腿而不是注释——本例补 `ST-00c`「靶子工作树 blob == HEAD blob」（保证变异只能落 S）；规模类腿的阀值别写死，用**同一读数的边界两侧**（`limit = riskDels` 不红、`limit = riskDels-1` 红），让腿只对「计数对不对」敏感，不对「今天谁在改哪个文件」敏感。自查：把同一份 `--selftest` 在有并发会话的仓里连跑两轮，读数必须逐字相同；不同就回去查靶子的选取条件。同轮附带抓到「打印器当取数器」（`topMovers` 返回字符串不是对象 ⇒ 传给 `cacheinfo` 的 sha 变 `undefined` ⇒ 半截 fatal），这条能被察觉全靠 52 的 `*-AB` 兜底腿——**兜底腿不改变结论，但决定了这条错误是红还是绿**。补形态腿的牙要用最便宜的反证自证一次：把该形态的**判据本体注释掉**再跑 `--selftest`，必须变红且 exit≠0（本轮 N 形态腿实测：注释掉 `forms.N` 的收集 ⇒ 11 PASS / 1 FAIL、exit 1，改回即复绿）——只做「造出来能点名」的正证不够，还得证「不造就抓不到」。
56. **豁免前置件读一个产品从不写入的字段 ⇒ 恒假死通道**（T02769，`verify-t02111-kickoff-acceptance.mts` 的 D-02/D-03/D-04）：三条时间线几何断言都挂着前置件 `!tlDegraded`，而 `tlDegraded` 取的是 `done.warnings.some(w => /时间线|回落列表/)`。实测产品侧根本不往 `warnings` 写降级播报——`kickoffBuilder.ts:877` 的 `note: 时间线回落列表版：…` 只进页面注记，`kickoffService.ts` 里 `notes` 零出现、`done` 事件的 `warnings` 由别处组装。于是「真降级时不要冒红」这条豁免**从来没生效过**，门体一直把「未降级」当前提跑，红的时候也读不出到底是降级还是失守。判据：任何被当**豁免/前置件**的取数条件，必须先证「它能取到非空」——写不出正例的前置件等于没有前置件；且取数面优先用**结构**（回落列表版的可辨形态是刚性表格 `<a:tbl>` 且无 `diamond`/`line` 轴），文案键只留作证据。修法落地：降级判据改结构键，并补一条合成副本的**一正一反**自证（`N-08a`：列表版副本结构键判降级、文案键判不降级；形状版副本两键都判不降级 ⇒ 既证结构键承重，又证旧文案键确实是死通道），另加实测读数腿（`N-08b`：夹具时间线走结构键为未降级、且文案键命中数恰为 0——哪天开始命中就点名形态变化，不让功能腿冒红）。同族自查：把门里每条 `!xxx` 前置件问一遍「这个 `xxx` 为真的现场，本仓今天存在吗？取数面产品真会写吗？」
57. **门自造的 mock/夹具拿产品提示词文案当路由键（偷听产品说话）**（T02769，同门 mock server）：门内 mock AI 用 `/【风险条目/.test(userPrompt)` 决定「这次请求该回大纲还是回措辞改写」。这串文案是产品 `kickoffService.ts:1186` 生成的提示词片段，产品把它改成「【风险清单」（等价重构）后，措辞请求会被当大纲请求回答 ⇒ `wordingCalls=0` ⇒ E-05 的行为腿以「AI 措辞没进产物」的红出现，真因却在门自己的取数键上。这是反模式 49 的新落点：**受害的不是字面腿而是门自己的夹具**，比锁产品文案更隐蔽，因为门头不会自称「本条不适用 okPair」。判别口径仍是「这串文案是谁生成的」，但要多问一句：**门在拿它做什么**——只做判据 ⇒ 拆 `okPair`；做路由/取数/分派 ⇒ 主键换到**契约面**（本例改走 JSON 字段契约 `/"risks"\s*:\s*\[/` ∧ `/"comms"\s*:\s*\[/` ∧ 非 `/"outline"/`，措辞键降为兜底），并留一条「今日落在哪一面」的探针腿（`N-08c`：装配取数键、mock 路由键、mock 计数键三把键各自的命中来源；落到兜底面即点名「形态漂移」）。探针腿必须带**正对照**（`N-07b`：先证「已装配：」在 `server` 面命中，才允许「门自造三条夹具文案在启动会产品四面零命中」成立）——否则「零命中」可能只是 `git grep` 探针坏了，与反模式 48 的负对照空转同形。牙的检查（实测）：把生成者换成不含该串的文件 ⇒ `N-07` 红并点名（`77/1`）；把主键改假 ⇒ `N-08c` 红并显示路由落到兜底面（`77/1`）；两腿改回即复绿 `78/0`。
58. **普查道把「0 命中」当成果，却没有任何一条腿证明「注入缺陷必被点名」⇒ 空转普查**（T02770，`verify-t02205-guard-selfcheck.mts` 的 L-04 + 新自检器 `scripts/lib/undefined-identifier-check.mts` 首版）：全量普查类判据的形状是「扫 N 支、命中 0 ⇒ PASS」，但 **0 命中有两种来路**——语料真干净，与「扫描根本没发生／自检器恒返回空」。前者是成果，后者是把「没查」写成「查过且合格」，比 FAIL 更危险，因为它永远不会红。批㉝ 的三轮变异实测把这条钉死：把自检器改成恒返回空（`return { fileName, hits: [] }`）后，双向夹具 L-01 与真实门体变异 L-02 立刻红，**而 L-04 独绿、汇总仍是 13 PASS / 2 FAIL**——「106 支全扫、0 处命中」在自检器彻底失灵那一刻照样自称通过。判别口径（写普查类判据时自查三问）：① 这条普查判据旁边有没有一条**同一实现**的「注入缺陷必被点名」腿？（本批 L-02 取 HEAD 真实门体、把某个具名 import 项从声明处摘掉——就是批㉛ 出事的原形，命中必须点到那个名字）② 有没有一条「多报即噪声」的反向腿？（只测「该抓的抓到」会把过度敏感当成有牙：首版自检器漏收具名 import 绑定与重命名解构，106 支报 102 支、L-04 命中 2914 处，那正是本判据要消灭的「红因不可归因」噪声的 AST 版本）③ 语料取数失败／为空时判据走哪一支？（`loadScanned === loadScanFiles.length` 必须进判据，否则「一支也没读到」与「一支也没问题」同形）。⚠ 别把反模式 39（数量当在位下限）的解法误读成「于是普查腿可以留痕不判」：普查腿照判成败，只是它的**在位性由夹具与变异负责，不由数量下限负责**。实测读数：正常 **15 PASS / 0 FAIL**（基线 11/0）；MU1 摘掉具名 import 绑定收列 → **12/3**（L-01/L-02/L-04 齐红、L-04 点名 2914 处）；MU2 撤掉「类基类是运行时取值」豁免 → **14/1**（只红 L-01 的 a4 例，隔离度正好）；MU3 自检器空转 → **13/2 且 L-04 独绿**。三轮跑完自检器文件 `git hash-object` 与变异前逐字相同——改工作树文件做变异必须带还原校验。
59. **给判据加豁免时，合成夹具的「合法例」不复现真语料的遮蔽条件 ⇒ 撤掉豁免后夹具照样绿**（批㊳ T02795，`scripts/t02795-tier-fixtures.mts` 的 s10 例 + 变异 MU2 实测）：静态判据的每条「不报」豁免都要配一例合法写法做反向钉（反模式 58 的第②问），但**合法例的形状必须和真语料里被剔除的那批读数同形**，否则钉的是另一个条件。档一首版普查报 13 处，取证后全是重命名解构 `const { a: b } = …` 的取键位被当读用；补的豁免在位例最初只写成模块顶层一条 `const { renderToStaticMarkup: rt2 } = await import(…)`，把「取键豁免」整条撤掉跑门——**夹具 L-05 照样 PASS，只有真语料普查 L-06 转红**（2 处）。原因是顶层那条即便被当读用，也被「同名声明的可见域覆盖读点」这条**另一重**规则兜住了，豁免撤没撤都判不出差别：这个合法例钉的是「可见域」，不是「取键位」。补 `if (x) { const renderToStaticMarkup = 2; }` + 块外解构取键的同形例（s11，把可见域兜底关掉）后，MU2 变成 **16 PASS / 2 FAIL**（L-05 与 L-06 同时红），豁免的牙才由夹具自己证明。**判别口径**：写「不该抓」例时先问「这条豁免撤掉后，是**这条例**转红，还是别的规则替它挡着」——判据越叠越多（本档从「读位置∉绑定集」叠到「可见域／遮蔽／逃逸面／CJS 包装」五层），重叠遮挡就越常见。同一口径另留一条对照读数：MU1（档一恒返回空）把 L-06 留成**独绿**，正是反模式 58 的形态在新档上复现——普查 0 读数与自检器失灵同形，两道人分工必须写清（夹具管合成形，普查管真语料形，缺一即哑）。
60. **变异腿的「变异」必须证明自己是合法形态的退化，而不是把夹具改死**（批㊴ T02696 N-09）：第一版把四行 WARN 的替换写成 `replace(/\[WARN\] no usable managed node[^\r\n]*/g, …)`——`[^\r\n]*` 一路吃到行尾，把**收尾引号**一起吃掉，产出 `Write-Host 'Write-Host ''`（未闭合字符串）；于是变异件是被 PowerShell 解析器杀掉的，仍然 exit 1、仍然零 WARN，看上去「符合变异预期」，实际测的是语法而不是「不许静默」这条判据，而同一条腿里「仍在 `[2]` 步如实中止」的断言因此红得毫无意义（红因是夹具坏，不是产品失守）。三件缺一不可：① 替换**整条语句**（`Write-Host "…[WARN]…"` → `Write-Host ''`，保证仍是合法空输出）；② **替换次数进判据**（`mutWarnStripped === 4`，防「一个都没换到」的恒空转变异）；③ 断言写成「到达中止/切断点 **且** 零提示」，把「产品变静默」与「夹具跑不起来」两种形状分开。与反模式 59 同族：负对照要能证明自己测的正是那件事——空转的变异腿比没有变异腿更危险，因为它给出一个红色的、看起来可信的证据。

### 新建门的默认写法

新建门（如 `verify-t02288-snapshot-cap.mts`）从一开始就按本规约写：断言打在**返回值/库/日志行**上，
需要「产品文案」时用可注入的**行为开关**（如 `MTASK_SYMBOL_SNAPSHOT_MAX_DIRS` 注入小帽复现撞帽分支）
而不是造 2 万个真实目录或匹配源码文本；字面锚一律走 `okPair`；每条改判自带负对照与计数器牙齿检查。


### 前置件缺失收口口径（exit 码约定，T02751）

以构建产物为考卷的门（吃 `web/dist`/`server/dist` 的浏览器腿、UI 腿），前置件缺失或早于 HEAD 提交时按以下统一口径收口（单源实现：`scripts/lib/artifact-preflight.mjs`，判据本体见批㊱）：

1. **exit 非 0，但汇总里 FAIL=0**——「谁没跑 build」不是「功能失守」，红因必须与判据失配可区分；skip 道照常打印 `PASS/FAIL/SKIP` 汇总并落结果文件，不得静默退场（反模式 52：半轮没跑完不许带着读数出闸）。
2. **SKIP 不算绿**——读取方（台账、CI、人工）以 `FAIL=0` 判过是本口径要消灭的误读；本轮什么都没测必须一眼可辨。
3. **时间基准只有一个**：产物 mtime 与 `git log -1 --format=%ct` 秒级向下取整比对；同秒不判旧，缺 dist 优先于 stale 报出（缺失时比对 mtime 无意义）。
4. **设计内豁免须被点名**：产物本身是考察对象的门（`verify-packaged-shell`）不适用本口径，豁免理由写在 lib 文件头——反模式 56 的镜像：豁免不写清边界，就会变成下一条漏网门的借口。
