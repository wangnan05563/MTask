## 二、缺陷报告

### D-1【严重】重复标题计划导入时需求关联相互覆盖丢失
- **模块**：从 PRD 导入项目计划（`PlanService.importPrd`，server/src/services/PlanService.ts L1093-1101）
- **问题描述**：导入后关联回写按「标题匹配刚创建的计划行」（`rows.find(x => x.title === p.title)`）。当导入批次内存在**同名计划**（或与项目既有计划同名）时，两条 planItems 的 `find` 命中**同一行**：第二条的 `req_ids` 覆盖第一条，第一条的需求关联**永久丢失**，需求跟踪矩阵出现「需求 0 关联」假象。
- **复现步骤**（API，见脚本 TC-06）：import-prd 传入两条同名计划 `6.1 重复标题验证`，reqNos 分别 `["REQ-011"]`、`["REQ-012"]` → 实测 REQ-011 关联计划数 = 0、REQ-012 = 1。
- **影响**：矩阵数据不完整且无任何告警，用户无法察觉关联丢失；PRD 覆盖度统计失真。
- **修复建议**：`createBatch` 返回**逐条创建的 id 列表**（按输入顺序），importPrd 直接按下标回写 `req_ids`，彻底废弃标题匹配；`clean` 过滤后下标对齐。

### D-2【一般】需求与计划/待办的跨项目关联未校验
- **模块**：需求跟踪矩阵关联调整（`PlanService.linkRequirement`，L1192-1203）
- **问题描述**：`/prd-requirements/:id/link` 仅校验目标计划/待办存在，**不校验需求与目标是否同项目**——A 项目的需求可关联到 B 项目的计划（实测 200 放行）。矩阵按项目查询时 A 项目矩阵展示 B 项目的计划（标题/状态跨项目混入）。
- **复现步骤**（脚本 TC-13）：创建项目 B 与计划；将项目 A 的 REQ-001 link 到项目 B 计划 → 200。
- **影响**：数据一致性与矩阵可信度受损（同类问题在 `linkTodo` 已有「仅可关联同项目」校验，此处遗漏）。
- **修复建议**：linkRequirement 内查目标行 `project_id` 与需求行 `project_id` 比对，不一致抛「仅可关联同项目的计划/待办」。

### D-3【一般】超大文件上传返回 500 而非 413
- **模块**：PRD 解析上传（`/ai-parse-prd`、`/ai-import-wbs`，express raw limit 30mb）
- **问题描述**：31MB 文件触发 express `entity.too.large`，但错误处理器未映射状态码，实测返回 **500**（body 为 `{"error":"request entity too large"}`，尚可读）。前端据 500 会提示「服务器错误」误导用户。
- **复现**（脚本 TC-16）：POST 31MB 二进制至 `/ai-parse-prd` → 500。
- **修复建议**：错误中间件对 `err.type === 'entity.too.large'` 返回 413 + 中文提示「文件超过 30MB 上限」。

### D-4【建议】AI 解析提示词与实际排期行为不符
- **模块**：`aiParsePrd` 系统提示词（L1001）vs `createBatch`（L1284）
- **问题描述**：提示词要求「startDate 一律空串（保存后由系统按**工作日串行排期**）」，但 `createBatch` 对空日期**每行独立取今天**（T00561 各行日期独立语义），实测 8 条计划全部同日起始，非串行瀑布。PRD 导入出的计划因此天然「全部今天开始」，与提示词承诺不符。
- **修复建议**：二者取一——改提示词为「起始日由系统按导入日并行排布」，或 importPrd 后补一次串行重排（需产品决策，与 PRD 附录 C-2「手动设置串并行」线索相关）。

### D-5【建议】无效 reqNos 静默丢弃，无告警
- **模块**：`importPrd` 关联回写（L1099-1100）
- **问题描述**：`reqNos` 引用不存在/被过滤的需求编号时静默过滤（`.filter(!!x)`），返回值不含未命中信息；前端与用户无从得知部分计划未建立关联。
- **修复建议**：返回 `unlinkedReqNos` 明细或在 `coverageWarn` 类似机制中提示。

## 三、测试总结

- **覆盖范围**：导入主链路（导入 → 计划/待办落库 → 矩阵生成）、矩阵 CRUD、关联调整双向同步、删除清理、边界与异常文件（格式/空文件/超大文件/无效工具）共 18 个用例；PRD 样本真实（高情商聊天回复助手 SRS，10 需求 + 8 计划代表性子集）。
- **执行方式**：全部经 HTTP API 真实执行（隔离实例 + 独立 SQLite），脚本可一键重跑（`node scripts/t00707-prd-matrix-api-test.mjs`）。
- **通过率**：16/18；2 FAIL = 2 确认缺陷（D-1 严重、D-2 一般），另记录 D-3/D-4/D-5 三项。
- **风险说明**：D-1 会在「PRD 拆分出同名任务（实际场景常见，如多模块同名子任务）」时静默丢关联，属矩阵可信度的最大风险点，建议优先修复。
- **遗留与未覆盖**：
  1. **AI 解析环节未真实调用**（需有效模型工具）——`aiParsePrd` 的提示词遵从度、需求逐条提取质量、JSON 容错恢复需配置真实模型后人工/单独回归；
  2. **GUI 层未实测**（Agent 无 GUI）——矩阵面板渲染、「从 PRD 导入」确认对话框、coverageWarn 提示展示需人工过目；
  3. `.docx / .xlsx / .pdf` 格式的文本提取路径未覆盖（本轮以 .md 样本为主，.docx 走 `docxToMarkdown` 未测）。

## 四、关联关系验证结论

**导入功能与需求跟踪矩阵的数据一致性：正常路径完全一致，异常路径（重复标题）存在关联丢失。**
- ✅ 正常导入：需求 ↔ 计划 ↔ 待办三方关联（req_ids）与导入声明的 reqNos **逐条一致**；待办带 `[PRD]` 前缀并同步携带关联；管理节点（空 reqNos）正确不挂关联。
- ✅ 生命周期联动：link/unlink 双向即时同步、需求删除后悬空引用事务内清理、PATCH 状态/优先级即时反映。
- ❌ 重复标题计划（D-1）与跨项目关联（D-2）两处一致性缺口，已给出定位与修复建议。
