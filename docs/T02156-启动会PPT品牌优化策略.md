# T02156 优化策略：恒生模板 × WorkBuddy pptx 技能逻辑落地

> 对应诊断：《T02156-启动会PPT样式问题诊断报告.md》
> 目标：让「项目启动会 PPT 生成」产出严格遵循 `2023恒生PPT模板.pptx` 品牌视觉规范的原生可编辑 .pptx。

## 一、策略总纲：三条单源 + 一次绕过

1. **色值单源**：恒生品牌四色（`08409C` 深蓝 / `0059E9` 亮蓝 / `C9DCF6` 浅蓝 / `FFFFFF` 品牌底白字）进 `server/src/util/exportStyle.ts`，`kickoff-layout.ts` 的 `PALETTE` 只引用不定义——PRD §6.3 门禁 6「色值单源」不破。
2. **字体单源**：正文/表格/图表全显式声明 `微软雅黑`（FONT.face），图表轴/图例/数据标签一个不落——图表不再回落 Arial。
3. **背景资产单源**：恒生模板三张版式背景（封面/目录/内容）提取为 1280×720 JPEG 副本进 `server/src/services/assets/kickoff/`，构建时随 `dist` 打包。
4. **一次绕过 N1**：PRD §7 非目标 N1「不做模板母版套用」的根因是装机版无 Python 运行时；本单用 pptxgenjs 原生 `defineSlideMaster({ background })` 把背景落成**版式资产**——不引 Python、不加依赖、不走母版套用。

## 二、借鉴 WorkBuddy pptx 技能的什么

| 技能逻辑 | 本单落地方式 |
| --- | --- |
| 设计令牌先行（颜色/字体/尺寸常量集中） | 品牌四色进 exportStyle 单源，PALETTE 集中消费 |
| 全元素显式样式（不让任何文字裸奔到默认字体） | 图表四类文本（catAxis/valAxis/dataLabel/legend）字体与颜色全部显式声明 |
| 版式即资产（背景/装饰是版式不是内容） | 背景图走 `defineSlideMaster` 版式层，slide 内容保持纯原生对象（验收 5 不放宽） |
| Layout Safety 断言前置 | 沿用 T02098 六条门禁；新增 T02156 品牌门 26 条断言（背景就位/字体唯一/表头品牌底/无浮点直出/降级页带背景） |
| 「宁可素，不出坏页」 | 背景资产缺失 → 不登记该版式 → 回落默认白版式；内容与断言一条不受影响 |

## 三、具体改动清单

### 1. `server/src/util/exportStyle.ts`
新增 `BRAND_DEEP=08409C`、`BRAND_BRIGHT=0059E9`、`BRAND_PALE=C9DCF6`、`ON_BRAND=FFFFFF`（附恒生模板取色出处注释）。

### 2. `server/src/services/kickoff-layout.ts`
- `PALETTE` 增加 `brandDeep/brandBright/brandPale/onBrand` 四项；
- `auditPalette()` 增加三对对比度断言（表头白字/品牌深底、品牌深/纸面、品牌亮/纸面，全部 ≥4.5）。

### 3. `server/src/services/kickoffBuilder.ts`
- **背景**：`defineBrandBackgrounds()` 把三张背景登记为自定义版式（`KICKOFF_BG_COVER/TOC/CONTENT`），页面按 `bgKindOf(layout)` 选版式。走版式而非逐页 `slide.background`——同图 14 页共用只落一份媒体（逐页会被 pptxgenjs 复制 14 份，稿子从 150KB 涨到 1.1MB）。
- **标题/页脚**：墨黑 → 品牌深蓝。
- **表格**：表头浅靛蓝底墨字 → 品牌深蓝底白字（恒生表格头样式），斑马纹/边框不变。
- **时间线**：条 `3B5BDB`→品牌亮蓝，菱形 `B42318` 警示红→品牌深蓝（红色与「里程碑已达成」语义相反），轴线同步深蓝。
- **图表**：`chartColors` 换品牌三色；`catAxis/valAxis/dataLabel/legend` 的 FontFace 全部 `FONT.face`、颜色全部墨色；绘图区白底成「图表卡片」，网格线用边框灰。
- **数字呈现**：新增 `fmtNum`（1 位小数），只作用于派生量（报价 P84、阶段分布）；合计行（`总工作量 … 人天`）保持库内原值——验收 6「页面数字与取数同源」的比对值不动。
- `kickoffService.ts` 页脚 P50/P84 同步 1 位小数呈现。

### 4. 门禁同步（三处放行 + 一处新增）
- `verify-t02100 / t02101 / t02111`：原「全稿零位图（ppt/media 无真图）」收紧为「**内容零位图**」——slide 无 `<p:pic>`、slide 内无任何 `r:embed`（背景 embed 全在版式层），整页贴图仍是红线。理由：背景是版式不是内容，验收 5 禁的是内容位图化。
- 新增 `scripts/verify-t02156-kickoff-brand.mts`（26 断言）：三张背景按 layout 就位且媒体只落 3 份、slide 零 Arial、图表渲染路径全雅黑+墨色（doughnut 组级兜底块的 pptxgenjs 硬编码残留按「逐点已覆盖」豁免并注释）、表头品牌底白字、标题/页脚品牌蓝、工作量页无长浮点、降级页也带背景、样本 ≤600KB。

## 六、五页面背景逻辑调整（2026-10-14 二轮，用户按模板截图指正）

首轮背景映射是**按版式序号猜的**（cover=image2/toc=image3/content=image1），与模板实际用法不符。
按模板各 slide 实际引用的版式背景重新核定，恒生模板是**五页面角色体系**：

| 页面角色 | 模板依据 | 背景资产 | 本生成器对应 |
|---|---|---|---|
| 封面 | slide1/layout1（LOGO 顶左 + 标题白带） | `bg-cover.jpg`（image1.jpg） | layout=`cover` |
| 目录页 | slide2/layout3（左浅蓝 + 右白） | `bg-toc.jpg`（image2.jpeg） | layout=`toc` |
| 标题页（章节页） | slide3/layout5（中部浅蓝色带托 28pt 标题 + 32pt 编号） | `bg-section.jpg`（image3.jpeg） | layout=`section`（新增） |
| 正文页 | slide4-10/layout6（纯白底 + 标题左侧蓝色装饰 image5.png） | `bg-content.jpg`（白底合成件） | twoCol/table/chart/timeline/list |
| 结束页 | slide11/layout9（THANKS + LOGO + 版权区） | `bg-thanks.jpg`（image6.jpeg） | layout=`thanks`（新增） |

配套改动：
- **新增 `section`/`thanks` 两个版式**（服务端 `KICKOFF_LAYOUTS`、前端下拉候选、大纲提示词三处同源，t02111 G-01/G-03 守同序）；章节页渲染「32pt 编号（按出现序 01/02…）+ 28pt 章节标题」双居中，结束页渲染致谢标题 + 「项目名 · 数据截至」口径行；两者的 dataKeys 在校验层清空并记 warning（纯版式页不挂数）。
- **正文页装饰**：模板标题左侧的蓝色装饰（image5.png，0~0.92"）合成进 `bg-content.jpg`，数据/双栏族标题 x 右移 0.5" 让位，不压字。
- **目录页正文右移**至 x=2.6，议程条目排在背景白区（与模板编号列表同侧）。
- 版式族从 3 套扩为 5 套（`layoutFamilyOf` 9 值 → 5 族，t02098 U-20/U-21 同步）。

二轮验证：品牌门 33/33（新增章节编号递增、结束页口径、标题让位、五背景各就其位等断言）；既有门全绿（t02098 48、t02099 37、t02100 43、t02101 42、t02103 77、t02112 33、t02105/t02095/t02096 EXIT 0、**t02111 端到端 69/69**）；server tsc + vite build 均 EXIT 0；五页面逐张几何目检确认。
