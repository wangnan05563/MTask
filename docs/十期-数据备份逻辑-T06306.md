# 十期 · 数据备份逻辑（T06306 / REQ-039）

## 结论

新增本地数据打包备份工具 `server/scripts/backup-data-package.mjs`：把 SQLite 主库（online backup）、`artifacts/`、`templates/` 及其他数据文件打成 `tar.gz`，同时输出逐文件 `manifest.json` 与归档级 `.sha256` 旁车；`--verify` 可反向解包、逐文件校验 SHA-256/大小，并对归档内 SQLite 执行 `PRAGMA integrity_check`。**全程只读写本地文件，不连接任何云端存储。**

既有 `BackupService` 只做数据库快照（每日自动 + 手动 + 恢复），本单补齐“可搬走的完整数据包 + 完整性证据”，二者不冲突。

## 实现

### 归档结构

```
mtask-data-backup-YYYYMMDD-HHMMSS.tar.gz
├── manifest.json      # format/version/createdAt/totals/entries[size,sha256]/excluded/skipped
├── db/mtask.db        # better-sqlite3 db.backup() 在线一致快照
└── files/<相对路径>    # 数据目录内业务文件（artifacts/templates/顶层生成物等）
```

- 默认输出到 `<数据目录>/backups/`；可用 `--out` 指定。
- 归档旁车 `<name>.tar.gz.sha256` 记录整个归档的 SHA-256。

### 排除项（避免泄密与递归膨胀）

- `backups/**`：旧数据库快照，避免包内套包；
- `tunnel/**`：含访问令牌，属敏感配置，**不进入备份**；
- `tmp/**`、`mtask-test-data/**`、`*.log`；
- `mtask.db-wal` / `mtask.db-shm`、`mtask.db.bak-*`、`preupgrade-*.db*`（主库已由 online backup 覆盖）；
- 已有 `mtask-data-backup-*.tar.gz` 及旁车。

### 校验

1. 旁车 SHA-256 与归档实际哈希一致；
2. 解包后逐文件对比 `manifest.entries[].size` 与 `sha256`；
3. 对 `db/mtask.db` 执行 `PRAGMA integrity_check`；
4. 归档条目路径先做穿越检查（拒绝绝对路径与 `..`）。

任一项失败退出码 1，stdout 输出 JSON 错误清单；通过退出码 0。

### 命令

```bash
# 创建（默认数据目录：MTask_DATA_DIR > %APPDATA%\mtask\data > server/data）
npm run backup:data

# 指定目录与输出
node server/scripts/backup-data-package.mjs --data-dir <数据目录> --out <归档.tar.gz>

# 校验
node server/scripts/backup-data-package.mjs --verify <归档.tar.gz>
npm run verify:data-backup   # 跑隔离夹具契约测试
```

## 边界（本单未做）

- **不做恢复**：恢复与恢复后数据核对属 T06307；本单只交付备份包生成与完整性校验。
- **不做 UI 按钮**：完成定义为“交付工具脚本”，当前通过 npm/CLI 执行；设置页一键入口未接。
- **不打包 tunnel 配置**：访问令牌敏感，恢复后需重新配置；这是有意的安全边界。
- **依赖系统 tar**：Windows 10+/Linux/macOS 自带；无 tar 的环境会明确报错，不静默产出半包。
