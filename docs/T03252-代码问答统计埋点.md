# T03252 代码问答统计埋点（PRD 5.3）

## 1. 数据模型

新表 `workspace_qa_events`（`server/src/db/schema.ts`，CREATE IF NOT EXISTS）：

| 列 | 用途 |
| --- | --- |
| `kind` | `ask` / `citation_click` / `feedback` 三类事件同表 |
| `event_id` | 点击与反馈指回的提问事件 id（ask 行自身为空） |
| `ok` / `cited` | 本次提问是否成功、是否给出可核验引用 |
| `truncated` / `context_chars` / `question_len` | 预算与问题规模，便于后续按截断率回看 |
| `useful` | 反馈值（1 有用 / 0 无用），ask/click 行为 NULL |
| `path` / `line` | 被点击的引用 |

索引：`(project_id, created_at)`、`(project_id, kind)`。

## 2. 口径（`server/src/services/workspaceQaTelemetry.ts`）

统计全部现算，不维护计数器（避免明细与计数器双写不一致）：

- **提问数** `asks` = 绑定工作空间且真正进入检索的提问；未绑定（`no-workspace`）不计，因为没进入问答。
- **回答成功率** = `ok=1 且 cited=1` 的提问 / `asks`。分母是提问数，**不是**「有回答数」——否则模型失败/检索为空的提问会被悄悄移出分母。
- **引用点击数** = `citation_click` 按 `event_id` 去重的提问数；**引用点击率** = 去重点击 / 有引用的回答数（一篇回答点 10 次不会把点击率刷到 1000%）。
- **有用/无用** = `feedback` 行计数；同一提问重复反馈**覆盖**不堆行；`eventId` 不存在或跨项目返回 `false`（不写孤儿数据，路由回 404）。

`askWorkspace` 在三条出口各记一次 ask 事件（无证据 / 模型失败 / 正常返回），并把 `eventId` 返回给前端。

## 3. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/workspace/ask` | 响应新增 `eventId` |
| POST | `/api/workspace/ask/citation-click` | `{ projectId, eventId, path, line }`，仅计数 |
| POST | `/api/workspace/ask/feedback` | `{ projectId, eventId, useful:boolean }`；eventId 无效 404 |
| GET | `/api/workspace/ask/stats?projectId=` | `{ asks, answered, successRate, citationClicks, citationRate, useful, useless }` |

## 4. 前端（`web/src/ui/WorkspaceAskPanel.tsx`）

- 点引用 chip 时先 fire-and-forget 记 `citation-click`（失败不挡看原文），再走 `/workspace/file`。
- 回答页脚显示「本项目提问 N 次、成功率 X%、引用点击率 Y%」，并提供「回答有用吗」👍/👎（`data-t03252="useful"/"useless"`）；提交后按钮禁用并显示「已反馈」，统计随即刷新。
- 埋点失败不影响问答主链路（服务层 try/catch，前端 catch 不弹错）。

## 6. 边界

- 埋点只落库、不对外发送；无遥测上报通道。
- 只统计工作空间问答自身，不并入 `ai_usage` 卡片维度统计（两者口径不同，混用会污染 AI 用量面板）。
- 历史数据不回溯：本单上线前的问答没有明细可补，统计从上线后第一条事件起算（不伪造回填）。
