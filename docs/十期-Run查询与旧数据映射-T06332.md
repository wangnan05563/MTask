## 1. 交付内容

### 新增服务

- `server/src/services/RunQueryService.ts`
  - `GET /api/runs` 的列表查询；
  - 支持 `taskId`（内部 id 或 `Txxxxx` 编号）、`projectId`、`status`、`legacySource`、`q`、`from`、`to`；
  - 分页 `limit`（默认 50，上限 200）/ `offset`；
  - 字段覆盖：任务编号/标题、项目、状态、触发类型、模型、Prompt 版本、Token、成本、执行者、起止时间、错误码、legacy 来源/引用、步骤数。
- `server/src/services/RunLegacyMapper.ts`
  - `POST /api/runs/legacy-map` 的旧数据映射；
  - 支持 `queue_job`、`exec_session`、`ai_usage` 三类来源；
  - 稳定 ID：`legacy:<source>:<旧表主键>`；
  - 旧表只读，所有写入仅落 `agent_runs` / `agent_run_steps`。
- 路由接入：`server/src/routes/index.ts`
  - `GET /api/runs`
  - `POST /api/runs/legacy-map`
  - `GET /api/runs/:id/steps`
  - 复用既有 `GET /api/runs/:id` 详情契约（T06298）。
- 导出 Run 模型 DDL：`server/src/db/agentRunSchema.ts` 的 `AGENT_RUN_SCHEMA_SQL` 供门禁用真实建表语句初始化内存库。

### 新增验证

- `server/scripts/verify-t06332-run-api.mts`：服务层 + 内存 SQLite 门禁。
- `server/scripts/smoke-t06332-api.mts`：隔离 API 的 REST 冒烟与数据断言。

## 3. 旧数据映射规则

### 稳定 ID 与幂等

```
legacy:queue_job:<queue_jobs.id>
legacy:exec_session:<exec_sessions.id>
legacy:ai_usage:<ai_usage.id>
```

已存在映射时只刷新状态、结束时间、错误码与派生步骤，不新增 Run；`legacy_source + legacy_ref` 唯一索引作为最后一道幂等保护。

### 队列任务

- 生成 `prompt`、`tool`、`decision` 三个步骤；
- `queue_jobs.status` 映射：`queued→queued`、`sending→running`、`success→succeeded`、`failed/timeout→failed`；
- 工具模型取 `ai_tools.model`；执行者记录队列名或队列 id。

### 执行会话

- 生成 `observation`、`observation`、`decision` 三个步骤；
- `exec_sessions.status` 映射：`done→succeeded`、`failed→failed`、`aborted→cancelled`、`stalled→paused`、其他→`running`；
- 一个会话关联多个任务时取 `task_ids` 中第一个仍存在的任务，保持可复现。

### 用量记录

- 只有 `job_id` 能解析到队列任务或任务 id 时才生成 Run；
- 可解析时生成 1 个 `observation` 步骤，保留工具、模型、卡片、阶段、Token、字符数与错误；
- 无任务归属（典型是 `memory_extract` 等无任务来源的调用）返回 `skipped / no_task_attribution`，但仍生成稳定 `runId` 供追溯，不伪造 `task_id/project_id`，不写 `agent_runs`。

### 步骤语义

- legacy 步骤是“由旧记录派生的快照”，重复映射会重建该 Run 的派生步骤，以跟随旧记录终态；
- 原生 AgentRunStep 仍由 `trg_agent_run_steps_immutable` 保护，身份、seq、type、input、output、risk 不可变。

## 5. 边界与后续

- `GET /api/runs` 只列已落 `agent_runs` 的 Run；旧记录需先调用 `POST /api/runs/legacy-map` 才进入列表。
- 映射默认 `limit=100/源`，上限 1000；全量回填需要按 `offset` 分批调用。所有批次均幂等。
- `ai_usage` 没有 `task_id/project_id` 外键；无任务归属的用量只会出现在映射响应的 `skipped` 中（含稳定 ID），不会以伪造任务写入新表。这是当前旧表结构的硬边界，不是遗漏。
- 本单不新增 UI；列表/步骤 API 的前端消费留给后续 UI 任务。
- 旧表全程只读；映射只写 `agent_runs` / `agent_run_steps`。
