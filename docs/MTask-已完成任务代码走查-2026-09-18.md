**新发现 · N-1（低）前端 min 校验在选填态被跳过**

```ts
const numOk = !options.numberField || !showNum || !numRequired
  || (Number(num) >= (options.numberField.min ?? -Infinity) && num.trim() !== '');
```

普通/里程碑任务 `numRequired=false` → 后半段短路，`-3` / `0` 都能提交。
- **影响**：无数据风险——服务端 `PlanService.create` 有 `Math.max(1, Math.floor(Number(durationDays) || 1))` 兜底，最终落 1 天；但用户填 `-3` 得到 1 天**无任何提示**，属静默纠正。
- **触发场景**：工期框输入 0 或负数。
- **修复建议**：改为「填了就校验 min，空值才看必填」：

```ts
const numOk = !options.numberField || !showNum
  || (num.trim() === ''
      ? !numRequired
      : Number(num) >= (options.numberField.min ?? -Infinity));
```

### N-2（中·实质缺陷）流式生成无「输出截断」检测，半截 PRD 会被静默录入

`AIService` 的 `chat()` 有 T00714 的 `finish_reason === 'length'` 显式报错，但 **`chatStream` 没有**：

```ts
// openaiCompat.chatStream 收尾
if (!text) return { ok: false, error: 'AI 返回内容为空' };
return { ok: true, content: text };   // ← 未判断 finish_reason
```

- **影响**：max_tokens 触顶时流已输出大量内容 → `ok:true`，`prdMd` 是**半截文档**（结尾与 `<<<ISSUES>>>` 段被切掉）→ 前端展示半截 PRD，点「录入 PRD 管理视图」会把残缺文档写库，且问题清单恒为 0。
- **触发场景**：PRD 较长 / 工具 max_tokens 偏小 / 思考型模型把预算耗在 reasoning。
- **修复建议**：在 `readStreamLines` 回调中捕获最后一个 `finish_reason`，收尾复用 T00714 判定：

```ts
let finish = '';
await readStreamLines(res, (line) => { /* … */ if (json.choices?.[0]?.finish_reason) finish = json.choices[0].finish_reason!; });
if (finish === 'length') return { ok: false, error: `AI 输出超长被截断（finish_reason=length，已输出 ${text.length} 字符）——请调大该工具 max_tokens 或精简原始需求后重试` };
```

### N-4（低）死代码与可观测性

`generatePrdStream` 里 `const startedAt = Date.now()` 最终只 `void startedAt`——应记入日志：

```ts
logService.log('INFO', 'ai', `[PRD生成] project=… file=… prd=${prdMd.length}ch issues=${issues.length} 耗时=${Date.now() - startedAt}ms`);
```

### M-2（中·已知未修）refreshSymbols 同步全量扫描阻塞 SSE

生成前 `WorkspaceService.refreshSymbols` 为全同步 IO（readdirSync/readFileSync 递归），大仓库会阻塞事件循环，期间同实例的 SSE 与其他请求停摆。建议改 `fs/promises` 或 worker_threads；短期至少在 stage 之间 `await new Promise(setImmediate)` 让出事件循环。

**小结论**：功能链路完整、协议容错设计（JSON + 正文节回退）是加分项；**N-2 建议尽快修**——它直接导致「残缺文档入库」的静默数据质量问题。

### N-5（中·数据一致性）writeback 判重在「多行问题」场景失效

```ts
if (doc.content_md.includes(`### Q：${issue.question}\n`)) throw new Error('该问题的结论已回写至 PRD（按问题文本判重）…');
```

- **影响**：问题文本含换行（多行粘贴）时，正文里写入的是 `### Q：第一行\n第二行…`，而判定串同样含换行——看似匹配，但**问题文本前后若有 Markdown 包装/转义差异**即不匹配；更稳的失败场景是：问题被编辑过（`updateIssue` 改 question）后旧结论条目无法匹配 → 同一问题可重复回写多次，正文堆积重复结论。
- **触发场景**：先回写 → 再编辑问题文本 → 再回写。
- **修复建议**：改用稳定锚点（不依赖可变文本）：

```ts
const ANCHOR = `<!-- issue:${issue.id} -->`;
if (doc.content_md.includes(ANCHOR)) throw new Error('该问题的结论已回写至 PRD，无需重复回写');
const entry = `\n\n${ANCHOR}\n### Q：${issue.question}\n\n**结论**：${issue.answer.trim()}\n`;
```

### L-2（低）节在文档首行时产生重复小节

`content_md.indexOf('\n' + SECTION + '\n')` 要求节标题前有换行——若 PRD 首行即该节则判不到，else 分支会再追加一个同名节。建议改正则 `/^## 待确认问题结论\s*$/m` 匹配行首。

### L-4（低）PrdPanel 编辑态点击同文档行会静默丢弃未保存编辑

`openDoc` 在 `mode === 'edit'` 时仍重新拉详情覆盖 `editMd`。建议：编辑态下点击同一文档行直接 return（或 askConfirm「放弃未保存修改？」）。

### 一致性提示

前端 `PrdGenPanel.mergeAnswers` 与后端 `PlanService.writebackIssue` 产生**同一格式**的结论节，但是两份实现——建议在前端函数上方补注释「格式须与 PlanService.writebackIssue 保持同步」，后续可抽到共享常量/工具。

**小结论**：生命周期完整、XSS（html:false）与状态白名单/级联删除都处理到位；**N-5 建议随下一批修**（改锚点成本极低，收益是消除重复回写）。

if (globRe && !globRe.test(relChild)) continue;      // 文件名命中前

### N-10（中·数据一致性）工作空间换绑/解绑后旧符号索引残留

`workspace_symbols` 以 `project_id + path` 存储，但**没有任何清理入口**：
- 项目 `workspace_path` 改绑到另一个目录 → 旧目录的符号仍在库内 → `querySymbols` 返回**已不属于当前工作空间**的路径；
- 项目解绑（`workspace_path = ''`）→ 索引全量残留，且 `querySymbols` 的 `getProjectWorkspace` 会直接抛「未配置工作空间」，但 refresh 前残留数据仍可查（取决于调用顺序）。
- **触发场景**：用户切换项目工作空间（很常见）。
- **修复建议**：在 `PATCH /api/projects/:id`（workspacePath 变更）处清理，并在 `refreshSymbols` 开头对已换路径的情况全清重建：

```ts
// 项目绑定变更时
db.prepare('DELETE FROM workspace_symbols WHERE project_id = ?').run(projectId);
```
同时给 `querySymbols` 增加防护：若 `path` 在当前 workspace 下不存在则过滤掉（或 refresh 时顺带清理孤儿）。

### N-8（低）符号上限判断位置偏晚

`if (symbols >= 5000) return;` 只在**文件循环内**判断，`walk` 的 `readdirSync` 递归仍会遍历完整目录树（超大仓库仍全量读目录）。建议把上限判断提到 `walk` 开头（配合「已遍历目录数」计数）。

### N-9（低）中文滑窗关键词噪声

`extractKeywords` 对中文做 2~4 字滑窗，会产生「需求」「模块」「功能」等大量泛词 → autoContext 检索噪声高、命中片段相关度低。建议：英文 token 已够（≥3）时不再补中文词；或维护小停用词表过滤高频泛词。

### M-1（中·已知未修）organize 批量处理 O(N×K) 全目录扫描

`organize(taskIds)` 循环内逐任务调 `autoContext`（最多 11 关键词 × 全树遍历）。10 个任务 = 最多 110 次全树 IO。建议：按 projectId 做一次批量扫描并缓存命中（或首扫后 5 分钟 memo 复用）。

**小结论**：增量设计与忽略复用都正确；**N-10 优先于性能项**——它会导致「查到不属于当前项目的符号」的错误输出。
