# T03281 2.3 隐私红线加固

> 验收项（原单）：HTTPS / HMAC / 订阅最小化 / 可停用；快照字段白名单与敏感扫描。
> 取证时点：2026-10-29 ｜ 门：[`scripts/tests/verify-t03281-privacy-redline.mts`](../scripts/tests/verify-t03281-privacy-redline.mts) ｜ 结果：**PASS=30 FAIL=0**

## 1. 结论

Webhook 四控中三项既有实现已成立（HTTPS-only、HMAC-SHA256、可停用），**「订阅最小化」此前只在调用方自觉层面成立**——`emit()` 直接展开调用方数据，多传的 `description`/`secret` 会原样外发。本单补上出站 payload 白名单，并新建门把四控 + 快照脱敏全部打成行为断言。

## 2. 改动

| 文件 | 改动 |
| --- | --- |
| [`server/src/services/WebhookService.ts`](../server/src/services/WebhookService.ts) | 新增 `DATA_SHAPES` + `pickPayload()`：`task`/`plan`/`overdue` 三个数据块按字段白名单挑选，`emit()` 不再展开调用方原始对象 |

字段白名单：

- `task`：`id / taskNo / status / priority / title`
- `plan`：`id / title / status / progress`
- `overdue`：`date / dueTotal / overdue / rate`

服务端 `tsc -p server/tsconfig.json --noEmit` 零错误。

## 3. 门的判据（PASS=30 / FAIL=0）

| 组 | 断言 |
| --- | --- |
| S 隔离 | 隔离 `MTask_DATA_DIR`（D: 临时目录）、openssl 自签证书、`initSchema` 成功 |
| A 传输约束 | `http://` 被拒；URL 内嵌凭据被拒；回环地址需显式 `allowIntranet`；**被拒请求没有落库** |

| C HMAC 与投递 | 本地 HTTPS 端点收到 POST → 用同密钥在门内重算 `sha256=HMAC-SHA256(secret, rawBody)` 与请求头逐字节相等；错误密钥负对照必不相等；事件 ID/时间戳头齐备；成功日志记 200/attempts=1；3xx 重定向被拒且不跟随（防降级到非 HTTPS） |
| D 密钥与停用 | 接口只回掩码（`t032****6789`），不含明文；停用即把待执行投递置 failed 并清 `next_attempt_at`；停用后不再产生新投递 |
| E 重试与日志 | 1 → +1 分钟、2 → +5 分钟、3 → +30 分钟、第 4 次判 failed 且停止；`pruneLogs` 清理 >30 天已结束记录、保留 pending |

## 5. 边界

- 门内的本地端点用自签证书，`NODE_TLS_REJECT_UNAUTHORIZED=0` **仅在投递断言窗口内开启**，窗口结束立即恢复，且不传给子进程（F 组的快照门在已恢复的环境里跑）。
- 内网判定只看 URL 主机字面量，DNS 解析结果不在同步校验范围——与既有实现口径一致，本单未改。
- HMAC 密钥轮换后的旧投递重试会用新密钥签名（既有行为），本单未涉及。
