# T03257 建议入口显隐与禁用展示（AI-203 ④）

## 1. 范围

| 验收条 | 落点 |
|---|---|
| 未启用建议可隐藏 | AI 从未配置任何工具（`no_tool`）且台账从未展示过建议 → 两个建议入口都不渲染 |
| 配置失效按 D-14 显示禁用原因 | 配置过但当前不可用（工具全停用 / 未填模型 / 配置不符）→ 入口可见但禁用，`title` 与页面原因条给出原因与「去模型管理」修复动作 |
| 用户主动关闭 | T03256 开关关闭 → 隐藏（沿用，不反向受本单影响） |

本单不新增数据表、不改服务端：判据全部消费既有 `/ai/readiness`（D-14 单源，与运行时同口径）与 `/ai/suggestions/stats` 的 `shown`。

## 2. 判定口径

新增纯函数 `web/src/utils/suggestVisibility.ts`：

```ts
suggestEntryState({ featureEnabled, everShown, readiness }) → 'hidden' | 'disabled' | 'visible'
```

| 条件 | 结果 |
|---|---|
| 开关关闭 | hidden |
| 诊断未返回（加载中） | visible（避免首帧隐藏/闪现） |
| `ready = true` | visible |
| 不可用且 `code = no_tool` 且从未展示过 | hidden（从未启用） |
| 其余不可用（`missing_model` / `all_disabled` / `config_issue`，或展示过但工具被删） | disabled（可见 + 原因） |

「展示过」取台账 `shown > 0`：一旦建议真的展示给用户，就说明该能力启用过，此后即使工具被删也只能禁用不能隐藏——与 `aiReadiness.tsx` 头部约定「只有从未启用过的上下文建议允许隐藏」一致。

## 3. 前端

`web/src/pages/TasksPage.tsx`：

- 新建表单与任务行的建议按钮改为按 `suggestEntry` 渲染：
  - `hidden` → 不渲染；
  - `disabled` → `disabled` + `data-t03257="disabled"`，`title` 走 `aiBlockedTitle(readiness, 基础文案)`，即「分类建议 — … — 暂不可用：<原因>（点击「去模型管理」修复）」；
  - `visible` → 原行为。
- 页面工具条已有的 `AiUnavailableHint`（D-14 原因条）继续提供可见原因与修复按钮，本单不重复造另一条。
- 统计取数同时读 `enabled` 与 `shown`，一次请求喂两个判据。

## 5. 边界

- 判据只覆盖「建议入口」；其它 AI 按钮的显隐策略仍由各自卡片（T03176）决定。
- `no_tool` 定义为「一条 AI 工具都没配置」；只配了开发工具但没有整理工具的混合场景，入口保持可见，点击时按既有提示要求先配置整理工具。
