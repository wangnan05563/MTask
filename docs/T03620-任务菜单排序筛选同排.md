# T03620 任务菜单排序筛选布局优化（同排展示）

## 1. 改动

`web/src/pages/TasksPage.tsx` 列表视图：

- 三个 tab（待办/已完成/搁置）所在的 `.op-host` 行改为 `alignItems: center`，在三个 tab 之后追加一个
  `data-t03620="tab-controls"` 容器（`marginLeft: 'auto'`，即贴着「搁置」tab 所在行的右端）。
- 原三个 tab 各自下方独立的排序/过滤行被删除，控件按当前 `activeTab` 互斥渲染在同一容器内：
  - 待办 → `待办排序`（`data-t03620="todo-sort"`）
  - 已完成 → `已完成排序` + `验证状态过滤`（`data-t03620="done-sort"` / `done-filter`）
  - 搁置 → `搁置排序`（`data-t03620="shelved-sort"`）
- 容器带 `op-hidden`，沿用既有 `.op-host:hover/.op-host:focus-within` 规则：默认 `visibility:hidden`，
  悬浮 tab 行淡入；键盘焦点进入任一 tab 时同样显形（`focus-within`）。
- 多选模式的全选复选框仍留在原位置（独立 `op-host` 行，仅 `multiSelect` 时渲染），未随之迁移。

## 2. 与工单文字的一处偏差（判断项）

工单约束列表里写「搁置选项卡 → 显示搁置排序 + 验证状态过滤」。实现里 `验证状态过滤` 放在已完成 tab：

- 该过滤只作用于 `visibleDone`（`TasksPage.tsx` 的 `visibleDone` 派生即 `matchVerified(t, doneFilter)`），
  搁置列表从未应用过它；
- 若照字面挂到搁置 tab，要么是无效控件，要么得给搁置列表新增验证过滤——而 `doneFilter` 默认
  `unverified`，一旦生效会**默认隐藏已置为已验证的搁置任务**，属于验收要求「无功能回归」禁止的行为变化。

因此按「迁移布局、不改行为」的工单主旨，把过滤留在其实际生效的已完成 tab。
