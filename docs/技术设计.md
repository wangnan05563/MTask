## 1. 技术栈选型与理由

| 层 | 选型 | 理由 |
|----|------|------|
| 桌面壳 | **Electron**（预留） | 成熟稳定、生态大；与竞品 Super Productivity 同思路。Tauri 更轻但需 Rust 工具链，骨架阶段以 Electron 为默认，后期可切换 |
| 前端 | **React 18 + Vite + TypeScript** | 主流、类型安全；LibreChat/Open WebUI 均为 React 系，生态可借鉴 |
| 后端 | **Node.js + Express + TypeScript** | 本地 API 服务，替代"纯前端直连数据库"，便于队列/加密/审计逻辑与 UI 解耦（参考 Vikunja API-first） |
| 数据库 | **SQLite（better-sqlite3）** | 用户已确认 SQLite 文件；better-sqlite3 同步 API、零配置、单文件可移植（呼应 SRS NF5） |
| 密钥加密 | **Node crypto（AES-256-GCM）** | 系统内嵌，无额外依赖；API Key 加密落库（FR3.5） |

**结构决策**：桌面壳内嵌一个本地 HTTP 服务（127.0.0.1 随机端口），前端通过该 API 交互——既保证 UI 与数据层解耦，也为将来拆出 Web 版/CLI 预留接口。

## 3. 数据库设计（SQLite DDL）

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE IF NOT EXISTS projects (
  id          TEXT PRIMARY KEY,            -- UUID
  name        TEXT NOT NULL,
  description TEXT DEFAULT '',
  sort_weight INTEGER DEFAULT 0,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS tasks (
  id          TEXT PRIMARY KEY,
  project_id  TEXT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  title       TEXT NOT NULL,
  description TEXT DEFAULT '',
  priority    TEXT NOT NULL DEFAULT 'normal',   -- low/normal/high/urgent
  status      TEXT NOT NULL DEFAULT 'todo',     -- todo/done
  archived    INTEGER NOT NULL DEFAULT 0,
  archived_at TEXT,
  ai_summary  TEXT,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_tasks_project ON tasks(project_id);
CREATE INDEX IF NOT EXISTS idx_tasks_archived ON tasks(archived);

-- 任务截图/图片附件（图文混合描述，2026-08-20 新增）
-- 粘贴截图以 BLOB 落库，保持 SQLite 单文件可移植（SRS NF5）；随任务级联删除
CREATE TABLE IF NOT EXISTS task_images (
  id         TEXT PRIMARY KEY,
  task_id    TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE,
  mime_type  TEXT NOT NULL DEFAULT 'image/png',
  data       BLOB NOT NULL,                   -- 单图 ≤ 8MB（服务层校验）
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_task_images_task ON task_images(task_id);

CREATE TABLE IF NOT EXISTS ai_tools (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  type        TEXT NOT NULL,               -- code_assistant/agent/llm
  purpose     TEXT NOT NULL DEFAULT 'develop', -- organize/develop/develop,organize
  endpoint    TEXT NOT NULL,
  api_key_enc TEXT,                        -- 加密后密文（可为空=免密钥）
  model       TEXT,
  temperature REAL DEFAULT 0.2,
  max_tokens  INTEGER DEFAULT 4096,
  timeout_ms  INTEGER DEFAULT 60000,
  enabled     INTEGER NOT NULL DEFAULT 1,
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS queues (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL,
  date       TEXT NOT NULL,                -- YYYY-MM-DD
  status     TEXT NOT NULL DEFAULT 'draft',-- draft/running/finished
  created_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS queue_jobs (
  id               TEXT PRIMARY KEY,
  queue_id         TEXT NOT NULL REFERENCES queues(id) ON DELETE CASCADE,
  task_id          TEXT NOT NULL REFERENCES tasks(id),
  tool_id          TEXT NOT NULL REFERENCES ai_tools(id),
  order_index      INTEGER NOT NULL DEFAULT 0,
  status           TEXT NOT NULL DEFAULT 'queued', -- queued/sending/success/failed/timeout
  request_payload  TEXT,
  response_payload TEXT,                   -- AI 返回文本（保存待人工合并）
  error            TEXT,
  sent_at          TEXT,
  finished_at      TEXT
);
CREATE INDEX IF NOT EXISTS idx_jobs_queue ON queue_jobs(queue_id);
```

## 4. AIAdapter 统一接口（FR3 核心）

```ts
export interface TaskContext {
  taskId: string;
  title: string;
  description: string;
  aiSummary?: string;
  projectName: string;
  attachments?: string[];
}

export interface ToolConfig {
  endpoint: string;
  model?: string;
  temperature?: number;
  maxTokens?: number;
  timeoutMs?: number;
  apiKey?: string; // 仅运行时解密传入，绝不落日志
}

export interface JobResult {
  ok: boolean;
  content?: string;   // AI 返回文本
  error?: string;
  rawMeta?: Record<string, unknown>;
}

export interface AIAdapter {
  readonly type: string; // 'openai-compatible' | 'claude' | 'ollama' | ...
  testConnection(config: ToolConfig): Promise<{ ok: boolean; message: string }>;
  send(context: TaskContext, config: ToolConfig): Promise<JobResult>;
}
```

**适配器清单（2026-08-19 已升级为真实调用实现，并完成 mock 联调验证 29/29）**：
- `OpenAICompatAdapter`：`POST /v1/chat/completions`（**endpoint 自动补 /v1**，兼容「填根域名/填到 /v1」两种习惯），支持 OpenAI、DeepSeek、通义等；`testConnection` 走 `/models`
- `ClaudeAdapter`：Anthropic `POST /v1/messages`（x-api-key + anthropic-version 头）；`testConnection` 用 1-token 空会话探测
- `OllamaAdapter`：本地 `POST /api/chat`（stream=false）；`testConnection` 走 `/api/tags`

联调产物（`server/scripts/`）：`mock-ai-server.mjs`（零依赖 mock 端点 + `/__last` 请求记录）、`adapter-e2e.mjs`（真实跑适配器 TS 代码，51 项断言覆盖协议/解析/错误透传/超时，以及 WorkBuddy 异步提交 submit + 轮询 poll）。运行方式（Node 24 下需用 tsx 而非 `--experimental-strip-types`）：

```bash
cd server/scripts
node mock-ai-server.mjs                          # 终端 1
node ../../node_modules/tsx/dist/cli.mjs adapter-e2e.mjs  # 终端 2
```

系统提示词固定约束输出形态（思路 / 完整代码 / 风险与验证），便于人工审阅合并（FR4.4）。

**调度原则**（对应 FR4）：QueueService 按 `order_index` 顺序消费 Job；失败可重试；全部 Job 先取任务上下文快照存入 `request_payload`，避免发送后任务被改导致回执错位。

## 5. 模块边界

| 模块 | 职责 | 参考来源 |
|------|------|----------|
| `services/TaskService` | 任务 CRUD、状态流转 todo⇄done、批量移动、**采纳（adoptContent）**；TaskView 附带 images 元信息 | SRS FR1/FR5 |
| `services/TaskImageService` | 任务截图附件：base64 上传（≤8MB）/元信息列表/二进制读取/删除 | 图文混合描述（2026-08-20 新增） |
| `services/QueueService` | 队列构建/触发/Job 状态机/重试 | SRS FR4；OpenHands 控制器思路 |
| `services/AIService` | 梳理（FR2）与分发（FR4）共用适配层 | SRS FR2/FR4 |
| `services/ConfigService` | AITool 注册、密钥加密、连接测试、默认绑定 | SRS FR3 |
| `services/ArchiveService` | 归档/还原/删除（仅归档可删） | SRS FR6 |
| `adapters/*` | 各 AI 工具协议适配 | Continue/LibreChat provider 抽象 |

## 6. 核心流程落点

1. **AI 梳理（FR2）**：`TaskService → AIService.organize(task, tool)` → 结构化文本先入前端草稿，**用户确认后**回填 `ai_summary`。
2. **队列发送（FR4）**：`QueueService.sendAll(queueId)` → 逐 Job 调 `AIAdapter.send()` → 结果写入 `response_payload`（**仅保存文本，待人工合并**，呼应 Plandex Review Sandbox 思路）。
3. **审阅采纳（FR4.4/FR5.1，2026-08-19 新增）**：前端队列页 Job 行可展开审阅（request 快照 / response 全文）→ 「采纳」调 `POST /api/tasks/:id/adopt { content }` → `TaskService.adoptContent` 将文本保存到 `ai_summary` 并置任务 done；「复制」供人工粘贴合并。
4. **归档删除（FR6）**：`ArchiveService.archive(taskIds)` → `archived=1`；仅 `archived=1` 的任务允许删除。
5. **截图粘贴（图文混合描述，2026-08-20 新增）**：任务创建/描述编辑区监听 `paste` 事件，剪贴板图片经 FileReader 转 dataURL → `POST /api/tasks/:id/images { data, mimeType }` 以 base64 存入 `task_images`（BLOB）；`GET /api/images/:id` 直供 `<img>` 展示（Electron 壳内由 webRequest 将 `/api/*` 重定向到本地服务）；`DELETE /api/images/:id` 支持删除/替换。任务列表/详情接口随 TaskView 返回 `images` 元信息（不含 BLOB，批量查询避免 N+1）。图片随任务归档保留、随任务删除级联清理；AI 梳理/队列分发仍只消费文本字段，不受影响。
