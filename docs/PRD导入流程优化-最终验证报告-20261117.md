1. **描述厚度兜底**：`fillPlanDescription` / `ensurePrdPlanDepth`
   - 对不足 50 字的 plan 自动追加“完成定义：产出…并通过 AC…验收；不包含 P2/P3 范围…”。

   - 把 `acceptanceRefs` 合并进 `reqNos`，落库时写入 plan 的 `req_ids`。

   - 本轮 `REQ-012` 由此挂到 `开发调度器核心逻辑`。

## 五、仍建议继续改进的点

1. **M5.1 承载 26 条 AC，单卡偏重**
   - 当前作为“全量 AC 验收”汇总任务可执行，但 AI 一次完成 26 条验收容易漏项。
   - 建议下一轮拆为 2~3 条验收任务（按手动/自动/审计与性能分组），任务总数会从 33 到 35~36，仍在 30~40 区间。

2. **M5.1 描述中的 AC 范围与实际引用不完全一致**
   - 描述写“AC-01 至 AC-26”，实际 `acceptanceRefs` 还包含 AC-27/28/30 以及 AC-19~23。
   - 建议提示词禁止写死 AC 编号区间，改为“按任务关联的验收项逐项验证”；或在后处理阶段按实际 refs 重写这段。

3. **分片回退仍是风险路径**
   - 100k 字符 PRD 目前走单轮；若单轮失败仍会落到 `aiParsePrdChunked`，分片会各自造 WBS。
   - 当前质量门会拦下多套 WBS，不会把坏结构落库；但体验上是“导入被拦”，不是自动收敛。
   - 建议补“分片结果二次归并”或对超长 PRD 强制单轮 + 更强模型。

4. **结构字段尚未持久化**
   - DB 没有 `wbs_code/parent_code/import_batch_id` 列，结构信息目前只在导入 payload/内存中存在。
   - 旧 174 条计划未做批次软归档，`MTask十期` 仍是旧数据。
   - 建议下一轮加列 + 批次归档，支持“新旧批次对比/回滚”。

5. **预演与正式导入仍有口径差**
   - 孤儿统计已对齐，但 `previewPrdImport` 尚未调用服务端质量门；前端预演通过后仍可能在 import 阶段被拦。
   - 建议把 `validatePrdImportDraft` 只读复用到 preview，提前返回 `readiness`。

6. **前端还没有真正的树形预演 UI**
   - 当前只有日志和质量门阻断，“生成可执行计划”按钮未改名/改造。
   - 建议以里程碑→任务两级树展示，并在节点上标 AC/需求覆盖。
