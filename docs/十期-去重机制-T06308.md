# 十期 · 导入去重机制（T06308 / REQ-041 / AC-06）

## 结论

把导入去重从「查重 → 建任务 → 登记键」改为「**原子占键 → 建任务 → 绑定任务**」：同一项目、来源、外部 ID 的并发确认只有一个请求能拿到 claim，另一个直接计入 `skipped`；建任务失败时 claim 随事务回滚，不留死键。CSV/JSON 两条确认通道共用该机制，**不迁移、不回填、不删除任何历史数据**。隔离服务契约 **15/15 PASS**，T06304 导入回归 **17/17 PASS**，server tsc 0。

## 根因

T06304 已有 `task_import_keys` 唯一索引，但写入顺序是先查集合、再 `TaskService.create`、最后 `markImported`。两次同键确认若在「查重」与「建任务」之间交错，都会通过查重并各建一条任务；随后唯一索引只允许一条键登记，另一条任务成为无键孤儿。索引只能保证键唯一，不能保证任务唯一。

## 实现

- `ImportKeyService` 新增：
  - `claimImported(projectId, source, externalId)`：`INSERT OR IGNORE` 抢占唯一键，返回 `claimId` 或 `null`；占位 `task_id = pending:<claimId>`。
  - `bindImportedTask(claimId, taskId)`：任务创建成功后绑定真实 `task_id`；绑定失败抛错回滚整批。
  - `markImported` 保留兼容语义，内部改为 claim + bind。
- `server/src/routes/index.ts` 的 `/tasks/import-csv/confirm` 与 `/tasks/import-json/confirm`：
  1. 集合命中直接 `skipped`；
  2. `claimImported` 失败也计入 `skipped`（覆盖并发/跨进程）；
  3. claim 成功后才 `TaskService.create`，随后 `bindImportedTask`；
  4. 任一条抛错由既有单事务整体回滚，claim 一并撤销。
- 去重键仍为「来源 + 外部 ID」，沿用来源小写归一、外部 ID `trim + 200 字符上限`；无外部 ID 时回退标题去重。
- **无 schema 变更、无历史数据回填、无重复任务清理**：只对新的确认请求写新键。

- 本单仍遵守「不修改历史数据」：无 schema 变更、无回填、无重复任务清理；只对新确认请求写键。

## 边界（本单未做）

- 不做存量重复清理：任务要求「不修改历史数据」，已有重复任务与原键记录保持原样。
- 不做平台 API 增量同步：Trello/Jira/GitHub 仍按导出文件导入；本单只保证确认通道去重。
- 不做 1k 行进度条：沿用 T06304 的一次性预览 + 确认口径。
- 不提供去重键管理 UI/API：键表仅由导入确认通道写入，避免人工改键破坏唯一性。
