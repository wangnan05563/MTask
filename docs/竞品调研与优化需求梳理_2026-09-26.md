## 1. 四维对比（精简）

### 1.1 技术选型 / 架构
| 项目 | 架构风格 | 数据层 | 对 MTask 的参照点 |
|------|----------|--------|-------------------|
| OpenHands | 事件流（event stream）驱动 + 沙箱执行 + Web/CLI 双端 | 服务端 DB + 会话回放 | 事件溯源式任务历史、并行会话 |
| AppFlowy | 本地优先（Flutter+Rust 内核），可选云同步 | 本地库优先 + 端到端加密可选 | 桌面单文件 SQLite 同路线；加密是分水岭 |
| Plane | Web 自托管（Django+Next/React） | PostgreSQL | 视图配置保存、通知中心 |
| GPT Pilot | 规格驱动：spec→tasks→逐步实现+人工审查 | 项目文件即状态 | 审查点（human checkpoint）节奏 |
| task-master | CLI/MCP 工具集（无 UI），文件存任务 | Markdown/JSON per project | PRD→拆解→复杂度→依赖→next 推荐闭环 |
| Huly | 全能平台（自研协同内核） | 自有 DB | 负面参照：范围失控与归档风险 |
| Vikunja | API 优先（Go） | PostgreSQL/SQLite | API token、ICS 订阅等"拥有感"特性 |

### 1.2 需求功能覆盖（MTask 视角）
| 能力 | MTask 现状 | 最佳参照 |
|------|-----------|----------|
| PRD→任务拆解 | ✅ 已有（aiParsePrd + 矩阵 + WBS） | task-master（复杂度分析/子任务扩展）、Plane（intake 分流） |
| 任务依赖与排期 | ✅ deps/里程碑/节假日 | task-master（next-task 推荐）、Plane（甘特/cycles） |
| AI 执行闭环 | ✅ ai_state 状态机+回传+验证 | OpenHands（事件流/回放/diff）、GPT Pilot（审查点） |
| 运行可观测 | ✅ AI 控制台+流光状态（T01038） | OpenHands（会话回放）、WorkBuddy（流光文字，已对齐） |
| 通知体系 | ❌ 无 | Plane 通知中心、OS 级通知 |
| 统计/仪表盘 | ❌ 无 | Huly/Plane dashboards |
| 主题系统 | ⚠️ light/dark+字号 | AppFlowy（外观设置+自定义色）、WorkBuddy |
| 数据主权 | ⚠️ 本地 SQLite，无加密/无自动备份 | AppFlowy（端到端加密可选）、Vikunja（API token/ICS） |

### 1.3 客户体验对比要点
- **OpenHands**：每个动作可回放、每处修改有 diff——「信任感」是 AI 工具第一体验。
- **Plane**：列表/看板/甘特一键切换、保存的视图、批量编辑——重操作效率。
- **AppFlowy**：即开即用的模板库与离线可用——「零门槛上手」。
- **task-master**：`next` 命令直接告诉你「现在该做什么」——消除决策瘫痪。
- **MTask**：任务闭环与验证纪律独树一帜（verified 状态、回传归并、里程碑联动），但**可观测性 UI 与效率交互**落后头部产品一代。

## 4. 优先级路线建议

- **第一批（体验地基，P0×10）**：O-A1 通知、O-A2 重试、O-A3 下一个任务、O-B1 复杂度、O-B3 仪表盘、O-B4 甘特、O-B6 验收准则、O-C1 四视图、O-C2 侧滑详情、O-D1/O-D2 主题自定义+跟随系统、O-E1 备份、O-E2 加密。
- **第二批（效率纵深，P1）**：通知中心、事件时间线、批量操作、拖拽看板、命令面板增强、并行队列、提交关联、标签、FTS 全文搜索、骨架屏/动效/密度/虚拟滚动、主题预设、流光延展。
- **第三批（生态与长尾，P2）**：diff 视图、空态引导、循环任务、API token、Markdown 导出、高对比度、i18n、插画。

## 5. 差异化结论

1. **MTask 的护城河是「验证闭环」**——没有任何同类产品把「AI 执行 → 结果回传 → 人工/自动验证 → 归并」做成一等公民（GPT Pilot 的审查点最接近，但无持久化任务管理）。O-B6（验收准则字段化）是把护城河做深的最高杠杆。
2. **直接同类的空窗期**：task-master 转向商业产品（Hamster）、Huly 归档、GPT Pilot 放缓——「桌面端 + 本地数据 + AI 任务闭环」组合位当前没有头部占位者，值得加快 P0 批次。
3. **效率与外观是体验短板**，但均为成熟范式（Plane 的视图体系、AppFlowy 的主题体系、OpenHands 的事件流），可低成本跟进，不构成风险。
4. **动效语言已有起点**：T01038 流光文字与 WorkBuddy 对齐后，O-C3/O-C4/O-D5 沿同一体系铺开即可形成完整动效 token。
