## 改动

### 服务端

- 新增 `server/src/services/GlobalSearchService.ts`：
  - 只读本地 SQLite，**不调用** `WorkspaceService.searchAsync`，不索引外部工作空间文件。
  - **任务**：可见口径与任务页一致（`archived=0`、`history_at=''`、`shelved=0`）；检索 `title / description / task_no / handle_result / ai_summary`；复用 `parseTaskQuery/compileTaskQuery` 的 `status:/priority:/project:` 语法，解析或编译失败降级全文并回传 `degraded/hint`；`outOfSight` 按归档/历史资产/搁置三桶计数。
  - **Run**：`agent_runs`（T06293 增量表，存在即查询）∪ `exec_sessions`（当前实际可用的执行实例）。任务标题/编号、会话 ID、平台、阶段、状态、关联任务均可命中；原生 `legacy_source='exec_session'` 的行与旧会话按 `legacy_ref` 在结果层去重。
  - **排序**：任务按 `title`/`task_no` 精确 > 前缀 > 包含 > `updated_at DESC`；Run 按会话 ID/任务标题同口径。每条结果附 `snippet`。
  - **输入**：`type:task|run|all` 在服务端裁剪对象组；`@me` 移除并在 `hint` 说明「无负责人字段」；单查询截 200 字符，`limit` 默认 10、最大 25（每组上限）。
  - **响应**：`query/normalizedQuery/groups[{type,label,total,items}]/total/limit/elapsedMs/degraded/hint/zeroResult/suggestions/outOfSight`。
- `server/src/routes/index.ts`：
  - 新增 `GET /api/search?q=&limit=&type=`；`type=` 与 q 内 `type:` 取交集。
  - 新增 `GET /api/exec-sessions/:id`：会话面板首屏只取最近 100 条，搜索命中更早的 Run 时按 id 取回单行（复用任务摘要），供前端并入看板后定位。
- `server/src/services/ExecSessionService.ts`：抽出 `hydrate()`，`listSessions()` 与新增 `getSession()` 共用同一份关联任务摘要；不改变 100 条首屏与停滞判定口径。
- 未改数据库 schema；无迁移。

### 前端

- `web/src/pages/CommandPalette.tsx`：
  - 数据源从 `/tasks/search` 改为 `/api/search`，一次请求同时得到任务与 Run；输入 180ms 防抖，服务端轮次令牌丢弃迟到响应。
  - 结果带类型徽标、上下文预览第二行、`命中 N 条 · 耗时` 状态行；零结果展示服务端建议；任务命中为 0 但范围外有命中时继续显示三桶入口。
  - 输入关键词时搜索结果优先，空查询时页面/项目/提示词/设置直达优先；`↑↓` 移动高亮并自动滚入视口，Enter 执行。
  - Run 结果：执行会话写 `execSessions.focusId` 并切执行会话页；原生 Run 暂落关联任务详情（T06298 接入 Run 详情页后再改）。
- 新增 `web/src/ui/focusExecSession.ts`：会话存储 + `mtaskFocusExecSession` 事件双通道，兼容「页面未挂载」与「已停在执行会话页」。
- `web/src/pages/ExecSessionsPage.tsx`：
  - 消费搜索定位意图；若目标不在最近 100 条，调用 `/exec-sessions/:id` 取回并 pin 进看板（每次轮询刷新仍保留），随后滚动 + 1.6s 高亮脉冲。
  - 卡片增加 `data-session-id`，定位不改变原有 FLIP 动画与状态列。
- `web/src/api/client.ts` 增加 `SearchHitType/SearchHitSource/SearchMatch/SearchHit/SearchGroup/SearchOutOfSight/SearchResponse` 契约。
- `/tasks/search` 保留原契约，任务页与旧入口不受影响；`/workspace/search` 仍独立，命令面板不调用。

## 边界

- **范围**：统一 API 只交付任务 + Run。项目、需求、计划、提示词、报表、设置、文档未进入 `/api/search`；页面/设置/项目/提示词条目仍由命令面板本地生成，不能宣称 PRD §A3 的 9 类对象已全量覆盖。
- **文档口径**：当前库没有独立「文档」检索表，AC-02 的 1,000 份文档基准使用任务文档（标题+正文+处理结果+AI 摘要）作为本地可检索文本；未索引 `prd_docs`，更未索引外部工作空间文件。若验收要求独立文档对象，需要另开派生单。
- **Run 口径**：`agent_runs` 增量表已存在但当前没有写入方（生产快照 0 行）；实际可见 Run 全部来自 `exec_sessions`。原生分支已按表结构实现并有内存库覆盖，T06298 接入 Run 详情页后可直接复用；当前原生 Run 点击落到关联任务详情，不是独立 Run 详情。
- **语法**：`@me` 未生效（任务/会话表无负责人字段），服务端会移除并回传原因；`type:` 只支持 task/run/all；`status:/project:/priority:` 仅作用于任务，Run 不做同名字段筛选。
- **排序**：只实现「精确标题/编号 > 前缀 > 包含 > 最近更新」；没有语义向量、没有最近使用行为记录，空查询的“最近”是 `updated_at/last_heartbeat` 而非用户点击历史。
- **写动作**：未做「新建任务、完成、开始、排队、切主题、打开设置、导入」及确认/撤销；本单不产生写副作用。A3 的写命令需派生单，不能把页面导航当作动作命令。
- **Run 计数**：`Run` 组 `total` 是 `agent_runs ∪ exec_sessions` 的源计数；结果层已按 legacy_ref 去重，但两表回填重叠时总数可能略高于可见条目。当前生产原生表为空，不影响现状。
- **性能边界**：真实库 100 次搜索 P99 339.3ms（一次离群），AC-02 仅约束 P95；若后续任务正文继续增长到数万级，应改为增量索引或 FTS，不应继续依赖全表 `LIKE`。
