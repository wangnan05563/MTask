## 3. 本轮优化

### 3.1 任务行 `content-visibility` 样式缺失（实际瓶颈）

- 现象：`TasksPage` 给 `li.task-item` 挂了 `cv-auto` 类，但 `.cv-auto` 样式只写在设置页（`settings.tsx`），任务页从未加载该样式；5k 列表滚动基线 **54.6fps**（p95 33.3ms，3 个长帧）。
- 修复：在 `TasksPage` 页内样式补 `.cv-auto { content-visibility:auto; contain-intrinsic-size:auto 40px; }`，让屏外行跳过渲染。零业务行为变化。
- 效果：5k 列表 **54.6 → 59.6/60.0fps**，长帧 3 → 0。
- 说明：`TASK_OVERSCAN` 保持 4、`TASK_WINDOW_STEP` 保持 2，未改动窗口数学与触底续取；曾试验 overscan=2，帧率反而降到 49.2fps，已回退。

### 3.2 Windows 换行导致 T03215 门误红

- 现象：`verify-t03215` 的 S-04 正则按 `\n` 写死，Git 工作区 CRLF 下 `const nearEnd = count > 0\r\n` 匹配失败，门报「行为失守」。
- 修复：读取 `TasksPage.tsx` / `taskListWindow.ts` 源码后统一 `.replace(/\r\n/g, '\n')`，只影响测试读取口径，不碰产品代码。
- 回归：T03215 门 **32/32 PASS**。

## 5. 边界与遗留

- headless Chrome + SwiftShader，未覆盖真实 GPU、移动端、120Hz 屏；真机数值可能更高。
- 看板 5k 全量仍渲染 5000 个 DOM 节点（本次滚动达标但首次切换 ~1.07s）；更大规模（1 万+）建议后续做看板列虚拟化。
- 列表 5k 滚动达标依赖 `content-visibility`（Chromium 桌面壳支持）；非 Chromium 环境无此优化，需另测。
- 性能报告只覆盖任务页列表/看板与任务搜索，不含日历、表格、全局搜索与后端导出等路径。
