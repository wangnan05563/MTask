## 实现事实（既有代码）

`server/src/services/RunRiskService.ts`

- 审批创建时 `expires_at = now + approvalTimeoutMs`（默认 24h，最少 60s）。
- `expireApprovals(now)` 扫描 `status='pending' AND expires_at <= now`：
  - 审批 `status='expired'`、`reason='审批超时'`；
  - 原步骤与 approval 步骤均 `failed`；
  - Run `failed`、`error_code='approval_timeout'`、写 `ended_at`；
  - 审计 `event_type='expired'`、`actor='system'`、`reason='审批超时'`，detail 带 `expiresAt`。
- `decideApproval` 先调 `expireApprovals`，过期审批不能补批；`listApprovals({status:'pending'})` 亦惰性触发扫描。
- 审计表触发器禁止 UPDATE/DELETE，只追加。

## 边界与限制

- 只覆盖单节点审批；多节点会签不在本单范围。
- 超时扫描由调用方/读取路径触发（`decideApproval`、`listApprovals({pending})` 或显式 `expireApprovals`），没有独立定时器；这是既有设计，本单未改。
- 默认 24h 超时在生产侧生效；测试通过改写 `expires_at` 模拟到期，不缩短生产窗口。
