### P0-1. T06329：旧 localStorage 是 JSON 编码，新 store 按裸串读取，升级后项目作用域被重置

**位置**：
- 旧实现：`web/src/pages/TasksPage.tsx`（`1a2c5e7^`）`const [activeProject, setActiveProject] = usePersistentState('tasks.activeProject', '')`
- 旧写入：`web/src/ui/session.ts:24-30`，`storage.setItem(key, JSON.stringify(value))`
- 新读取：`web/src/ui/activeProject.ts:19-25`
- 新回退：`web/src/pages/TasksPage.tsx:1138-1142`

```ts
// activeProject.ts:19-25
function readStored(): string {
  try {
    return globalThis.localStorage?.getItem(ACTIVE_PROJECT_KEY) ?? '';
  } catch {
    return '';
  }
}
```

**问题**：旧 `usePersistentState` 写入的是 JSON 字符串，不是裸字符串。例如：

- 旧选择项目 `p1` → localStorage 实际值 `"\"p1\""`（带引号）
- 旧选择空串（全部项目）→ 实际值 `"\"\""`
- 旧选择全部哨兵 → 实际值 `"\"__all__\""`

新 `readStored()` 不做 `JSON.parse`，直接把这些带引号的字符串当作项目 ID。`TasksPage` 在 `:1140-1142` 发现它不在项目列表内，就回退到 `list[0].id` 并写回持久化。因此：

- **所有曾打开过任务页、且 localStorage 里已有该键的老用户，升级后项目作用域都会被静默重置为“第一个项目”**，原来选中的项目或“全部项目”丢失。
- 如果用户升级后先打开 Report/Plan/Queue，而不是任务页，这些页面会拿 `"\"p1\""` 去请求，顶栏显示“项目已删除”，列表/报表为空或错。
- 即使后续把 JSON 解析补上，`__all__` 仍需单独归一化为空串；当前 `readStored()` 也没有做这一层。

**证据链**：
- 旧值格式由 `session.ts:26` 的 `JSON.stringify` 确定。
- T06334 的视觉夹具在 `scripts/tests/verify-t06334-summary-button.mjs:207` 使用 `localStorage.setItem('tasks.activeProject', ${JSON.stringify(JSON.stringify(PROJECT_ID))})`，正是旧格式；但它在 app 加载后才写入（`:202` 先导航），`activeProject` 的模块快照已经初始化，同窗口写入也不会触发 `storage` 事件，所以页面仍显示“全部项目”。`02-ui-final7-tooltip-geometry.log` 第 4 行同时记录了 body “全部项目” 与 localStorage 原始值 `"\"dcb...\""`，恰好说明**夹具没有覆盖“启动时读取旧值”的真实路径**。
- T06329 SSR 门禁只测 `getActiveProject()` 在无 localStorage 时的初始空串（`verify-t06329-render.tsx:33`），完全没有覆盖旧 JSON 值。

**修复建议**：

```ts
function normalizeStored(raw: string | null): string {
  if (!raw) return '';
  let value = raw;
  try {
    const parsed = JSON.parse(raw);
    if (typeof parsed === 'string') value = parsed;
  } catch {
    /* 新格式本身就是裸串，解析失败按裸串处理 */
  }
  return value === ALL_PROJECTS ? '' : value;
}
```

- `readStored()` 使用 `normalizeStored`。
- `setActiveProject()` 同步把 `ALL_PROJECTS` 归一化为 `''`，避免新写入再产生哨兵。
- 首次读取到旧格式时，可一次性写回规范化值；至少要保证 `getActiveProject()`、`storage` 事件和所有消费页走同一入口。
- 补迁移测试：
  - `JSON.stringify('p1')` → `p1`
  - `JSON.stringify('')` → `''`
  - `JSON.stringify('__all__')` → `''`
  - 裸串 `p1` / 裸串空串仍正确
  - 从旧值读取后，`TasksPage` 不应再触发“回退首个项目”。

**严重度判断**：P0（升级阻断级 UI 回归）。不丢数据库数据，但会让老用户进入错误项目作用域，且跨页表现不一致。

### H-2. T06329：Report 的“全部项目（不限范围）”会被 effect 立刻打回具体项目

**位置**：
- `web/src/pages/ReportPage.tsx:1162-1169`
- `web/src/ui/projectScopePicker.tsx:94-107`（“全部项目（不限范围）”调 `onChange([])`）

```ts
const [globalProject] = useActiveProject();
const lastGlobalProject = useRef(globalProject);
useEffect(() => {
  const mountedWithGlobalScope = globalProject !== '' && projectIds.length === 0;
  if (lastGlobalProject.current === globalProject && !mountedWithGlobalScope) return;
  lastGlobalProject.current = globalProject;
  setProjectIds(globalProject ? [globalProject] : []);
}, [globalProject, projectIds.length, setProjectIds]);
```

**触发**：
1. 顶栏选中项目 P；
2. 报表页默认范围为 `[P]`；
3. 用户打开 `ProjectScopePicker` 点“全部项目（不限范围）” → `onChange([])` → `projectIds` 变为 `[]`；
4. effect 因 `globalProject=P` 且 `projectIds.length=0` 再次执行，`mountedWithGlobalScope=true`，立刻写回 `[P]`。

结果：用户点击“全部项目”看起来无效，无法在不改顶栏的情况下看全量聚合报表。

**次要问题**：如果进入报表页时 session 里已有范围 Q，顶栏为 P，effect 因 `lastGlobalProject.current` 初始就是 P 而不会覆盖 Q，顶栏与报表范围不一致。这属于同一 effect 的“首次同步/用户主动清空”边界没分开。

**修复建议**：
- 用 `initializedRef` 区分首次挂载与后续全局变化，effect 只依赖 `globalProject`，不要依赖 `projectIds.length`：

```ts
const initialized = useRef(false);
useEffect(() => {
  if (!initialized.current) {
    initialized.current = true;
    if (globalProject && projectIds.length === 0) setProjectIds([globalProject]);
    return;
  }
  if (lastGlobalProject.current === globalProject) return;
  lastGlobalProject.current = globalProject;
  setProjectIds(globalProject ? [globalProject] : []);
}, [globalProject]);
```

- 明确产品规则：报表范围是否独立于全局项目。若独立，顶栏切换只作为“首次默认值”，用户清空后不得回写；若强绑定，则“全部项目（不限范围）”应在全局切换器里提供，而不是报表内提供。
- 补测试：选 P → 清空范围 → 等待 effect → 仍为空；顶栏从 P 切到 Q → 范围变 `[Q]`；已有 session Q、顶栏 P 进入页面 → 不静默覆盖 Q（或明确断言产品选择）。

### M-2. T06332：`from/to` 只校验可解析，随后用原始字符串做字典序比较

**位置**：
- `server/src/services/RunQueryService.ts:128-133` `validateTime` 返回原始 `raw`
- `server/src/services/RunQueryService.ts:196-202` 直接拼 `COALESCE(...) >= ? / <= ?`

```ts
if (from) {
  where.push('COALESCE(ar.started_at, ar.created_at) >= ?');
  params.push(from); // 原始字符串
}
if (to) {
  where.push('COALESCE(ar.started_at, ar.created_at) <= ?');
  params.push(to);
}
```

**问题**：
- 数据库写入是 `new Date().toISOString()`（`Z` 结尾）。
- 调用方传 `to=2026-11-25` 时，比较是 `'2026-11-25T10:00:00.000Z' <= '2026-11-25'`，整天的记录都会被排除。
- 传带时区偏移的 ISO 字符串与 `Z` 字符串混比，同样不是时间先后，而是字符顺序。
- `from` 为 date-only 时通常会包含当天（因为 `'2026-11-25T...' > '2026-11-25'`），但这只是巧合，不是正确时间语义。

**触发**：前端 date input 直接传 `YYYY-MM-DD`，或外部调用方按本地日期筛选；中国用户按本地 11-25 筛选会漏掉 11-25 的记录。

**修复建议**：
- 在 `validateTime` 后统一规范化：
  - date-only `from` → 本地/约定时区当天 00:00 的 ISO UTC；
  - date-only `to` → 次日 00:00，SQL 用 `<` 边界；
  - 带偏移的 ISO → 转成 UTC ISO 再比较。
- 校验 `from < to`，否则返回 `invalid_time_range`。
- 更稳的方案是存 epoch 数值列比较，避免字符串比较。
- 补测试：`to=YYYY-MM-DD` 必须包含当天全部记录；`from/to` 跨时区；`from > to` 返回 400。

```ts
}
```

但 list 的 SQL 包含：

```sql
LEFT JOIN tasks t ...
LEFT JOIN projects p ...
(SELECT COUNT(*) FROM agent_run_steps s WHERE s.run_id = ar.id) AS step_count
```

**问题**：迁移/建表部分失败、手工删表、旧库只有 `agent_runs` 时，`assertSchema` 放行，随后 SQL 直接抛错，路由返回 500，而不是 503 `schema_missing`。`RunTraceService` 对 steps 有 `hasTable` 保护，两个服务的 schema 口径不一致。

**触发**：`agent_run_steps` 缺失，或 `tasks/projects` 缺失；`GET /runs`、`GET /runs/:id` 不同失败形态。

**修复建议**：
- `assertSchema` 至少检查 `agent_runs` + `agent_run_steps`；`tasks/projects` 若允许降级，则把 join 改成条件 join，或缺失时返回不带标题/项目名的结果。
- 与 `RunTraceService.hasTable` 统一成一个 schema helper，避免两个服务各自判断。
- 补测试：删 `agent_run_steps` 后 list 返回 503，不是 500；缺 tasks/projects 时行为明确。

### M-5. T06326：Dialog/Drawer/Popover 的模态层缺“只关最上层”、滚动锁和完整焦点环

**位置**：
- `web/src/ui/components/modalLayer.ts`（全文件）
- `web/src/ui/components/Popover.tsx:60-74`
- `web/src/ui/components/Tooltip.tsx:52-59,72`

**问题**：
1. 每个 open 的 Dialog/Drawer 都在 `document` capture 上注册 Esc；嵌套 Dialog 或 Dialog 内 Popover 按一次 Esc 会同时关闭多层，没有模态栈。
2. 没有 body scroll lock，也没有给背景加 `inert`/`aria-hidden`；遮罩打开时背景仍可滚动、读屏仍可访问。
3. `onKeyDown` 只在 panel 内判断 activeElement 是否 first/last；焦点被程序化移到 panel 外时，Tab 可逃逸。
4. `Popover` 关闭时只 `setOpen(false)`，不把焦点还给 trigger；焦点落在被移除的 panel 后会回到 body。
5. `Tooltip` 的 `aria-describedby` 挂在不可聚焦的 wrapper span 上，焦点在子按钮时描述关联无效；controlled `open` 时按 Esc 只改 inner state，不会关闭。

**当前影响级别**：这些原语目前尚未被生产页正式消费（页面主要用 `Button/Badge/Card/Table/Tooltip/IconButton`），所以是**latent** 问题；但不是“不会发生”，而是“正式接入前必须修”。

**修复建议**：
- 增加模态栈 manager：每个实例入栈，Esc 只由栈顶处理；Popover 也走同一栈。
- body scroll lock 使用引用计数，支持嵌套。
- 打开时给背景根节点设 `inert`/`aria-hidden`；关闭恢复。
- 焦点陷阱改为 document 级 keydown，检测 activeElement 不在 panel 内时重定向；关闭时把焦点还给 trigger。
- 原语接入生产页前补嵌套 Dialog、Esc 分层、背景不可滚、Tab 环、焦点回落测试。

### L-2. T06312：审计 `candidates_json` 解析后未校验数组

**位置**：`server/src/services/ModelRoutingService.ts:865-909`、`:539-556`

```ts

  try {
    return JSON.parse(String(r.candidates_json ?? '[]')) as RouteCandidate[];
  } catch { return []; }
})();
// buildDegradeOptions(candidates, ...).filter(...)
```


并补 `null`/对象/非法 JSON 的审计行测试。

另：审计行 `headroom=null` 时 `fitsBudget=true` 是有意口径，但 UI 若用审计数据做“预算可承受”提示，应标注“预算未知”，避免历史行看起来都适配。

### L-5. T06326：Toast `max=1` 时队列不会裁剪，且被淘汰项 timer 未清理

**位置**：`web/src/ui/components/Toast.tsx:92-102`

```ts
setItems((current) => [...current.slice(-(max - 1)), item]);
```

`max=1` 时 `-(1-1)=0`，`slice(0)` 保留全部，列表无限增长；`max<=0` 也异常。被 `slice` 淘汰的旧 toast 的 timer 仍在 `timers` Map 中，到期后空跑 dismiss。

修复：`max <= 1 ? [] : current.slice(-(max-1))`，把 `max` 规范到 ≥1，并在淘汰时 `clearTimeout/delete` 对应 id。

### L-6. T06326：Switch 静默丢弃调用方 `onClick`

接口继承 `ButtonHTMLAttributes` 且只 Omit `type/onChange/value`，调用方可传 `onClick`；渲染时 `{...rest}` 在前、内部 `onClick={toggle}` 在后，调用方 handler 被覆盖。

### L-7. T06326：Tooltip 的可访问描述关联与 controlled Esc 边界

**位置**：`web/src/ui/components/Tooltip.tsx:52-59,72`

- `aria-describedby` 挂在 wrapper span 上，wrapper 通常不可聚焦；焦点在内部按钮时描述关联不生效。应把 `aria-describedby` 透传给可聚焦子元素（cloneElement 或 render prop），或让 wrapper 可聚焦。

- Tabs 的 `.mt-tabs__list` 没有 overflow/scroll 策略，窄屏多 tab 会挤出容器；低优先级，建议加横向滚动与渐隐边缘。

### L-8. T06329：ProjectSwitcher 项目列表未加载时先显示“项目已删除”

### L-9. T06314：`.cv-auto` 的 40px 估算与密度 32/40/48 不完全对齐

**位置**：`web/src/pages/TasksPage.tsx:6077`，全局 `web/src/settings.tsx:263-269`

TasksPage 注入 `.cv-auto { content-visibility:auto; contain-intrinsic-size:auto 40px; }`；全局设置还有 64px 版本。紧凑 32px + 6px 上下 margin ≈44px，40px 偏差小；舒适/宽松下屏外行估算偏差更大，可能出现滚动条跳动或 `scrollIntoView` 偏移。`auto` 会记忆实际尺寸，首次渲染仍有抖动风险。

## 横切一致性、结构与错误处理评价

### 做得好的部分

- T06326 原语普遍使用 `forwardRef`、`displayName`、controlled/uncontrolled 双模式，`aria-*` 与 `data-*` 命名清晰；CSS 变量集中在 `components.css`，页面接入成本低。
- T06332 使用 `RunQueryError` 分类错误码，路由层统一映射；`RunTraceService` 对缺表有保护，`RunLegacyMapper` 用事务 + 失败记录，方向正确。
- T06342 的 minimal 页头保留了读屏 h1，删除了重复面包屑/可见标题，语义上没有直接把 h1 丢掉。
- T06343 把低频项收进 More 的初始动机合理，视觉上首排更干净；问题在“运行态入口也应留在 More 外”，不是收口方向错误。

### 需要收口的结构问题

- **双哨兵表示**：`ALL_PROJECTS='__all__'` 与全局 store 的空串 `''` 同时存在，页面各自做映射（TasksPage `globalProject || ALL_PROJECTS`、Report `projectIds=[]`、Plan `globalProject || session`），边界很容易再出错。建议在 `activeProject.ts` 提供唯一的 `toGlobalProject`/`toPageProject` 转换，页面不要各自解释。
- **`TasksPage` 体量与嵌套 render 函数**：`renderMorePanel`、`renderBeautifyToolbarButton` 都在 7k 行级组件内，运行态/布局状态耦合。至少把 beautify status、project actions、More groups 抽成纯组件，便于测试。
- **`PageHeader` API 语义**：`description`/`breadcrumbs` 在 `minimal` 下被静默忽略，调用方仍继续传，属于“接口接受但行为不实现”的误导；应删参数或文档化。
- **模态层不是单一职责**：`useModalLayer` 同时管焦点、Esc、遮罩点击，但没有 stack/scroll lock；在接入前应拆出 `ModalStackProvider`，否则每个 Dialog 各自注册 document listener 会越来越难维护。
- **T06332 两个服务 schema 口径不一致**：`RunQueryService.assertSchema` 只看 `agent_runs`，`RunTraceService` 有 `hasTable` 分支；同类问题应由一个 `assertRunSchema` 统一。

### 错误处理

- `RunQueryService` 的 `schema_missing`、`invalid_status`、`invalid_legacy_source` 分类清楚，但 `validateTime` 只做 `Date.parse` 可解析性校验，实际 SQL 又用字符串比较，属于“校验口径与执行口径不一致”。
- `RunLegacyMapper` 的 `recordFailure` 会把异常写进映射结果，方向正确；但 UPDATE 不含归属字段，是文档认可的设计，需在 API 契约/文档里明确，否则调用方会误读。
- `ModelRoutingService` 的 `try/catch` 只保护 `JSON.parse`，没有保护“解析结果类型”，异常会漏到路由层；应在边界处把未知数据降级为空数组。
- `T06343` 的错误提示写“请先在工具栏取消”，但取消入口实际在 More 内；提示与 UI 位置不一致，属于错误处理文案失真。
