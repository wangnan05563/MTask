# T03297 批量分类改为分批多次调用

## 背景

词表页「批量智能分类」原先逐条调用 `POST /tasks/classify`：500 条任务就是 500 次模型往返，既慢又容易触发厂商限流。本单在服务端按批切分、一次调用处理一批，前端整批提交后按 id 回填。

## 服务端

### 纯逻辑 `server/src/services/classifyBatch.ts`

- `chunkItems(items, size)`：连续下标切分，不重叠、不遗漏、顺序保持；批大小夹在 1~50（默认 20）。
- `parseBatchReply(raw, count, cats)`：优先按行首序号落位（`序号|分类名|优先级`），模型调序/漏行都不会错配；无序号时仅在行数等于条数时按顺序落位；其余位置为 `null`，交给重试/拆分，绝不猜。
- `matchCategory(name, cats)`：与单条 `classifyCategory` 同口径——精确名优先，其次最长名称包含（避免「开发/开发优化」误配）。
- `classifyItems({items, categories, chat, batchSize, concurrency})`：
  - 每批失败**重试一次**；仍失败且批内多于一条时**对半拆分递归**，直到单条；单条失败如实 `ok:false` 并带原因；
  - 账户级门禁（`402`/`429`/`rate limit`/`quota`/`额度`/`限流`）**不重试不拆分**：立刻置 `gated`，未派发批次与未落位条目统一带同一原因失败，供上层熔断；
  - 并发上限默认 2（可调 1~4）；`calls` 为真实模型调用数，`batches` 为顶层批次数（拆分产生的追加调用只进 `calls`）；
  - 结果按输入下标落位，与输入等长同序。

### 接线

- `AIService.classifyCategoryBatch(input, toolId)`：分类为空时零调用直接返回 `categoryId:null`；否则注入 `chat`，**每次真实调用**都 `recordUsage('classify', …)`。
- 新路由 `POST /api/tasks/classify-batch`：`toolId` 必填；`items` 非空数组、单次 ≤500 条（超出提示分批提交）；每项需含 `id` 与非空 `title`；返回 `{ ok, results, calls, batches, gated, error? }`。

## 前端

`web/src/pages/tasksClassifyBatch.ts` 新增 `batch` 选项：开启后按 200 条一包请求 `/tasks/classify-batch`，按 id 回填；缺条按失败计（`批量结果缺少该条`），`gated` 直接中止并透出原因，连续 ≥3 包失败熔断。词表页 `TasksPage.tsx` 的 `runBatchClassifyModule` 传入 `batch: true`。逐条 `/tasks/classify` 通道原样保留（单条分类与既有熔断门仍走原路径）。

## 验证

- `tsc -p server` / `tsc -p web` 通过；
- `scripts/tests/verify-t03297-batch-classify.mts`：**28 通过 / 0 失败**
  - A 切分 4 项（尾批、不重不漏同序、批大小夹取、非法值不丢数据）；
  - B 解析 5 项（按序号落位、优先级与 NONE、漏行判未知、无序号回退、行数不符不猜）；
  - C 匹配 3 项（精确优先、最长包含、无命中）；
  - D1 45 条/批 20 → 3 次调用、等长同序、不重不漏；
  - D2 大批判恒失败 → 重试后对半拆到 3 条成功，仅永久失败的那 1 条失败且带原因，`calls > batches` 证明拆分确实发生；
  - D3 串行门禁只发 1 次即 `gated`，全部条目带同一原因失败；D3c 并发 2 时最多多 1 个在途请求；
  - D4 漏行重试按待定条目重新编号后补齐；
  - D5 并发不超过 2；
  - E 接线锚点 5 项（路由与 500 条上限、每次调用记用量、前端批量通道与 200 切块、启用开关且保留逐条通道、缺条/门禁处理）。
- 既有 `verify-t02307-classify-breaker.mts`（逐条通道熔断）复跑无回归。
