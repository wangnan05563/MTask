## 2. AI 智能关联流程

1. 点按钮 → `POST /git/ai-link-suggest`（body `{ projectId, toolId }`）。
2. 服务端 `services/gitAiLink.ts`：
   - 候选任务 = 本项目中 `status='done'`、未归档、未搁置、**尚无任何 `task_git_links`** 的任务（默认最多 20 条）；
   - 候选提交 = `queryGitLog` 取该仓库最近提交（默认 100 条），**剔除已被任何任务关联过的 sha**；
   - 提示词要求模型只输出 JSON 数组：`{task 序号, commits 短 SHA, confidence, reason}`，并明确「宁缺勿错」。
3. **服务端二次校验（关键）**：模型输出只是候选，以下一律丢弃——
   - 短 SHA 不在本次取到的提交清单里（含前缀歧义：7 位前缀命中多条）；
   - `confidence < 0.5`；
   - 任务序号越界；
   - 同一条提交被多条任务认领（保留置信度更高者，平手保留先出现的）。
4. 前端弹出建议面板：按任务分组、逐提交复选框（默认全选）、显示置信度与理由；底部「确认关联 N 个提交」随勾选数变化。
5. 确认才逐条调 `POST /tasks/:id/git/links`（`source=manual`）；**取消不产生任何写入**。完成后刷新徽标与列表。

降级口径与 §4.2 一致：未绑定工作空间 / 非仓库 → `ok:false` + `kind` + 人话消息（前端 toast）；缺 `projectId`/`toolId` 才 4xx。
AI 不可用时按钮 `title` 走 `aiBlockedTitle(readiness, …)`，保留「为什么不可用」。
