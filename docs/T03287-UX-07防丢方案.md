# T03287 UX-07 PRD 防丢方案（M3 3.3）

> 决策对象：PRD 相关链路的防丢策略（dirty 确认 / 会话草稿）
> 产品约束（PRD UX-07）：两者「至少满足一种，不得两种都缺」
> 结论：**两种都采用**——编辑态用会话草稿兜底，覆盖/离开等破坏性动作走 dirty 确认；按界面分别落位

## 1. 逐场景落位

| 界面 / 动作 | 采用哪种 | 实现证据 |
|---|---|---|
| PRD 管理面板：Markdown 编辑中切面板/菜单/切文档 | 会话草稿 | `web/src/pages/PrdPanel.tsx` T03158：未保存编辑实时写 `sessionStorage`（按文档 id 分键），重新进入提示「已恢复上次未保存的草稿」；同文件 T00783-L4 修掉「点同一行重新拉详情覆盖 editMd」的静默丢弃 |
| PRD 生成面板：结论/自定义内容在生成与录入之间切换 | 会话草稿 | `PrdGenPanel.tsx` 以 `PRD_CONCL_KEY` / `PRD_CUSTOM_KEY` 持久化，切走再回来内容仍在 |
| PRD 生成面板：确认版命中同源文档、即将覆盖 | dirty 确认 | `PrdGenPanel.tsx` T03159：`askConfirm` 展示「既有 filename（现有 N 字符）/ 本次 M 字符」；取消则明确提示「既有 PRD 未改动」并直接返回，不写库 |
| PRD 导入面板：解析结果、需求清单、WBS 计划草稿 | 会话草稿 | `PrdImportPanel.tsx` 以 `PERSIST_KEYS.reqs/plans/sources` 落 sessionStorage；解析在卸载期间完成也能在挂载时取回；反向覆盖（文件名/正文命中存量文档）另有告警 |
| PRD 导入面板：预览确认导入 | dirty 确认 | 预览先行、勾选门槛后才允许导入（T03185 UX-07②③），未勾选不进入写库 |
| 启动会 PPT：大纲行编辑 | 会话草稿 | `KickoffPptPanel.tsx` `OUTLINE_SESSION_KEY` 持久化行数据 |
| 任务详情抽屉：编辑中父级刷新 | 不覆盖未保存草稿 | `TaskDetailDrawer.tsx`：编辑态时展示镜像不跟随 props，避免吞掉正在输入的内容 |

## 2. 为什么两种都要

- 只用 dirty 确认：用户切页/切菜单时根本没有「确认框」时机（组件已卸载），内容仍会丢
- 只用会话草稿：覆盖既有 PRD 这类**不可恢复**动作没有二次确认，用户感知不到旧内容已被替换
- 因此：可逆场景用草稿兜底，不可逆场景叠加确认；两者不重叠使用，避免「既弹确认又留草稿」造成误判

## 3. 边界与残余风险

- 草稿只保会话生命周期（`sessionStorage`）：关窗/换会话即清，符合「会话草稿」定义，不做跨会话持久化
- 存储写入失败（配额/隐私模式）不阻断编辑，只在恢复时缺内容；等价于「无草稿」而非报错
- 覆盖确认只覆盖「同源命中」路径；新建条目仍走原「加序号上新」逻辑，不弹确认
