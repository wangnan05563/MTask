# T03282 代码问答安全边界（PRD 2.4 工作空间只读）

日期：2026-10-29 ｜ 关联需求：AI-201（工作空间只读代码问答）｜ 验收口径：§2.4「无写文件或执行命令路径」+ AI-201 ⑤「安全测试证明只读边界」

## 一、结论

工作空间问答链路的只读边界**当前实现成立**，本轮不改产品代码，只补一支行为级安全门并留下快照级只读证明。

实现侧边界（`server/src/services/WorkspaceService.ts`）：

| 控制点 | 实现事实 |
| --- | --- |
| 未绑定工作空间 | `getProjectWorkspace` 直接抛 `该项目未配置工作空间（项目管理 → 选择工作空间）`，不降级成全盘检索 |
| 路径越界 | `safeResolve` 只接受解析后仍落在工作空间根内的相对路径，越界抛 `路径越界：目标不在工作空间内` |
| 忽略列表 | `.env` 等敏感文件名在读取前拦截，且检索侧不产出其内容 |
| 检索范围 | 忽略 `node_modules`、`.git` 等目录，不进索引 |
| 写/执行通道 | 路由层只有 `GET /workspace/search`、`GET /workspace/file`、`GET /workspace/symbols`、`POST /workspace/symbols/refresh`；**不存在**写文件或执行命令的接口 |

## 四、边界与未覆盖项

- 只证明「工具层无可达写/执行路径」，**不**覆盖 AI 回答内容本身的正确性与幻觉（属 AI-201⑥ 统计评估范畴）。
- 路径穿越只覆盖 4 种常见写法；不覆盖 NTFS 8.3 短名、符号链接/junction 指向根外的情形（当前 `safeResolve` 用 `path.resolve` 前缀比较，符号链接未做 `realpath` 校验——如需收紧应另立单）。
- 忽略列表按文件名/目录字面匹配，不是全量敏感信息识别（例如自定义命名的密钥文件不在拦截内）。
- 越界拒绝依赖工作空间根已存在且为目录；工作空间被删除后的行为未在本次断言内。
- 门脚本留在 `scripts/tests/` 未入库（裁定 A）。
