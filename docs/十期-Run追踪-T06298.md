# T06298 · Run 追踪 UI（REQ-036 / PRD §B6）

## 1. 任务与范围

- 任务：`T06298` `[PRD] Run 追踪UI`，项目 `MTask十期`。
- 原始任务描述引用 `REQ-006`；任务 `req_ids` 实际指向 `4184e4ff-e90d-4410-bc9f-29fb700bfe47`（`REQ-036`「Run 数据模型」，PRD §B6）。本单按标题与 §B6 执行，并与 T06293/T06297 的编号错位一并记录。
- 本单只做「Run 详情页渲染与只读追踪」，不实现失败点重跑、断点恢复、审批决策、队列执行或 Run 列表。
- 因 `T06332`（Run/RunStep 查询与旧数据映射 API）仍是 `todo`，本单在 UI 数据契约内补了**单 Run 只读端点**；完整列表、旧 `queue_job`/`ai_usage` 回填仍归 T06332，不能以本单替代。

## 2. 数据契约

新增 `GET /api/runs/:id`（`server/src/routes/index.ts`）：

- `id` 支持：
  - 原生 `agent_runs.id`；
  - `legacy:exec_session:<exec_sessions.id>`；
  - 直接传 `exec_sessions.id`。
- 读取顺序：
  1. `agent_runs` 表存在时，先按 Run ID 查；
  2. 再按 `legacy_source='exec_session'` + `legacy_ref` 查原生映射；
  3. 没有原生映射时，回退 `exec_sessions` 只读兼容视图；
  4. 找不到返回 `404 {error:'run_not_found'}`。
- 原生分支：`RunTraceService` 读取 `agent_runs` + `agent_run_steps`，按 `seq` 排序，返回头部字段、步骤、风险、审批、成本拆分。
- 兼容分支：
  - 稳定 ID `legacy:exec_session:<id>`；不落库、不改旧表；
  - 3 个只读合成步骤（会话启动 / 阶段观察 / 状态决策）；
  - `cost=0`、`tokens=0`，并用 `warnings` 明示成本与 Token 未记录；
  - 不伪造成本、Prompt、工具调用或审批。
- 成本归因：按步骤类型汇总；`agent_runs.cost > 步骤成本合计` 时输出「未归因差额」；步骤合计高于 Run 成本时给 warning（测试覆盖）。

## 3. UI

新增 `web/src/pages/RunDetailPage.tsx` + `runTrace.css`：

- 入口：执行会话卡片的「追踪」按钮（`data-lck="trace-run-btn"`），整页切到 Run 详情，返回恢复原看板；不新增一级导航。
- 头部：状态、来源、任务编号/标题、项目、模型、Prompt 版本、耗时、Token、成本、审批状态；任务编号可直达任务详情。
- 时间线：每步显示序号、类型、状态、风险、耗时、成本；失败步骤默认展开，其余点击展开输入/输出/更新时间。
- 成本归因：总成本、Token、按步骤类型占比；旧会话显示「未记录成本」而非 0 元误导。
- 审批卡：已批准/等待/拒绝/无审批；原生 Run 从 `approval` 步骤推导。
- 运行中（`queued/running/awaiting_approval`）每 3 秒静默刷新，展开状态保留；页面隐藏时暂停。
- 底部固定操作：`从失败步骤重跑` 明确禁用（本单不实现 B8）；`导出产物` 导出产物步骤 JSON；`查看审计` 禁用并注明后续接入。
- 响应式：1440/1280/760 截图验收；1280 以下头部改为上下布局，760 以下单列。

## 5. 边界与后续

- 生产库当前 `agent_runs` 表由 T06293 建表脚本管理；没有真实写入方时，UI 只能显示旧会话兼容视图。原生 Run 的真实步骤/成本需执行器接入或 T06332 映射回填后才有数据。
- 兼容视图的步骤是从会话状态合成，不是原始 RunStep；`cost/tokens` 不伪造，页面明确提示。
- 本单的 `GET /runs/:id` 只服务详情页，不是完整 Run API；Run 列表、分页、按项目/状态筛选、`queue_job`/`ai_usage` 旧记录映射仍由 T06332 完成。
- 断点重跑、审计查询、产物文件级导出未实现；底部按钮显式禁用，避免“看起来能用”。
- 浏览器验收使用测试库副本和夹具 Run，不代表生产已有真实 Run 数据。
