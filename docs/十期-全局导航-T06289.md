# 十期 · T06289 全局导航

## 一、范围与需求

- 任务：`T06289`「重构全局导航」。
- 任务卡标签写 `REQ-011`，但任务 `req_ids` 实际指向 `REQ-041`（`4f60c618-2a35-469a-9426-2b5363c26482`）§C1「导航与页面壳」；本单按实际需求落地。
- 本单目标：把旧顶部 9 个平铺页签收敛为 5 个一级入口，左侧垂直导航 + 顶栏二级页签切换器，支持折叠与快捷键；不包含移动端。

## 二、交付内容

1. **一级导航单源**：新增 `web/src/ui/nav/primaryNavGroups.ts`，导出 `NAV_GROUPS`、`NavGroup`、`navGroupForTab`。
   - 首页 → `dashboard`（默认）
   - 任务 → `tasks`
   - 项目 → `plan` / `req` / `report`（默认 `plan`）
   - AI 控制台 → `queue` / `exec-sessions` / `prompts` / `aitools`（默认 `queue`）
   - 设置 → `settings`

2. **左侧导航组件**：新增 `web/src/ui/nav/PrimaryNav.tsx`。
   - 5 个 `.mt-nav-item` 一级入口；当前入口展开二级 `.mt-nav-subitem`。
   - 当前一级入口展开二级 `.mt-nav-subitem`；一级默认页或二级页签各自带 `aria-current="page"`。
   - 每个一级入口 `aria-keyshortcuts="1"`～`"5"`，对应全局数字键直达。
   - 折叠按钮维护 `aria-expanded` 与 `aria-controls="mt-primary-nav-groups"`。

3. **导航样式**：新增 `web/src/ui/nav/primaryNav.css`。
   - 展开 240px、折叠 64px；顶栏 56px；侧栏与顶栏均 `position: sticky`。
   - 当前项使用 `--accent-soft` + 左侧 `--accent` 条；二级页签同样复用主题变量。
   - `960px` 以下顶栏收窄内边距，`1180px` 以下隐藏一级入口标题，二级页签横向可滚动。
   - 不含硬编码色值。

4. **接入应用壳**：修改 `web/src/App.tsx`、`web/src/main.tsx`。
   - 根容器取消旧 `1600px` 上限与外层 16px 留白，改为 `PrimaryNav + main` 两栏。
   - `main` 内新增 sticky 顶栏 `.mt-top-switcher`：当前一级入口名 + 二级页签；通知铃铛、后端连接状态、使用向导收进顶栏右侧。
   - 页面区域 `padding: 24px 24px 40px`，内容宽度继续由 T06288 `PageShell` 收口到 1440px。
   - 默认页签改为 `dashboard`；数字快捷键从 1～9 收敛为 1～5，对应各分组默认页。
   - 折叠状态持久化键 `mtask.nav.collapsed`（`'1'` 为折叠）。

5. **页面路由表**：修改 `web/src/ui/tabs.ts`。
   - `Tab` 新增 `dashboard`；`report` 显示名改为「报表」。
   - 保留全部 10 个页面键，旧深链、命令面板页面直达仍可逐页到达。

6. **配套门禁与文档**：新增 `scripts/verify-t06289-nav.mjs`、`scripts/verify-t06289-render.tsx` 及本文档。

- 首页默认：侧栏 240px、5 个一级入口、顶栏仅「首页」、无二级页签。
- 项目入口：二级页签 计划/需求/报表；切到「需求」后侧栏与顶栏同步高亮。

- 顶栏高度 56px、`position: sticky`；1280/1920 均无横向溢出。
- 控制台无 JS 异常。

环境说明：本机共享 `node_modules` 在并发任务清理中反复缺包（`typescript`/`esbuild`/`react` 等包目录不完整），本次生产构建改用与 `package-lock.json` 同版本的独立干净依赖目录（`C:\pyfix_tmp\mtask-webdeps`，Vite 6.4.6、TypeScript 5.9.3），挂接到 `web/node_modules` 后执行；未改动仓库内 `package.json`/`package-lock.json`。这是本机依赖环境问题，不是本单代码缺陷。
