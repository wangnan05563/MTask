# 十期 · 导入向导（T06304 / REQ-010 / PRD §B2）

## 结论

在既有 CSV/JSON 导入（T03267）基础上补齐 PRD §B2 的三项硬要求：**来源 + 外部 ID 去重**、**确认导入单事务失败回滚**、**重复项跳过并报告**。既有「文件选择 → 字段映射 → 预览 → 确认」向导骨架保留，新增外部 ID 字段映射与预览列；Trello/Jira/GitHub 仍走各自导出文件，不做平台 API 直连。

## 实现

### 去重键（新增）

- 表 `task_import_keys(id, project_id, source, external_id, task_id, created_at)`，唯一索引 `(project_id, source, external_id)`（`server/src/db/importKeySchema.ts`）。
- `ImportKeyService.ts`：来源归一（`github/jira/trello/json/generic`，CSV 的 `generic` 与 `json` 分开命名空间）、外部 ID 归一（trim + 200 字符上限）、`listImportedKeys`、`isImported`、`markImported`（`INSERT OR IGNORE` 幂等）。
- 初始化挂到 `schema.ts` 的 `ensureSchema()`。

### CSV 导入

- 表头别名新增 `externalId`：`外部 ID / 外部id / 外部编号 / Issue key / issuekey / key / id / 编号`；Jira 导出列 `Issue key` 自动映射。
- 预览：有外部 ID 时按「来源 + 外部 ID」判重，命中返回 `来源+外部 ID 重复：jira:JIRA-101`；无外部 ID 才回退标题判重；预览行回传 `externalId`。
- 确认：接收 `source`，整批 `db.transaction`；逐条判重，重复计入 `skipped`；任一异常抛出即整体回滚，返回 `{ok,count,skipped}`。

### JSON / Trello / GitHub

- `extractJsonImportItems` 增加外部 ID 提取：`id / key / issueKey / issue_key / number / shortId`。
- 来源推断：`lists[].cards` → `trello`；`fields/issueKey` → `jira`；`html_url/number` → `github`；其余 `json`。
- 预览与确认同样按「来源 + 外部 ID」判重，确认走单事务，返回 `skipped`。

### 前端（TasksPage）

- 字段映射新增「外部 ID」下拉（可选，未映射则不参与键去重）。
- 预览表新增「外部 ID」列；JSON 与 Trello 共用同一预览块。
- 确认导入传 `source`；成功回执显示「N 条重复已跳过」。

## 边界（未做 / 不在本单）

- **平台 API 直连未做**：Jira 走 CSV 导出、Trello 走 JSON 导出、GitHub 走 CSV/JSON 导出；PRD 的「Trello/Jira/GitHub 导入」按导出文件口径满足，不含 OAuth/增量同步。
- **1k 行流式进度未做**：当前为一次性预览 + 确认，无进度条/分片续传；PRD §B2 的「1k 行有进度」仅以请求与渲染可用性覆盖，未做 1k 行实测。
- 未做 dry-run 独立模式：预览本身即只读 dry-run，确认才写库。
- 未改既有导入回执/失败回执结构，仅在成功提示追加跳过数。
