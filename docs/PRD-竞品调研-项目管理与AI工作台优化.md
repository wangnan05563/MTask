## 2. 背景与目标

### 2.1 业务背景

1. **MTask 的定位是「桌面端 AI 任务开发管理工具」**，不是代码托管平台。本 PRD 的竞品对标因此做**能力映射而非功能照搬**：竞品「项目管理」对标 MTask 的任务/计划/里程碑/需求矩阵/测试用例/估算体系；竞品「AI 工作台」对标 MTask 的 AI 能力卡片 + 提示词库 + 模型管理 + AI 任务闭环。
2. **行业拐点已至**：2026 年五家竞品全部把「AI 队友/Agent」做进了项目管理主链路——GitHub 的 coding agent 可直接被 assign 到 issue 并在看板上呈现 queued/working/in review/done 状态（agent sessions GA 2026-03）；Gitee 上线四位 AI 队友（PMO 助手做周期报告与 Issue 治理，2026-08-04 企业版正式开放）；Azure DevOps 以 MCP Server 让 AI 助手读取工作项/构建/测试计划。「AI 是团队成员」从概念变成出货功能，管理工具的交互范式正在重写。
3. **MTask 的既有优势必须守住并放大**：本地优先（数据不出本机，除 AI 调用）、「任务→MCP 派发→AI 处理→结果回传→通知」闭环（§3.2 L1）、需求矩阵↔计划↔待办↔用例↔估算全链路关联（L2）、提示词仓库与内置技能（L3）。这三项是五家竞品都没有的组合。

### 2.2 本次优化目标（可量化）

| 编号 | 指标 | 基线（现状） | 目标 | 口径 |
|---|---|---|---|---|

## 4. 项目管理模块需求

> 格式：编号 / 标题 / 描述 / 用户故事 / 验收标准（可测）/ 优先级（P0=MVP，P1=V1.1，P2=V2.0；依据=用户影响面×实现成本）。

### 4.1 客户体验提升

#### PM-101 看板列设置与超限提示
- **描述**：看板视图增加列级设置（显示任务数、可选隐藏空列）与 WIP 软上限（单列 ≥N 张时列头橙标，N 项目可配，默认 10）；对齐 Azure Kanban WIP limits 与 GitHub 看板分组的可配置性，不做硬阻断（桌面单用户场景无队列压力）。
- **用户故事**：作为同时跟进多个任务的人，我想要在看板上一眼看到哪一列堆积过多，以便及时拆分或转出。
- **验收标准**：① 列头显示实时任务数；② 超限列头出现橙标+标题「超出建议上限 N」；③ 上限值在项目设置可改（1~50），改后即时生效；④ 隐藏空列后刷新仍保持（会话级持久化，对齐 `TasksPage.tsx:321` 范式）。
- **优先级**：P0（影响面：全部看板用户；成本：S——纯前端，复用既有 board 视图与 useSessionState）。

#### PM-102 命令面板搜索语法
- **描述**：Ctrl+F 命令面板（`web/src/pages/CommandPalette.tsx:23`）支持结构化过滤语法 `status:done AND priority:high`（AND/OR/括号），对齐 GitHub advanced search（GA 2026-07）；无语法时按原模糊匹配，不破坏现有行为。
- **用户故事**：作为任务量 500+ 的重度用户，我想要用一行语法精确筛出「未完成且高优先级」，以便不用翻页。
- **验收标准**：① 输入含 `status:/priority:/project:` 键值对时按结构化过滤；② AND/OR/大小写不敏感；③ 语法非法时降级模糊匹配并在面板底部提示「语法无效，已按全文搜索」；④ 匹配延迟 ≤300ms（1000 任务数据集）。
- **优先级**：P0（影响面：全部用户；成本：S——既有搜索管道上加解析层）。

#### PM-103 新项目空态引导
- **描述**：空项目/零资料项目首次进入时，展示「推荐下一步」三步引导卡（导入 PRD → 生成需求矩阵 → 建计划），每步带深链跳转；复用既有 `EmptyState` 组件（`web/src/ui/EmptyState.tsx`）与 kickoff 卡深链范式（T02108）。

#### PM-104 移动端核心链路补齐

#### PM-105 批量操作增强（既有 T00457/T01065 能力为基线）
- **描述**：**评审修订**——系统**已具备**批量操作：多选模式（`web/src/pages/TasksPage.tsx:742 multiSelect`）+ 选中集合（`:746 selectedIds`）+ 5 种批量动作（`:94-96 ACTION_LABEL`：状态/分类/优先级/颜色/归档）+ 10 级撤销栈（`:109 MAX_UNDO_STEPS`，T01065）。原 v1.0 把批量当新增是误判，本条改为**补齐既有能力的三处缺口**：① 跨项目批量（当前选中集合与批量栏在单项目视图内生效，跨项目需从「全部项目」视角或看板全局视角进入）；② **批量导出所选**（导出既有 xlsx/CSV 路径扩展为「仅所选」）；③ 批量结果**逐条回执**（部分失败时列出失败条与原因，而非整体静默）。
- **用户故事**：作为每周整理任务的人，我想要在「全部项目」视角一次选中跨项目的 30 条统一归档并导出一份清单，以免逐个项目重复操作且无法自证改了哪些。
- **验收标准**：① 「全部项目」视图可进入多选并跨项目选中（沿用既有 `selectedIds` 集合，不新建选择状态）；② 「导出所选」按既有导出路径生成（不新增格式）；③ 批量操作部分失败时弹回执（成功 n 条/失败 m 条+失败原因），失败条不静默丢弃；④ 撤销栈行为不变（回归：连续 10 步可逐级回退）；⑤ 批量动作集合零新增（沿用 `:94` 五种），避免与既有能力分叉。
- **优先级**：P0（影响面：重度整理用户；成本：S~M——跨项目视角+导出所选为增量，既有批量零改动）。

### 4.2 功能扩展

#### PM-201 迭代（Sprint）管理
- **描述**：新增「迭代」一等实体（项目下）：起止日期+目标+任务集+完成定义；任务可加入迭代；提供迭代看板与**燃尽图**（按剩余任务数/剩余工期双口径）。这是五家竞品标配而 MTask 唯一缺口（F-3）。**数据模型（评审修订）**：先评估**零新表路径**——迭代作为 `plan_tasks` 的「起止区间 + 成员集合」视图（迭代=区间，计划行带 `deps:child` 或区间归属标记），燃尽按区间内计划行进度折算；仅当零新表路径无法表达「跨项目的任务归属」时才新增 `iterations` + 关联列（DDL 由技术方案裁决，本 PRD 只定义行为）。
- **用户故事**：作为用两周节奏交付的人，我想要把任务纳入迭代并看燃尽图，以便在评审会上用数据回答「这个迭代能否按时完成」。
- **验收标准**：① 可建/改/归档迭代（起止日期、目标文案）；② 任务可加入/移出迭代（单个+批量）；③ 燃尽图按日绘制：剩余任务数线与剩余工期线（工作日口径，复用 `web/src/utils/workday.ts`）；④ 迭代结束自动生成「迭代小结」（完成数/未完成数/逾期清单）并可一键发周报卡；⑤ 一个任务同一时间只属于一个迭代；⑥ **技术方案评审须明确零新表路径是否可行**（若可行则不新增表）。
- **优先级**：P1（影响面：全部项目管理者；成本：M~L——新实体+燃尽计算；MVP 后第一优先）。

#### PM-202 任务级依赖（blocked-by）

- **用户故事**：作为等待他人交付的人，我想要把任务标记为被某任务阻塞，以便对方完成后自动解脱且历史可查。
- **验收标准**：① 任务详情可加/移阻塞关系（同项目内）；② 被阻塞任务在列表/看板显示阻塞徽标；③ 阻塞方转 done 时自动移除该关系并写 task_events（kind=status）；④ 循环阻塞被拒并提示链路；⑤ 计划 deps 解析路径零改动（回归 `scripts/verify-t02042-milestone-deps.mts`）。

#### PM-205 项目洞察页
- **描述**：新增项目级洞察视图：累积流图（CFD，按任务状态按日快照）、任务周期时间分布（创建→done 天数）、逾期趋势（月末未完成数，口径同 G-4 计划行）、吞吐（每周 done 数）；数据源=task_events+tasks 历史。**历史深度约束（评审新增，与 T02170 B1 同源）**：`task_events` 默认仅保留 **90 天**（`server/src/services/EventRetention.ts:23`，可配 `events.retentionDays`，0=不清理），因此**超过 90 天的历史无法从事件表重建**——洞察页的长历史**唯一来源是自建日快照表**（本条已含该表），且页面须显式标注每个图表的实际可回溯窗口；快照缺失区间显示「数据积累中」而非空白图。

- **验收标准**：① 四张图（CFD/周期时间分布/逾期趋势/吞吐）可按项目+时间范围渲染；② **日快照表为长历史唯一来源**，CFD 按快照渲染而非实时扫事件表；③ 每张图标注实际可回溯窗口起点（=最早快照日）；④ 周期时间分布含 P50/P90；⑤ 全部图表可导出 PNG（复用导出闸）；⑥ 空数据时显示「数据积累中」而非空图。
- **优先级**：P1（影响面：项目管理者；成本：L——需快照表与聚合；依赖 G-4 指标前置）。

#### PM-401 项目级 Webhook
- **描述**：项目可配置 Webhook URL，订阅事件（任务创建/状态变更/计划变更/逾期），HTTPS only、HMAC-SHA256 签名、失败重试 3 次指数退避、投递日志可查；对齐五家标配（F-8）。**不含** inbound webhook（外部写 MTask），保持「外部只读、写入必经 API Token+MCP」的安全边界。
- **用户故事**：作为想把任务变更同步到自建看板的人，我想要配个 Webhook 让变更主动推出去，以免轮询。

## 5. AI 工作台模块需求

> AI 工作台定义：ReportPage 能力卡片（现状 7 张+已批准 2 张：T02170 总结 PPT、T02169 评审讲稿）+ 控制台并行任务（AI 对话/问答）+ 提示词仓库 + 模型管理 + AI 任务闭环（现状锚点 #8/#9/#10）。

### 5.1 客户体验提升

#### AI-101 生成溯源面板
- **描述**：每张 AI 卡输出区增加「用了哪些数据」溯源面板：数据源（表/端点）、条数、时间窗、截断标记；对齐 kickoff 卡页脚溯源（T02170 FR-5.13）并推广到全部卡片。用户可展开核对，做到「AI 说的每个数字都能回到系统内视图」。
- **用户故事**：作为要向上汇报的人，我想要点开报告就看到它引用了哪些数据和截止时间，以免被问住。
- **验收标准**：① 每张卡生成完成后展示溯源面板（数据源清单+条数+时间窗）；② 面板可折叠，默认展开；③ 数据截断/降级（如 T02170 S9 事件覆盖率）在面板中以 ⚠ 明示；④ 导出稿文末附同款溯源段（与 PRD 页脚口径一致）。
- **优先级**：P0（影响面：全部卡片用户；成本：S——采集层已带元数据）。

#### AI-102 生成前成本预估
- **描述**：发起生成前面板显示「预估调用次数/字符量/耗时区间」，依据=数据规模×模板系数（T02169 FR-7.1 已定义此机制，本条将其推广为全部卡统一行为）；用户确认后才发起（沿用配额纪律）。
- **用户故事**：作为自付 API 费用的人，我想要在点生成前知道这次大概花多少，以免月底账单惊吓。
- **验收标准**：① 预检完成后展示预估（调用次数/字符/耗时区间三项）；② 实际消耗与预估偏差 >50% 时在完成后明示；③ 预估不准确本身不阻断生成；④ 用量面板（ai_usage）可回看每次实际值。
- **优先级**：P0（影响面：全部付费模型用户；成本：S）。

#### AI-103 分段幂等与断点续生成
- **描述**：长文生成（讲稿/总结 PPT/周报长文）按段幂等：单段失败仅重试该段，已生成段不丢；刷新/切页后可「从第 n 段继续」（console_jobs 持久化范式已在线，`schema.ts:167-178`）。对齐 T02169 §7.4 可靠性设计并推广。
- **用户故事**：作为生成到一半失败过的人，我想要只重跑失败那段，以免整篇重来还烧一遍配额。
- **验收标准**：① 任一段失败标记失败段且已生成段保留；② 提供「重试失败段」单按钮；③ 刷新页面后任务可恢复并显示进度；④ 中止后再次进入同一任务可继续（不重复已完成段的调用）。
- **优先级**：P1（影响面：长文场景用户；成本：M）。

#### AI-104 提示词模板变量与使用统计
- **描述**：提示词仓库（`schema.ts:122-133`）增强：变量占位符 `{{项目名}}`/`{{周期}}` 渲染、按使用次数排序、一键「用此模板发起控制台任务」；与卡片内置技能分离（模板=用户资产，技能=系统能力）。
- **用户故事**：作为有固定汇报口径的人，我想要把常用提示词存成带变量的模板并一键调用，以免每次复制粘贴改词。
- **验收标准**：① 模板支持 `{{变量}}` 占位，发起时弹出变量填写；② 模板列表按使用次数+置顶排序（**评审修订**：`prompts` 表**无使用计数字段**，`app_settings:160` 为应用级 KV 不适合逐模板计数 → 本期按 `ensureColumn('prompts','usage_count',…)` 幂等补列，落「启动时+1」；不从 console_jobs 派生以免口径不一致）；③ 一键发起走控制台任务既有链路（SSE）；④ 使用次数可归零（管理动作）。
- **优先级**：P0（影响面：提示词库用户；成本：S）。

### 5.2 功能扩展

#### AI-201 工作空间代码问答（编码代理的前置步）
- **描述**：新增「代码问答」卡：基于项目 `workspace_path` 的文件读取（`/api/workspace/file`）与符号索引（`/api/workspace/symbols`）回答代码库问题，答案带 `file:line` 引用；**本期只读不写码**。完整编码代理（Issue→自动实现→提交 PR，对标 Gitee 代码研发助手/GitHub coding agent）涉及写权限与安全面，列 V2.0 观察项（Q-3）。
- **用户故事**：作为接手陌生模块的人，我想要直接问「这个函数被谁调用、改动会影响什么」，以免全文搜半天。
- **验收标准**：① 选中项目后可提问，答案引用 ≥1 个 `file:line`；② 引用可点击跳转工作空间文件视图；③ 无 workspace_path 项目置灰并提示绑定；④ 上下文预算遵循分段装配（不超模型窗口，超限明示截断）；⑤ 全程只读（无写文件/无执行命令路径）。
- **优先级**：P2（影响面：开发者用户；成本：M~L；编码代理另立 Q-3）。

#### AI-202 智能代码审查卡（T02169，进行中）
- **描述**：PRD 已批准（`docs/PRD-代码评审会议讲稿生成.md` v1.1），派生实施单 T02219 待 E-1~E-4 签字后启动。本条仅做排期登记，不重复定义需求。
- **用户故事**：作为要主持评审会的人，我想要把本次增量代码自动变成一份能照着念的评审讲稿，以免会前手工翻 diff 拼材料。
- **验收标准**：以 T02169 PRD §8.2 A-1~A-7 为准（含本次评审新增的 Windows git 编码断言）。
- **优先级**：P1（已批准，实施排期待 T02219 激活）。

#### AI-203 任务分类与优先级建议
- **描述**：新建/编辑任务时 AI 建议分类与优先级（基于标题+描述+同项目历史），用户可一键采纳或忽略；采纳/忽略行为沉淀为后续建议校准。对位 Gitee PMO 助手的 Issue 治理能力（F-2），差异化=本地模型可用+全链路关联。
- **用户故事**：作为懒得逐条归类的人，我想要 AI 直接建议分类和优先级，以免任务堆积成未分类荒原。
- **验收标准**：① 新建任务时给出建议（分类+优先级+理由一句话）；② 采纳率/忽略率可观测（ai_usage 或事件）；③ 可整卡关闭（设置项）；④ 建议不自动落库（必须用户确认）；⑤ 无 AI 配置时该功能静默不可见（不报错）。
- **优先级**：P1（影响面：全部用户；成本：M）。

#### AI-204 逾期预警与周期报告增强
- **描述**：周期报表（日/周/月）增加「预测将逾期」清单（**评审修订口径**）：预测对象是**计划行**（`plan_tasks` 有 `start_date/end_date/duration_days/progress`，可算「时间已过比例 vs 完成进度」），**不含任务行**——`tasks` 表**无任何排期字段**（无 start/duration/due_date，仅 `progress`/`created_at`/`updated_at`，见 §3.2 现状 #1），任务级逾期在现有模型下不可计算，是否新增 `tasks.due_date` 列列 **Q-4**（建议本期不做，与 Q-1 同逻辑：不改 tasks 核心结构）。月报附里程碑达成预测（PM-204 同源算法）。对位 Gitee PMO 助手延期预警（F-2）。
- **用户故事**：作为管理者，我想要在周报里直接看到「按当前进度下周会逾期哪些计划」，以免会后才发现。
- **验收标准**：① 周报/月报含「预测将逾期」节（计划标题+预测日期+依据）；② 预测口径在节内明示（时间已过比例 vs 完成进度，纯几何）；③ 无计划类活动时该节不渲染（不出现空节）；④ 与 PM-204 共用同一推算函数（单源，防两套数字）；⑤ 报告中不出现「任务逾期」字样（任务无排期字段，不得暗示其可预测）。
- **优先级**：P1（影响面：管理者；成本：M；依赖 PM-204 推算函数）。

#### AI-205 阶段性总结汇报 PPT 卡（T02170，已批准）
- **描述**：PRD 已批准并回写计划（`docs/PRD-阶段性项目总结汇报PPT.md` §12），实施任务 T02259~T02268。本条登记排期：S0/S1 先行（周期参数化+保留期一致性）。
- **用户故事**：作为周期性汇报的人，我想要按周期一键生成单/多项目的总结汇报 PPT，以免每周手工誊数据做片子。
- **验收标准**：以 T02170 PRD §8 验收 1~15 为准。
- **优先级**：P1（已批准，按 S0~S8 依赖序推进）。

### 5.3 UI 升级

#### AI-301 卡片分组与检索
- **描述**：卡片增至 9+ 张后按场景分组（规划类/汇报类/质量类），组内排序可按使用频率；顶部加卡片过滤输入。对齐竞品「项目模板库」的组织方式（GitHub templates/Gitee 项目模板）。
- **用户故事**：作为卡片越来越多的用户，我想要按用途分组并快速找到那张，以免上下翻。
- **验收标准**：① 卡片按三组渲染，组标题可见；② 过滤输入按标题/描述模糊匹配，输入后 ≤200ms 出结果；③ 组内默认按使用频率排序（**评审修订**：`ai_usage.kind` 记录的是 AI 通道类型而非卡片标识，**无 card 列**，故本期按 `kind` 粗映射（organize/ask/askJson/askStream/各 generate-stream）归组统计，精度有限但零 schema 变更；精确卡片维度需新增列，列 **Q-6**（建议本期不做））；④ 分组规则配置化（加新卡只需声明组别）。
- **优先级**：P0（影响面：全部用户；成本：S）。

#### AI-302 「上下文+输出」双栏标准组件
- **描述**：把 T02169 设计的「左上下文/右输出」双栏抽象为标准组件（`LectureSplitView` 式）：新卡默认双栏、可切全宽、上下文区支持折叠；统一流式输出渲染（Markdown+代码块，复用 `web/src/ui/Markdown.tsx`）。
- **用户故事**：作为同时要看数据和结果的人，我想要所有 AI 卡都是「左边数据右边结果」的一致布局，以免每张卡重新适应。
- **验收标准**：① 双栏组件单源实现，≥3 张卡接入；② 折叠/展开状态卡片级持久化；③ 流式输出打字顺畅（chunk 合帧，≤16ms/帧）；④ 窄屏自动降级为上下分区（不横向滚动）。
- **优先级**：P1（影响面：全部卡片用户；成本：M）。

#### AI-303 AI 输出排版规范
- **描述**：统一 AI 生成物的排版规范：标题层级上限、表格最小列宽、代码块语言标注、长文自动目录；暗色主题下 AI 输出区域对比度达标（与 PM-301 联动验收）。
- **用户故事**：作为读者，我想要 AI 产出的东西排版一致可读，以免每篇格式都不同。
- **验收标准**：① 全部 AI 输出经同一 Markdown 渲染管线（`ui/Markdown.tsx`）；② 超 3000 字输出自动生成目录锚点；③ 代码块标注语言且暗色下可读；④ 排版规范文档化（组件库示例页）。
- **优先级**：P1（影响面：全部用户；成本：S~M）。

#### AI-304 流式输出可访问性
- **描述**：流式区域 aria-live  polite 播报阶段变更（不逐字播报）、焦点管理（生成中切走再回来焦点位置保持）、减少动画偏好支持（`prefers-reduced-motion`）。
- **用户故事**：作为使用辅助技术的人，我想要知道 AI 生成到哪个阶段了，以免只看到一片静默。
- **验收标准**：① 阶段变更（collecting→outline→section:n）有 aria-live 播报；② 逐字流不播报（防刷屏）；③ `prefers-reduced-motion` 下关闭打字机动画；④ 与 PM-303 验收②共用断言集。
- **优先级**：P2（影响面：辅助技术用户；成本：S）。

### 5.4 功能丰富

#### AI-401 模型路由与用量上限
- **描述**：模型管理（`schema.ts:64-84` ai_tools）增强：按卡片配置默认模型（简单分类用轻量模型、长文用大模型）；本地模型（ollama）优先开关；**用量上限 + 超限告警**（**评审修订**：`ai_usage` 表**只有 `duration_ms`/`content_chars`/`kind`，无 token 与金额字段**，故本期上限用**代理指标**——调用次数与字符量；真实成本核算需新增用量计量，列 **Q-5**（建议本期不做）。对齐竞品模型可选策略（GitLab Duo 模型选择、Gitee 企业版算力）。
- **用户故事**：作为精打细算的人，我想要简单活儿用本地小模型、写稿才用大模型，并以调用次数/字符量为闸，以免全烧在贵模型上。
- **验收标准**：① 每卡可配默认模型（缺省=全局默认）；② 「本地优先」开关开启时离线模型可用则不外发；③ 月度上限可按**调用次数与字符量**设定，达到 80%/100% 两级告警（通知中心+面板）；④ 告警不阻断进行中的生成（仅提示）；⑤ 页面明确标注上限为「用量代理指标，非金额」，不显示虚假金额估算。
- **优先级**：P1（影响面：付费模型用户；成本：M）。

#### AI-402 Agent 会话看板增强
- **描述**：外部平台 AI 会话（exec_sessions，`schema.ts:341-356`）可视化增强：会话状态（active/stale/finished）、进度、阶段、最近心跳一屏总览；停滞会话一键重派（既有 Supervisor 能力前端化）。对位 GitHub agent sessions 看板呈现（F-1）。
- **用户故事**：作为把任务派给外部 AI 的人，我想要看到每个会话活着没、干到哪了，以免派了没人管。
- **验收标准**：① 会话列表含平台/任务/状态/进度/阶段/心跳六列；② 停滞会话（心跳超时）高亮+一键重派；③ 重派走既有 RelayDispatch 通道（不新造）；④ 看板数据 ≤2s 刷新（既有轮询范式）。
- **优先级**：P1（影响面：编排用户；成本：S~M——数据与通道均已存在，主要是前端）。

#### AI-403 内置技能版本化
- **描述**：内置技能（`server/src/skills/`）声明输入输出 schema 与版本号，升级可灰度（新旧并存一版）；技能与提示词模板边界文档化（模板=用户可改，技能=系统受控）。
- **用户故事**：作为依赖内置技能产出的人，我想要技能升级不偷偷改我的输出格式，以免每次升级都要重新调。
- **验收标准**：① 技能元数据含 version+ioSchema；② 升级采用「新版本并存+下版移除」策略并在更新公告明示；③ 卡片可锁定技能版本（高级设置）；④ 版本切换不丢历史产物。
- **优先级**：P2（影响面：技能依赖用户；成本：M）。

#### AI-404 AI 输出多语言
- **描述**：i18n 底座（`web/src/i18n.ts`）之上：AI 输出语言可配（中文/英文/跟随界面语言），周报/讲稿可双语生成（正文一种语言+关键术语双语）。对齐竞品多语言支持（GitHub/GitLab UI 多语言，Gitee 文档五语言）。
- **用户故事**：作为要交英文材料的用户，我想要让 AI 直接出英文版周报，以免自己翻译。
- **验收标准**：① 卡片可配输出语言（默认跟随界面）；② 周报英文版结构/口径与中文版一致（术语表对照）；③ 双语模式术语附英文原文（首次出现）；④ UI 界面文案迁移继续按 T01071 渐进推进（不在本需求范围，仅声明边界）。
- **优先级**：P2（影响面：涉外用户；成本：S~M）。

## 6. 非功能性需求

### 6.1 性能

| 项 | 要求 | 依据 |
|---|---|---|
| 列表性能 | 5000 任务首屏 ≤1s、滚动 ≥50fps | PM-304 |
| 搜索响应 | 结构化搜索 ≤300ms（1000 任务） | PM-102/PM-304 共用基准 |
| AI 生成 | 生成成功率 ≥90%（G-3）；分段首字 ≤8s（P50，T02169 口径） | T02169 §7.2 |
| Webhook 投递 | 事件触发 ≤5s 投递；重试 1/5/30min | PM-401 |
| 导入 | 1000 行 CSV ≤30s | PM-402 |

### 6.2 安全与隐私（护城河原则）

- **本地优先红线**：任何新需求不得把项目数据默认外发；AI 调用仅发用户自配厂商端点（既有口径），代码问答（AI-201）读工作空间文件同样只发自配端点；「本地模型优先」开关（AI-401）为默认推荐配置。
- **Webhook 安全**：仅 HTTPS outbound；HMAC-SHA256 签名；密钥加密存储（复用 ai_tools.api_key_enc 体系）；不做 inbound webhook（写入必经 API Token+MCP）。
- **权限边界不变**：本期不引入多人协作（PM-404 非目标），故不新增角色模型；分享快照必须脱敏（不含描述/处理结果）。
- **命令执行边界**：AI-201 只读；T02169 采集引擎白名单+编码红线已定义，编码代理（Q-3）若立项须先过同等安全评审。

### 6.3 兼容性

- 桌面端：Windows 为主（打包目标仅 win，`package.json:70-72 electron-builder.build.win.target`），Electron 产物兼容 Win10+；macOS/Linux 不做本期承诺（现状即未承诺，保持）。
- 移动端：PM-104 补齐后核心链路可用；甘特只读。
