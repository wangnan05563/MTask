# AI 工具厂商预制与配置记录接口说明（T05784）

本文档说明「模型」页面中厂商预制目录、配置记录表单与后端接口的契约。厂商目录只在后端维护一份，前端通过接口读取，不在前端硬编码厂商清单。

## 1. 数据来源与扩展方式

- 单一数据源：`server/src/config/aiProviderPresets.ts` 的 `AI_PROVIDER_PRESETS`。
- 服务层：`server/src/services/AIProviderService.ts` 只读导出，不读数据库。
- 路由层：`server/src/routes/index.ts` 的 `GET /api/aitools/providers`。
- 前端消费：`web/src/pages/AIToolsPage.tsx` 拉取目录后渲染厂商卡片，点击卡片打开已预填的「新增配置记录」表单。
- 新增厂商：在 `AI_PROVIDER_PRESETS` 追加一条记录即可；前端不需要新增组件或分支。`adapter_type` 必须是 `server/src/adapters/index.ts` 已注册的适配器类型，否则连接测试会失败。

## 2. 接口

### 2.1 获取厂商预制目录

```http
GET /api/aitools/providers
```

响应为数组，字段统一为 snake_case：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 预制唯一标识，例如 `deepseek`、`openrouter` |
| `provider_name` | string | 展示名称，例如 `DeepSeek`、`Anthropic Claude` |
| `provider_type` | string | 厂商业务属性：`国内直连` / `国际直连` / `聚合路由` / `国内聚合` / `本地部署` |
| `adapter_type` | string | 接入协议/适配器，例如 `openai-compatible`、`claude`、`ollama` |
| `base_url` | string | 预填的 Endpoint / Base URL |
| `console_url` | string | 厂商官方控制台/密钥页面 |
| `icon_url` | string | 厂商官方 favicon/CDN 图标地址 |
| `default_model` | string | 预填的默认模型 |
| `docs_url` | string | 厂商官方 API 文档 |
| `description` | string | 预填到「模型配置说明」的简述 |

示例：

```json
[
  {
    "id": "deepseek",
    "provider_name": "DeepSeek",
    "provider_type": "国内直连",
    "adapter_type": "openai-compatible",
    "base_url": "https://api.deepseek.com/v1",
    "console_url": "https://platform.deepseek.com/api_keys",
    "icon_url": "https://www.deepseek.com/favicon.ico",
    "default_model": "deepseek-chat",
    "docs_url": "https://api-docs.deepseek.com/",
    "description": "DeepSeek 官方 API，兼容 OpenAI Chat Completions 协议。"
  }
]
```

### 2.2 配置记录新增/修改中的厂商属性

配置记录接口（既有的 `GET/POST /api/aitools`、`PATCH /api/aitools/:id`）新增可选字段：

- 请求体字段：`providerType`（camelCase）
- 响应/列表字段：`provider_type`（snake_case）

```json
{
  "name": "DeepSeek",
  "type": "openai-compatible",
  "providerType": "国内直连",
  "endpoint": "https://api.deepseek.com/v1",
  "model": "deepseek-chat",
  "consoleUrl": "https://platform.deepseek.com/api_keys",
  "purpose": "develop",
  "enabled": true
}
```

约定：

- `type` 表示**接入协议/适配器**（如 `openai-compatible`、`claude`、`ollama`），`providerType` 表示**厂商业务属性**（如 `国内直连`、`聚合路由`、`本地部署`），两者独立，不再把适配器名当业务分类。
- `providerType` 可留空；老数据升级后默认空字符串，不影响既有配置。
- API Key 仍按既有逻辑加密保存，列表只返回 `hasApiKey` 与掩码，不返回明文。
- 厂商预制的 `base_url`、`default_model` 等只做表单预填，保存后成为普通配置记录，可继续手工修改。

## 4. 页面联动行为

1. 进入「模型」页，先展示后端返回的厂商卡片；卡片显示厂商名、业务属性、Base URL。
2. 点击任一卡片，打开「新增配置记录」弹窗，自动填入：
   - 名称（`provider_name`）
   - 接入协议（`adapter_type`）
   - 厂商属性（`provider_type`）
   - Endpoint / Base URL（`base_url`）
   - 厂商控制台 URL（`console_url`）
   - 默认模型（`default_model`）
   - 模型配置说明（`description`）
3. 表单保留「重置默认」按钮：恢复该厂商预制的上述字段，但不清空人工填写的 API Key、用途、备注。
4. 已保存的配置记录在名称旁显示厂商属性徽标；列表可按接入协议筛选，并保留原有的搜索、排序、归档、连接测试等能力。
5. 新增配置也可从空表单手工录入；厂商预制加载失败时页面提示错误，但不阻断手工新增和既有配置记录的使用。
