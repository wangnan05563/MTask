# 十期 · 风险拦截逻辑（T06299 / REQ-007）

## 1. 范围

在 Run 执行步骤前增加风险门禁：风险分级 → 项目策略裁决 → ask 暂停审批 / block 拦截 → 审计留痕。对应 PRD §B7 与 AC-07：高风险操作被拒绝时，审计日志正确生成。

本单只做后端门禁与审批/审计契约，不做审批流 UI（T06300），不接入自动审批。

## 2. 风险分级

| 等级 | 含义 | 默认可逆示例 |
|---|---|---|
| R0 | 只读 | read / list / search / inspect |
| R1 | 可逆写 | write / create / update / rename |
| R2 | 覆盖、删除、批量 | delete / overwrite / batch >= 2 |
| R3 | 外发、部署、权限、不可逆 | send / publish / deploy / grant / reversible=false |

分类器优先读取引擎显式 `operation`，再叠加文本关键词；未知动作保守按 R1。`reversible=false` 直接升 R3，`batchSize>=2` 升 R2。人工可用 `overrideLevel` 覆盖，但必须同时给 `overrideReason`，否则服务端拒绝；覆盖动作会写一条 `override` 审计。

## 3. 项目策略

默认：

```json
{ "R0": "allow", "R1": "allow", "R2": "ask", "R3": "block" }
```

策略按项目存储，`PUT /api/run-risk/policy/:projectId` 可覆盖单个等级，只接受 `allow/ask/block`；每次变更写 `policy_changed` 审计，保留变更前后值。

## 4. 执行闭环

- `allow`：只写 `allowed` 审计，Run/Step 状态不变。
- `ask`：Run 置 `awaiting_approval`，原 Step 置 `awaiting_approval`，追加一条 `approval` 类型步骤；审批行状态 `pending`，默认 24 小时超时。
- 批准：审批 `approved`，Run 回 `running`，原 Step 回 `running`，审批步骤 `succeeded`，写 `approved` 审计。
- 拒绝：审批 `rejected`，Run `cancelled`（`error_code=approval_rejected`），原 Step `skipped`，审批步骤 `failed`，写 `rejected` 审计。拒绝发生在工具执行前，因此无需回滚业务副作用。
- `block`：Run `cancelled`（`error_code=risk_blocked`），原 Step `skipped`，不建审批，写 `blocked` 审计。
- 超时：Run `failed`（`error_code=approval_timeout`），审批 `expired`，写 `expired` 审计。

## 5. 数据表

`server/src/db/agentRunRiskSchema.ts` 新增三张增量表，启动时在 `ensureAgentRunSchema()` 之后幂等创建：

- `agent_run_risk_policies`：项目级 R0~R3 策略。
- `agent_run_approvals`：审批主体、影响范围、diff/预览、请求者、超时、决策人。
- `agent_run_audit`：append-only 审计；SQLite trigger 对 `UPDATE` / `DELETE` 直接 `RAISE(ABORT)`。

`agent_run_steps.output` 属 T06293 的不可变字段，审批结论写审计，不反写步骤 output，避免触发 `agent_run_steps immutable fields cannot be updated`。

## 6. API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/run-risk/policy/:projectId` | 读策略（含 default/project 来源） |
| PUT | `/api/run-risk/policy/:projectId` | 改策略，`{ levels:{R0..R3}, actor? }` |
| POST | `/api/run-risk/gate` | 步骤门禁，`{ runId, stepId, projectId, signal, actor?, impact?, diff?, preview? }` |
| GET | `/api/run-risk/approvals?status=pending&projectId=&runId=` | 审批列表；pending 查询先收口超时 |
| GET | `/api/run-risk/approvals/:id` | 单审批详情 |
| POST | `/api/run-risk/approvals/:id/decision` | `{ decision:'approved'\|'rejected', actor?, reason? }` |
| GET | `/api/run-risk/audit?projectId=&runId=&eventType=&limit=` | 审计列表；`download=1` 返回 JSON 文件 |

## 8. 边界

- 验证使用内存库契约测试 + 临时数据目录的测试服务，不是生产真实 Run 数据；生产首次启动会由 `initSchema()` 建表，未对生产库执行迁移。
- 门禁必须由真实 Run 引擎在工具执行前调用；目前 MTask 尚无自动执行器接入点，本单交付的是可被接入的服务与 REST 契约。
- 审批 UI 由 T06300 基于本单 `/api/run-risk/approvals` 契约实现，不在本单范围。
- 未做自动审批、自动回滚与审批通知。
