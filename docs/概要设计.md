# MTask 系统概要设计

> 版本：v1.0（基于 2026-09-12 代码现状整理，替代旧版 `技术设计.md` 的「骨架阶段」描述）
> 关联文档：`需求规格说明书.md`、`同类产品分析报告.md`、`docs/详细设计/*`、`docs/MCP接口文档.md`、`docs/PRD-项目计划.md`
> 技术栈一句话：Electron（桌面壳）+ React 18 / Vite / TypeScript（前端）+ Express / TypeScript（后端）+ SQLite（better-sqlite3）

---

## 1. 系统定位

MTask 是面向开发者的 **AI 任务开发管理工具**，解决「基于 txt 的粗糙任务管理」痛点。围绕「项目」维度组织开发任务，提供：

- **任务管理**：项目/任务/分类、优先级、状态、验证标记、置顶、截图附件、父子两级层级、拖拽排序、CSV 批量导入；
- **AI 能力**：AI 梳理（单条/批量+草稿确认回填）、标题美化、描述优化、智能分类、队列分发（同步即时 + 异步提交轮询收口）、AI 控制台并行分析；
- **知识沉淀**：提示词仓库、通用需求仓库、项目计划（甘特/串行瀑布时间线）、周报/月报（Excel/Word/PDF/PPT + AI 洞察）；
- **工程化**：数据迁移（换机 bundle 导入导出）、数据维护（DB 在线 CRUD）、内网穿透（Cloudflare/Cpolar/Tailscale + 访问令牌）、应用自更新（GitHub Releases 检查）、后台日志；
- **多端**：桌面（Electron）+ 移动 Web（随手记/离线草稿）+ 对外 **MCP（Model Context Protocol）** 接口，使外部 AI Agent 可读写同一套数据。

---

## 2. 技术栈

| 层 | 选型 | 用途 / 理由 |
|----|------|------|
| 桌面壳 | **Electron 33** | 成熟稳定；主进程内嵌本地 HTTP 服务并加载前端产物 |
| 前端 | **React 18 + Vite + TypeScript** | 类型安全、HMR；SPA 以 `tab` 状态路由（无 react-router） |
| 后端 | **Express 4 + TypeScript** | 本地 API 服务，UI 与数据层解耦（便于拆 Web/CLI） |
| 数据库 | **SQLite（better-sqlite3）** | 同步 API、零配置、单文件可移植；WAL 模式 |
| AI 接入 | **`@modelcontextprotocol/sdk` + 自研适配器** | OpenAI 兼容 / Claude / Ollama / WorkBuddy 四类协议 |
| 报表 | **exceljs / docx / pptxgenjs / pdfkit** | 在 Worker 线程内合成报表文件（不阻塞主循环） |
| 加密 | **Node `crypto` AES-256-GCM** | API Key / 更新 Token 加密落库（FR3.5） |
| 构建 | **electron-builder（NSIS）** | Windows 安装包；`asar` 打包（better-sqlite3 解包） |

## 3. 总体架构

```
┌──────────────────────────────────────────────────────────────────────┐
│ 桌面壳 Electron 主进程                                                  │
│  · 内嵌启动 server（tsx 直跑 TS 源）                                    │
│  · webRequest 将 file:// 页面的 /api/* 重定向到 http://127.0.0.1:39876   │
│  · 加载 web/dist（生产）或 Vite dev server（开发 MTask_DEV=1）          │
└───────────────┬──────────────────────────────────────────────────────┘
                │  http(s) /api  (CORS 放行, X-Access-Token 可选)
┌───────────────▼──────────────────────────────────────────────────────┐
│ 表现层（web/src）                                                       │
│  桌面 SPA（App → Shell → 8 个 Tab 页面）  ·  移动 Web（mobile/*）        │
│  api/client（fetch 封装）· api/sse（SSE）· stores/ui 通用件            │
└───────────────┬──────────────────────────────────────────────────────┘
                │ REST（/api）+ SSE（/api/events）+ MCP（/api/mcp）
┌───────────────▼──────────────────────────────────────────────────────┐
│ 服务/API 层（server/src）                                               │
│  routes/*（HTTP 边界）  ·  services/*（业务）  ·  adapters/*（AI 协议）   │
│  mcp/*（MCP 暴露）  ·  tunnel/*（内网穿透）  ·  util/*（加密/缓存）       │
│  后台：QueueService 5s 轮询器 · ReportService Worker 线程池 · SSE 推送   │
└───────────────┬──────────────────────────────────────────────────────┘
                │  getDb() 单例
┌───────────────▼──────────────────────────────────────────────────────┐
│ 数据层（SQLite，server/src/data/mtask.db，WAL）                         │
│  17 张业务表 + 索引；密钥列 api_key_enc 加密；app_settings KV           │
└──────────────────────────────────────────────────────────────────────┘
```

**进程模型**：单个后端 Node 进程（监听 127.0.0.1，开发版端口 `39876`、打包版 `39877`）常驻于 Electron 进程内；UI 在渲染进程；**报表合成**在独立 Worker 线程（单 Worker 串行队列，避免 CPU 竞争）。

## 5. 进程与部署

- **端口**：`MTask_PORT`（默认 `39876`）；Electron 打包版监听 `39877`，并将前端 `file://` 请求重定向到本地服务。
- **Electron 启动**：主进程 `electron/main.js` 内嵌启动 server（tsx 直跑 TS 源），`webRequest` 把 `/api/*` 重定向到 `http://127.0.0.1:39876`，前端零改动。
- **静态伺服**：server 同时 `express.static(web/dist)` 并兜底 SPA，使隧道 URL / 浏览器可直接打开 Web 界面。
- **后台任务**：① `QueueService.pollPending` 每 5s 将异步已受理 Job 收口；② `ReportService` 经 `report-worker` 串行合成报表；③ `ChangeBus` → SSE `/api/events` 推送 `{kind}` 变更。
- **构建**：`npm run build:server` + `npm run build:web` → `electron-builder --win`（NSIS，可选安装目录，桌面快捷方式）。
- **环境变量**：`MTask_PORT`、`MTask_DATA_DIR`（默认 `server/data`）、`MTask_MASTER_KEY`（密钥主密钥，生产必配）、`MTask_DEV`（开发加载 Vite）。

## 6. 数据存储设计

SQLite 共 **17 张业务表**（`db/schema.ts` 幂等建表 + 迁移兜底 + 种子）：

| 表 | 关键列 | 职责 |
|----|--------|------|
| `projects` | id, name, description, sort_weight | 项目容器（种子 `sys-inbox` 收件箱，禁止删） |
| `tasks` | id, **task_no**(UNIQUE T+5位), project_id(FK), title, description, priority, status, verified, archived, ai_summary, pinned, category_id, **parent_id**(两级), user_sort, handle_result | 任务；含编号/层级/手动排序/处理结果 |
| `task_categories` | id, name, sort_weight | 任务分类 |
| `task_images` | id, task_id(FK), mime_type, data(BLOB) | 任务截图（≤8MB，随任务级联删） |
| `ai_tools` | id, name, type, purpose, endpoint, **api_key_enc**, model, is_default_organize/develop, console_url, pinned, sort_weight | AI 工具配置（密钥加密） |
| `queues` | id, name, date, status(draft/running/finished/failed) | 发送队列 |
| `queue_jobs` | id, queue_id, task_id, tool_id, order_index, status(queued/sending/success/failed/timeout), request_payload, response_payload, error, ticket, submitted_at | 队列任务（异步回执 ticket） |
| `prompt_categories` | id, name, description, sort_weight, builtin | 提示词分类 |
| `prompts` | id, category_id(FK), title, content, pinned | 提示词 |
| `req_categories` | id, name, sort_weight | 通用需求分类 |
| `req_entries` | id, category_id(FK), title, content, pinned, fingerprint(sha256 查重) | 通用需求条目 |
| `app_settings` | key(PK), value | KV（默认记事项目等） |
| `console_jobs` | id, title, prompt, category, period, status(busy/done/error), answer, error | AI 控制台并行任务 |
| `plan_tasks` | id, project_id(FK), title, description, start_date, end_date, duration_days, progress, status(todo/doing/done/blocked), assignee, sort_order, linked_task_id, archived | 项目计划（串行瀑布） |
| `holidays` | date(PK), name | 节假日（工作日排除项） |
| `ai_usage` | id, tool_id, tool_name, model, kind, ok, duration_ms, content_chars, error | AI 调用用量 |

**关键约束**：`tasks.parent_id` 仅两级（禁止三级链）；`task_no` 存量补发；`queue_jobs` 外键 CASCADE；所有写操作经 `db.transaction(...)`；`busy_timeout=5000`。

## 7. 关键流程

1. **AI 任务分发（队列）**：`POST /queues/:id/submit` → `QueueService.submitAll` → `AIService.buildSubmitter`（适配器 `submit` 或回退 `send`）→ Job 落 `sending`+`ticket`；主进程 **每 5s** `pollPending(buildPoller())` → `adapter.poll(ticket)` → 收口写回；同步工具走 `POST /queues/:id/send` 直接 `success`。成功后置待办 done（受 `AppSettings.queue.autoCompleteTask` 开关），并触发计划联动。
2. **计划串行瀑布重排**：计划增删改 / 节假日变更 → 事务内 `rescheduleFrom`：后续每行 `start = 前置 end 的下一工作日`（跳过周末+节假日），`end_date` 冗余存储；计划状态变更同步关联待办（`linked_task_id`）。
3. **AI 周报**：`POST /report/ai-generate`（或 SSE `/ai-generate-stream`）→ `gatherReportData`（真实周期数据）→ `AIService.ask/askStream`（注入版式 SKILL）→ 洞察 → `report-worker` 串行合成 xlsx/docx/pdf/pptx → 落临时文件返回 `token` → 前端 `/report/ai-download` **读即删**。
4. **数据迁移**：`SettingsService.exportBundle/importBundle`（overwrite/keep/merge，API Key 明文导出后按本机主密钥重加密）支持换机；MCP `mtask_export_data/mtask_import_data` 同能力。
5. **内网穿透**：`tunnel-service` 编排 Cloudflare/Cpolar/Tailscale；一旦配置 `accessToken`，**除 `/tunnel/*` 与 `/health` 外所有 `/api` 数据接口须携带 `X-Access-Token`**。
6. **MCP 暴露**：`createMCPServer` 复用现有 Service（无第二套实现），使外部 Agent 以工具形式读写同一数据（含 `taskNo` 定位、查重、计划镜像）。

## 8. 接口总览

- **REST（routes/index.ts）**：项目/任务/分类/AI 工具/队列/梳理/报表/提示词/通用需求/归档/设置/更新/控制台/日志/数据维护/计划/隧道，约 90+ 端点（详见 `docs/详细设计/B11-路由与REST接口.md`）。
- **MCP（/api/mcp，Streamable HTTP，JSON-RPC 2.0）**：**21 个工具**（项目/任务/计划/提示词/报表/导入导出），详见 `docs/MCP接口文档.md` 与 `docs/详细设计/B12-MCP服务.md`。
- **SSE**：`GET /api/events` 推送 `{kind:'tasks'|'plans'|'queue'}` 变更；`POST /report/ai-generate-stream` 推送 `stage/chunk/done/error`。

## 9. 安全设计

- **密钥加密**：`util/crypto.ts` AES-256-GCM，主密钥来自 `MTask_MASTER_KEY` 或本机指纹派生；`ai_tools.api_key_enc` 密文落库，界面仅脱敏显示，明文按需解密。
- **公网保护**：配置 `accessToken` 后，所有 `/api` 数据接口要求 `X-Access-Token`；EventSource 经 `?token=` 携带；`/tunnel/*` 与 `/health` 放行（避免锁死）。
- **防注入**：`DbAdminService` / `report-worker` 表名列名 `^[\w]+$` 正则校验；模板上传安全字符校验 + 防路径穿越；报表 token 用 UUID 正则防任意路径读。
- **删除保护**：非归档任务不可删；归档删除不可恢复（操作前确认）。

## 10. 横切关注点

- **SSE 变更总线（ChangeBus）**：各 service 写后 `notifyChange`，前端 `openChangeStream` 自动刷新，替代纯轮询。
- **TTL 缓存（util/ttl-cache）**：读多写少列表 5s TTL（projects/prompt-categories/req-categories/queues/report-templates/ai-tools models 5min），写端点主动 `cacheClear`。
- **慢请求日志**：仅记录 ≥100ms 请求（含状态码与耗时），不打印密钥字段。
- **日志环形缓冲（LogService）**：劫持 `console.*`，上限 2000 条，`GET /logs?since=` 增量拉取。
- **事务化**：全部写操作经 `db.transaction`；迁移 bundle、计划批量、队列发送均单事务回滚。
