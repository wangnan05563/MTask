## 4. 复审中确认的一致性要点

1. **状态机闭环**：`building → draft → published(is_active=1) → stale(仍 active) → archived`；发布只接受 `draft`；编辑只接受 `draft`；读取只认 `is_active=1`。三处规则互不冲突。
2. **任务状态三件套**：`tasks.status`（todo/done）、`test_task_meta.health`（五值）、`quality_gate_passed`（0/1）在 §4.5.2、§4.6.3、§4.7、§4.8、§7.2、附录 B 中口径一致。
3. **枚举单源**：`TestMapScope` / `TestCoverageMode` / `TestDraftItemStatus(skipped)` / `TestNodeHealth` 与 DDL CHECK、REST、MCP 参数一致。
4. **里程碑与验收对齐**：P0 → AC-01~13、27、29、30、32；P1 → AC-14~23、31；P2 → AC-21~26、28、33。AC-31（Token 鉴权）随 P1 Agent 协议验收，但 `scopes` 列与回填在 P0 落 schema，避免老库二次迁移。
5. **新增表数**：14 张，`tasks` / `test_cases` / `agent_runs` 仍未改动；`api_tokens` 仅增列。

## 13. v1.2.2 跨模块联动专项评审

### 13.1 评审方法

不再按章节通读，而是以「相邻模块触发 → 测试侧响应 → 反向影响 → 降级行为」逐链路推演，覆盖框架顶栏、项目、任务、计划、历史资产、归档、AI 控制台/执行会话、全局搜索/命令面板、首页收件箱、需求矩阵/手工用例共 11 条链路。仓库核对：`server/src/services/GlobalSearchService.ts`（全局搜索索引落点）、`web/src/ui/WorkspaceSearchPanel.tsx`、`TaskService` dedupe 释放钩子、`ChangeBus` 事件面。

### 13.2 发现的联动断点与关闭

| ID | 断点 | 风险 | v1.2.2 处置（PRD §4.13） |
|---|---|---|---|
| LK-01 | 任务 done/归档/删除释放 `test_task_dedupe` 后未定义广播 | 草稿页 skipped 行永远显示「并发占用」，用户无法重新确认 | §4.13.2：释放时必须发 `test:drafts`（+ `test:maps` 刷新节点任务数）；AC-42 ① |
| LK-02 | purge 删除 `test_task_meta` 后任务详情测试区块行为未定义 | 任务详情死链/报错，违反「任务本身保留」承诺 | §4.13 L-03：meta 被 purge 后显示「测试资产已删除（批次 purged，时间）」占位；AC-42 ② |
| LK-03 | 沉淀/恢复/purge 后测试四页与顶栏 scope 下拉未列入 `test:archive` 订阅方 | 用户需手动刷新才能看到恢复项目；scope 指向已沉淀项目时数据错位 | §4.13 L-07 + §6.7：测试四页与 scope 下拉订阅 `test:archive`/`projects`，当前 scope 失效收敛到全部项目只读 + toast；AC-42 ③ |

| LK-05 | AI 控制台终止会话与 test run 终态关系未定义 | 控制台终止被误实现为 run failed/passed，污染健康度与质量门 | §4.13 L-08：会话终止不改 run 终态，租约到期回收；监控页「会话失联」黄条；立即停止走测试侧 abort |

## 14. 下一轮 UI 与跨模块联动改版设计（2026-11-26，已确认待实施）

### 14.1 目标与边界

本轮采用「文档 + DEMO 全链路」交付：更新评审报告，必要时修订 PRD 联动契约，重构独立 DEMO，并重新生成 PRD+DEMO 整合文档后回归。联动演示覆盖 P0–P2 全部阶段；P1/P2 能力必须保留阶段标识，不得表述为已实现。

视觉方向为 **A·产品质量台**：延续现有高密度工作台，强化层级、留白、状态色和局部反馈，不改成联动指挥台或场景导览。动效采用 **均衡增强**：服务状态因果与日常产品感，单次界面动效主要落在 160–420ms。

### 14.2 信息架构

- 保留测试看板、测试地图、测试任务、测试运行、历史资产、归档管理六条主路径。
- 顶栏保留项目/产品互斥作用域，新增全局搜索（`Ctrl/Cmd+K`）、收件箱和「联动演练」审查入口。
- 统一粘性上下文条展示当前作用域、维度、地图版本和只读状态。
- 任务详情补齐测试区块：关联节点、最近运行、health/质量门；purge 后显示删除占位。
- 运行详情/监控补齐会话失联、租约倒计时和测试侧 abort 边界。
- 联动演练面板按 L-01~L-11 提供触发、当前状态与预期结果；P1/P2 显示阶段徽标。
- 看板首屏突出核心质量指标，次要指标可展开，减少同时争夺注意力的内容。

### 14.3 单文件内部结构化

对外仍交付无外部依赖的离线单文件；对内拆成统一 mock store、事件总线、作用域解析、可见性 selector、渲染器和动效层。

- store 集中管理项目、产品、作用域、地图版本、草稿、任务、运行、归档批次、通知和搜索索引。
- 动作先提交状态，再发布 `test:maps / drafts / runs / issues / archive / projects`；测试四页、顶栏和搜索订阅刷新，生命周期事件 300ms 防抖。
- `resolveScope()` 统一处理手动切换与深链；深链不写回持久化，失效 scope 回落只读聚合态并提示。
- 搜索、看板、地图、草稿、运行共用可见性 selector，避免沉淀、归档或 purge 后跨页残留。
- 只重绘受影响区域；状态变化使用短高亮或骨架反馈，不重播整页入场。

### 14.4 视觉与动效

- 使用轻冷灰背景、白色卡片、细边框和克制阴影；语义色只表达健康、风险、只读和阶段。
- KPI 强化数值、同比和迷你趋势；图表增加悬浮/键盘提示，避免仅靠颜色传达信息。
- 表头与关键列粘性；移动端保留主操作，功能不能只依赖 hover 发现。
- 按压/悬浮 120–180ms，视图/数字/局部刷新 220–320ms，作用域/模态/状态高亮 300–420ms；运行进度与处理中 shimmer 可持续。
- 事件受影响卡片短高亮；toast 说明对象与结果，并提供可跳转入口。
- 弹窗/抽屉圈定并归还焦点，运行卡支持 Enter/Space，搜索支持方向键，toast 使用 live region，同步 `aria-current` 与禁用原因。
- `prefers-reduced-motion` 下关闭位移、描线、shimmer 与数字动画，仅保留即时状态变化。
- 验证 1680/1440/1050/768/390px；窄屏搜索使用全屏面板，宽表允许内部横向滚动。

### 14.5 异常与文档同步

必须可演示：非法/失效深链、重复确认幂等、purge 后占位、搜索无结果、会话失联、恢复不自动重跑。

评审报告区分 PRD 契约问题与 DEMO 未兑现问题；PRD 仅在必要时补强 §4.13/AC-42。独立 DEMO、整合文档、版本号和对照表同步更新，删除与事实不符的「已演示」表述。

### 14.6 验收标准

- 逐条回归 L-01~L-11，重点验证 dedupe 释放、生命周期后四页同步、purge 占位、搜索过滤、通知深链和运行不串任务。
- Chrome/Edge 桌面真实走查；覆盖上述响应式尺寸、键盘全流程和减少动态偏好。
- 保留离线 `file://` 打开；控制台与页面错误为空。
- 移动端页面本身不横向溢出，表格仅容器内部滚动。
- 整合文档内嵌 DEMO 解码后与独立 DEMO 完全一致。
- 测试证据写入评审报告；截图使用临时目录，不纳入无关工作区改动。

### 14.7 非目标

不引入前端框架或外部运行时依赖，不实现真实后端、SQLite、MCP 或 Agent 执行；不在本轮自动提交或推送代码。
