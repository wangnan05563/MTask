# 票交所合规审查规则库

本规则库供"票交所合规审查员"角色在 Phase 4 审查时使用，确保 PRD 文档符合上海票据交易所（SHCHPE）规则与接口标准。

---

## 一、报文规范审查

### 1.1 报文字段完整性

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| MSG-001 | 每个交易类型需明确对应的票交所报文类型编码 | 🔴阻塞 |
| MSG-002 | 报文必填字段不可为空，需在前端做强制校验 | 🔴阻塞 |
| MSG-003 | 报文字段长度不得超过票交所规定上限 | 🔴阻塞 |
| MSG-004 | 金额类字段精度必须为2位小数 | 🔴阻塞 |
| MSG-005 | 日期类字段格式必须为 yyyy-MM-dd 或 yyyyMMdd | 🔴阻塞 |
| MSG-006 | 报文发送前需做字段完整性校验，校验不通过不允许发送 | 🔴阻塞 |
| MSG-007 | 报文发送后需等待票交所响应，不可假设成功 | 🔴阻塞 |
| MSG-008 | 响应超时需有重试机制，重试次数不超过3次 | 🟡建议 |
| MSG-009 | 响应失败需记录错误码和错误信息，并通知操作人 | 🔴阻塞 |
| MSG-010 | 票交所返回的票据号码需与本地记录关联存储 | 🔴阻塞 |

### 1.2 常见报文类型

| 交易类型 | 报文方向 | 说明 |
|----------|----------|------|
| 出票登记 | 发送 | 登记票据基本信息 |
| 提示承兑 | 发送 | 请求承兑人承兑 |
| 承兑签收/拒绝 | 接收+响应 | 承兑人处理承兑请求 |
| 提示收票 | 发送 | 通知收款人签收 |
| 收票签收/拒绝 | 接收+响应 | 收款人处理收票请求 |
| 背书转让 | 发送 | 票据权利转让 |
| 贴现申请 | 发送 | 向金融机构申请贴现 |
| 质押/解质押 | 发送 | 票据质押或解除质押 |
| 保证 | 发送 | 为票据提供保证 |
| 提示付款 | 发送 | 到期请求付款 |
| 追索 | 发送 | 行使追索权 |

## 二、ECDS 状态同步审查

### 2.1 状态同步规则

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| ECDS-001 | 本系统票据状态必须与 ECDS 状态保持实时一致 | 🔴阻塞 |
| ECDS-002 | ECDS 状态变更通知需及时处理，延迟不超过5分钟 | 🔴阻塞 |
| ECDS-003 | 状态不一致时需有告警机制，不可静默忽略 | 🔴阻塞 |
| ECDS-004 | 状态同步失败需有补偿机制（定时对账） | 🟡建议 |
| ECDS-005 | 关键状态变更（承兑、付款、追索）需同步更新票据影像 | 🟡建议 |

### 2.2 状态映射

| ECDS 状态 | 本系统状态 | 同步方向 |
|-----------|-----------|----------|
| 01-出票已登记 | 出票登记 | 双向 |
| 02-提示承兑 | 承兑待处理 | 接收 |
| 03-承兑已签收 | 承兑已签收 | 接收 |
| 04-承兑已拒绝 | 承兑已拒绝 | 接收 |
| 05-提示收票 | 收票待处理 | 接收 |
| 06-收票已签收 | 票据已签收 | 接收 |
| 07-收票已拒绝 | 票据已拒绝 | 接收 |
| 08-票据已背书 | 背书已转让 | 双向 |
| 09-票据已贴现 | 贴现已完成 | 双向 |
| 10-票据已质押 | 质押已生效 | 双向 |
| 11-票据已保证 | 保证已生效 | 双向 |
| 12-提示付款 | 付款待处理 | 发送 |
| 13-票据已结清 | 票据已结清 | 接收 |
| 14-票据已拒付 | 票据已拒付 | 接收 |

## 三、异常票据库校验

### 3.1 校验规则

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| EX-001 | 交易前必须查询票交所异常票据库 | 🔴阻塞 |
| EX-002 | 票据在异常库中时，禁止执行交易操作 | 🔴阻塞 |
| EX-003 | 异常票据需在页面明显位置标记警示标识 | 🟡建议 |
| EX-004 | 止付票据需额外校验止付通知的合法性 | 🔴阻塞 |
| EX-005 | 查询异常票据库的结果需记录日志，便于审计 | 🟡建议 |

### 3.2 异常类型

| 异常类型 | 处理方式 |
|----------|----------|
| 挂失止付 | 禁止交易，提示联系出票人 |
| 公示催告 | 禁止交易，提示法律程序进行中 |
| 除权判决 | 禁止交易，票据权利已失效 |
| 法院冻结 | 禁止交易，提示联系法院 |
| 止付通知 | 禁止交易，需核实止付通知真伪 |

## 四、交易时间窗口审查

### 4.1 交易时段规则

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| TW-001 | 票据交易需在票交所规定的交易时段内进行 | 🔴阻塞 |
| TW-002 | 非交易时段提交的交易需排队等待下一交易时段 | 🟡建议 |
| TW-003 | 交易时段外需在页面提示"当前非交易时段" | 🟡建议 |
| TW-004 | 临近交易时段结束前需提醒用户（如最后15分钟） | 🟢提示 |
| TW-005 | 提示承兑/收票的响应有时效要求，超时自动处理规则需明确 | 🔴阻塞 |
| TW-006 | 撤回操作需在对方未处理前执行，超时不可撤回 | 🔴阻塞 |
| TW-007 | 追索权行使有法定时效，系统需做时效提醒 | 🟡建议 |

## 五、风控规则审查

### 5.1 黑名单校验

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| RK-001 | 交易对手方需校验黑名单（票交所/人行/内部黑名单） | 🔴阻塞 |
| RK-002 | 黑名单命中时禁止交易，并记录风控日志 | 🔴阻塞 |
| RK-003 | 黑名单校验需覆盖：出票人、承兑人、收款人、背书人 | 🔴阻塞 |
| RK-004 | 承兑交易需校验承兑行额度，额度不足不可承兑 | 🔴阻塞 |
| RK-005 | 贴现交易需校验贴现行额度，额度不足不可贴现 | 🔴阻塞 |
| RK-006 | 额度占用需实时生效，避免超额 | 🔴阻塞 |
| RK-007 | 交易取消/失败后需及时释放已占用额度 | 🔴阻塞 |
| RK-008 | 额度查询需支持实时余额和可用额度 | 🟡建议 |
| RK-009 | 大额交易需触发反洗钱审查（单笔≥5万元或累计≥20万元） | 🔴阻塞 |
| RK-010 | 可疑交易特征识别：频繁背书、短期多次贴现等 | 🟡建议 |
| RK-011 | 反洗钱审查结果需记录并上报 | 🔴阻塞 |

## 六、信息披露审查

### 6.1 商承信息披露

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| DI-001 | 商业承兑汇票的承兑人需在票交所完成信息披露 | 🔴阻塞 |
| DI-002 | 未完成信息披露的商承，系统需提示风险 | 🔴阻塞 |
| DI-003 | 信息披露内容需包含：承兑人名称、信用评级、逾期情况 | 🟡建议 |
| DI-004 | 信息披露状态需实时查询，不可使用缓存数据 | 🟡建议 |

## 七、审查输出格式

票交所合规审查员审查结果按以下格式输出：

```markdown
### 票交所合规审查报告

#### 🔴 合规阻塞项
| # | 合规领域 | 规则编号 | 问题描述 | 合规要求 |
|---|----------|----------|----------|----------|
| 1 | 报文规范 | MSG-001 | 未明确贴现交易的报文类型编码 | 需对应票交所贴现报文标准 |

#### 🟡 合规建议项
| # | 合规领域 | 规则编号 | 问题描述 | 合规要求 |
|---|----------|----------|----------|----------|
| 1 | ECDS同步 | ECDS-004 | 未说明状态同步失败的补偿机制 | 建议增加定时对账机制 |

#### 🟢 合规提示项
| # | 合规领域 | 规则编号 | 问题描述 | 默认假设 |
|---|----------|----------|----------|----------|
| 1 | 交易时段 | TW-004 | 未说明临近收盘提醒 | 默认不提醒 |
```
