# 票据业务专家规则库

本规则库供"票据业务专家"角色在 Phase 4 审查时使用，确保 PRD 文档在业务逻辑层面的完整性。

---

## 一、CRUD 完整性检查

### 1.1 实体操作覆盖

对每个票据相关实体，检查是否覆盖以下操作：

| 操作 | 检查要点 |
|------|----------|
| 创建（Create） | 新增入口、必填字段、默认值、编号生成规则 |
| 查询（Read） | 列表查询、详情查看、条件筛选、排序规则 |
| 修改（Update） | 可修改字段、修改权限、修改后联动影响 |
| 删除（Delete） | 逻辑删除/物理删除、删除条件、删除后关联数据处理 |

### 1.2 票据核心实体清单

| 实体 | 说明 | 必检操作 |
|------|------|----------|
| 票据本体 | 票面信息、状态、金额等 | 全部 CRUD |
| 票据交易 | 承兑、贴现、背书等交易记录 | 创建 + 查询 |
| 票据影像 | 票据正反面扫描件 | 上传 + 查看 |
| 票据状态日志 | 状态变更记录 | 查询（不可修改） |
| 客户信息 | 出票人、承兑人、收款人等 | 查询 + 关联 |
| 额度信息 | 承兑额度、贴现额度等 | 查询 + 占用/释放 |

## 二、状态流转闭环检查

### 2.1 票据状态机（通用模型）

```
出票登记 → 出票已登记
    ↓
提示承兑 → 承兑待处理
    ↓ (承兑人签收)         ↓ (承兑人拒绝)
承兑已签收               承兑已拒绝
    ↓
提示收票 → 收票待处理
    ↓ (收款人签收)         ↓ (收款人拒绝)
票据已签收               票据已拒绝
    ↓
┌───────────────────────────────┐
│ 可执行：背书 / 质押 / 保证 / 贴现 │
└───────────────────────────────┘
    ↓
到期提示付款 → 付款待处理
    ↓ (付款成功)          ↓ (付款拒绝)
票据已结清               票据已拒付
    ↓
追索（如有）
```

### 2.2 状态流转检查规则

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| SF-001 | 每个状态必须有合法的前驱状态和后继状态 | 🔴阻塞 |
| SF-002 | 不允许出现"孤岛状态"（无入边也无出边） | 🔴阻塞 |
| SF-003 | 每个操作必须明确前置状态要求 | 🔴阻塞 |
| SF-004 | 状态变更必须记录操作人、操作时间、操作原因 | 🟡建议 |
| SF-005 | 撤回操作必须限定在对方未处理的时间窗口内 | 🔴阻塞 |
| SF-006 | 拒绝操作必须要求填写拒绝原因 | 🟡建议 |

### 2.3 按票据类型的差异化状态

| 票据类型 | 特殊状态/规则 |
|----------|---------------|
| 银行承兑汇票 | 承兑人为银行，承兑环节需校验银行承兑额度 |
| 商业承兑汇票 | 承兑人为企业，需关注商承信息披露要求 |
| 银行承兑汇票（可转让） | 无独立承兑环节，出票即生效，支持背书转让 |
| 商业承兑汇票（可转让） | 无独立承兑环节，出票即生效，支持背书转让 |

## 三、金额校验规则

### 3.1 票面金额

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| AM-001 | 票面金额必须大于 0 | 🔴阻塞 |
| AM-002 | 大写金额与小写金额必须一致 | 🔴阻塞 |
| AM-003 | 票面金额不超过票交所单张票据上限（当前为 1 亿元） | 🔴阻塞 |
| AM-004 | 金额修改后需重新校验大写小写一致性 | 🔴阻塞 |

### 3.2 交易金额

| 交易类型 | 金额校验规则 |
|----------|--------------|
| 贴现 | 贴现金额 ≤ 票面金额；贴现利息 = 票面金额 × 贴现利率 × 贴现天数/360 |
| 背书 | 背书金额 = 票面金额（全额背书），不支持部分背书 |
| 质押 | 质押金额 ≤ 票面金额，解押后释放额度 |
| 保证 | 保证金额 = 票面金额（全额保证） |
| 付款 | 付款金额 = 票面金额 |

### 3.3 利息计算

| 规则编号 | 规则描述 |
|----------|----------|
| IN-001 | 贴现天数 = 到期日 - 贴现日（按实际天数计算） |
| IN-002 | 贴现利率需在系统参数配置的上下限范围内 |
| IN-003 | 逾期利息计算规则需明确（是否计收、利率标准） |
| IN-004 | 利息计算结果需四舍五入到分 |

## 四、日期规则

### 4.1 票据日期校验

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| DT-001 | 出票日 ≤ 当前日期 | 🔴阻塞 |
| DT-002 | 到期日 > 出票日 | 🔴阻塞 |
| DT-003 | 票据期限：纸质汇票最长不超过6个月，电子汇票最长不超过1年 | 🔴阻塞 |
| DT-004 | 贴现日 ≥ 出票日 且 贴现日 < 到期日 | 🔴阻塞 |
| DT-005 | 提示付款日：到期日前10天内可发起 | 🟡建议 |
| DT-006 | 追索权行使期限：自被拒绝承兑或被拒绝付款之日起6个月 | 🟡建议 |

### 4.2 工作日规则

| 规则编号 | 规则描述 |
|----------|----------|
| WD-001 | 到期日若为非工作日，顺延至下一个工作日 |
| WD-002 | 利息计算按实际天数，不区分工作日与自然日 |
| WD-003 | 交易操作时间窗口需遵守票交所交易时段 |

## 五、数据一致性检查

### 5.1 主从表一致性

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| DC-001 | 票据主表状态与最新交易记录状态一致 | 🔴阻塞 |
| DC-002 | 票据金额与交易金额汇总一致 | 🔴阻塞 |
| DC-003 | 票据影像记录与票据本体一一对应 | 🟡建议 |
| DC-004 | 额度占用/释放记录与交易记录匹配 | 🔴阻塞 |

### 5.2 跨系统一致性

| 规则编号 | 规则描述 | 严重程度 |
|----------|----------|----------|
| DC-010 | 本系统票据状态与 ECDS 状态一致 | 🔴阻塞 |
| DC-011 | 交易报文发送后，票交所返回确认状态需同步更新 | 🔴阻塞 |
| DC-012 | 异常票据库查询结果需标记在票据信息中 | 🟡建议 |

## 六、票据类型约束

### 6.1 按类型的功能差异

| 功能 | 银承 | 商承 | 银转 | 商转 |
|------|------|------|------|------|
| 承兑环节 | ✅ 需承兑 | ✅ 需承兑 | ❌ 无承兑 | ❌ 无承兑 |
| 承兑人 | 银行 | 企业 | - | - |
| 信息披露 | ❌ 不需要 | ✅ 需要 | ❌ 不需要 | ✅ 需要 |
| 额度管控 | 银行承兑额度 | 企业授信额度 | - | - |
| 贴现限制 | 较宽松 | 较严格（需审查承兑人信用） | 较宽松 | 较严格 |

### 6.2 类型转换规则

| 规则编号 | 规则描述 |
|----------|----------|
| BT-001 | 票据类型一旦确定不可更改 |
| BT-002 | 银承与商承的区分在于承兑人类型（金融机构 vs 非金融机构） |
| BT-003 | 转账票据无承兑环节，出票即生效 |
